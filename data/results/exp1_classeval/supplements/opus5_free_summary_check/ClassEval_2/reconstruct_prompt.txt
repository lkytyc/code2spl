`ArgumentParser` is a class that parses command-line style argument strings into a key-value store, with optional type coercion and required-argument enforcement.

**State it maintains:**
- `arguments` — a dict of parsed key-value pairs from the input string
- `required` — a set of argument names that must be present
- `types` — a dict mapping argument names to their expected Python types

**How you configure it:**
Call `add_argument(arg, required=False, arg_type=str)` before parsing. This registers an argument name, marks it as required if specified, and records its type for later conversion. Defaults to `str` if no type is given.

**How parsing works:**
`parse_arguments(command_string)` splits the string on whitespace and skips the first token (treating it as the program name). It then walks the remaining tokens and handles two formats:

- `--key=value` — splits on `=` and stores the value; if there's no `=`, stores `True` as a boolean flag
- `-key` — looks ahead to the next token; if it doesn't start with `-`, uses it as the value; otherwise stores `True` as a flag

After consuming all tokens, it checks whether any names in `required` are absent from `arguments`. If any are missing, it returns `(False, set_of_missing_names)`. On success it returns `(True, None)`.

**Type conversion:**
`_convert_type(arg, value)` looks up the registered type for an argument and calls it on the string value (e.g., `int("42")` → `42`). If the argument has no registered type or the conversion raises `ValueError`, it falls back to returning the raw string.

**Retrieving values:**
`get_argument(key)` returns the stored value for a key, or `None` if it wasn't parsed.

**Notable gaps and edge cases in the current code:**
- The short-flag parser (`-key`) advances `i` logically but doesn't actually skip the consumed value token — the next loop iteration will try to parse it as an argument name too.
- There's no validation that `--key=value` argument names match any registered argument before storing them.
- Calling `parse_arguments` multiple times on the same instance accumulates results in `self.arguments` rather than starting fresh.
