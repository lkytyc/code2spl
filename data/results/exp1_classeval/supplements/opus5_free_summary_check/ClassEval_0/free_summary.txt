`AccessGatewayFilter` acts as a request gatekeeper, deciding whether an incoming HTTP-like request should be allowed through.

**filter (main entry point)**

Takes a request dict with at least `path` and `method` keys. It first checks if the URI starts with a whitelisted prefix (`/api` or `/login`); if so, it passes immediately without any auth check. Otherwise, it attempts to extract and validate a JWT token from the request. If the user's `level` is greater than 2, it logs the access and grants entry. Any exception during that process results in a denial (`False`).

**is_start_with**

Simple prefix check against the two hardcoded open paths. Returns `True` on first match.

**get_jwt_user**

Pulls the `Authorization` header from the request, which is expected to be a dict containing a `user` object and a `jwt` string. If the JWT string starts with the user's name, it extracts the trailing portion as a date string and parses it. If that date is 3 or more days in the past, it returns `None` (treating the token as expired). If the JWT doesn't start with the user's name, or the token is still fresh, it returns the token as-is.

**set_current_user_info_and_log**

Logs a string combining the user's name, their `address`, and the current timestamp at log level 1.

**Key interactions and notes**

- The `filter` method calls `get_jwt_user` but doesn't explicitly check for a `None` return — it immediately accesses `token['user']`, so a `None` return from an expired token will raise a `TypeError`, which is silently caught and treated as a denial.
- The `level` check (`> 2`) means level 0, 1, and 2 users are denied even with a valid, unexpired token.
- Error handling is a broad bare `except`, so any malformed request structure (missing headers, wrong types) also results in a silent `False`.
