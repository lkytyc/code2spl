## Program Overview
This program reads multiple square matrices from standard input, computes a trace and duplicate detection metrics for each, and outputs formatted results. It processes a variable number of test cases.

## Input
- First integer: number of test cases (t)
- For each test case:
  - Integer n: matrix dimensions (n×n)
  - n×n integers: matrix elements read row by row

## Output
For each test case, a single line formatted as:
`Case #N:  K R C`
Where N is a case counter, K is the trace, R is row duplicate count, C is column duplicate count.

## Main Function Control Flow
1. Creates a Scanner for standard input
2. Reads test case count t
3. Loops while t decrements to zero:
   - Reads matrix size n
   - Allocates n×n array
   - Nested loops read all matrix elements
   - Calls vestigium function with matrix and size

## Vestigium Function Processing

### Trace Calculation
- Initializes k=0
- Single loop sums diagonal elements (a[i][i]) into k

### Matrix Transposition
- Creates new n×n array b
- Nested loops copy transposed matrix: b[i][j] = a[j][i]

### Row Duplicate Detection
- Sorts each row of original matrix a using Arrays.sort
- For each row, counts consecutive equal elements
- Tracks maximum consecutive duplicates across all rows
- Resets repeat counter after each row if duplicates found
- Stores result in variable r as count+1

### Column Duplicate Detection
- Sorts each row of transposed matrix b (equivalent to sorting columns of original)
- Same duplicate detection logic as rows
- Stores result in variable c as count1+1

### Output Logic
- Initializes counter=1
- Four conditional branches based on duplicate presence:
  1. No duplicates in rows or columns: outputs count and count1 (both 0)
  2. Duplicates in both: outputs r and c (count+1, count1+1)
  3. Duplicates in rows only: outputs r and count1
  4. Duplicates in columns only: outputs count and c
- Each branch increments counter after printing

## Data Dependencies
- Matrix a is modified in place (rows sorted) before row duplicate detection
- Matrix b depends on original matrix a values before sorting
- Trace k computed before any sorting occurs
- Row duplicate count depends on sorted rows
- Column duplicate count depends on sorted transposed rows
- Output values depend on both duplicate counts and trace

## Notable Behavior
- The counter variable resets to 1 for each call to vestigium, so all test cases output "Case #1"
- The duplicate counting logic counts consecutive equal elements after sorting, which identifies any duplicate values in a row/column
- The r and c values are computed as count+1, which appears to represent the number of rows/columns containing duplicates rather than total duplicate count
