# Code Description

## Overview
This program processes multiple test cases involving a pursuit scenario on a 2001×2001 grid. It reads input containing coordinates and a movement string, then determines whether and when an intercept is possible.

## Inputs
- First line: integer T (number of test cases)
- For each test case:
  - Three values: X, Y (integers), and M (string of directional characters N, S, E, W)

## Outputs
- For each test case, outputs "Case #t: " followed by either:
  - An integer representing the time of interception
  - "IMPOSSIBLE" if interception cannot occur

## Data Structures
- Direction arrays dx and dy for four cardinal movements
- 2D integer array g (2001×2001) marking positions visited by the target
- 2D boolean array visited for BFS tracking
- List of coordinate pairs (tour) recording the target's path
- Queue of Pair objects for BFS traversal
- Pair class storing x, y coordinates and distance

## Main Processing Flow

### Initialization
- Sets up scanner and output builder
- Initializes direction vectors for N, S, E, W movements

### Target Path Construction
For each test case:
1. Reads target's starting position (X, Y) and movement string M
2. Initializes grid position at (1000, 1000) as starting point
3. Marks starting position in grid g
4. Iterates through each character in M:
   - Updates position based on direction (N decreases y, S increases y, E increases x, W decreases x)
   - Marks new position in grid
   - Records position in tour list

### Interception Search
1. Sets starting position for pursuer at (1000-X, 1000+Y)
2. Performs BFS from pursuer's start position:
   - Checks if current position matches any target position (grid value = 1)
   - If found, records distance and coordinates, stops search
   - Otherwise, explores four adjacent positions within grid bounds
   - Marks visited positions to avoid revisiting

### Result Determination
If no interception found during BFS (tmp = -1):
- Outputs "IMPOSSIBLE"

If interception found:
1. Finds the index in tour where the interception point occurs
2. Compares BFS distance (tmp) with tour index (ti):
   - If tmp ≤ ti: Calculates answer as tmp + (ti - tmp + 1)/2
   - If tmp > ti: Performs additional check:
     - Iterates through tour positions from ti onward
     - Marks positions from the target's future path
     - Checks if pursuer's path position matches any marked target position
     - If match found, outputs that index; otherwise outputs "IMPOSSIBLE"

## Control Flow Branches
- Main loop iterates T times for test cases
- Direction handling uses independent if statements (not else-if)
- BFS continues until queue empty or interception found
- Boundary checking prevents out-of-bounds access
- Two different calculation paths based on comparison of tmp and ti

## Function Calls
- Scanner methods for input reading
- Queue operations (offer, poll, isEmpty)
- List operations (add, get)
- StringBuilder append operations

## Data Dependencies
- Target path depends on input coordinates and movement string
- BFS results depend on grid markings from target path
- Final answer depends on both BFS distance and tour position indices
- The second verification loop depends on both the BFS result and tour path
