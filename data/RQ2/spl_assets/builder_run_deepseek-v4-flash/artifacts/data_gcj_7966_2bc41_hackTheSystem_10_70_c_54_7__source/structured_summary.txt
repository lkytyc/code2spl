# Structured Description of Solution.java

## Overview
This program processes test cases for a system-hacking simulation. Each case provides a shield value and a sequence of commands ('C' for charge, 'S' for shoot). The goal is to determine the minimum number of adjacent swaps needed to reduce total damage to at most the shield value, or report "IMPOSSIBLE" if that cannot be achieved.

## Inputs
- **Primary input**: Read from standard input via a Scanner.
- **First line**: Number of test cases (integer).
- **Each subsequent line**: Two space-separated values:
  - A long integer representing the shield capacity.
  - A string of characters ('C' and 'S') representing the command sequence.

## Outputs
- For each test case, prints: `Case #<index>: <result>` where `<index>` starts at 0.
- `<result>` is either:
  - The minimum number of swaps (as a string) if achievable.
  - The string `"IMPOSSIBLE"` if not achievable.

## Global/Static Variables
- `shootDamage`: Long, current damage per shot (starts at 1).
- `shootCounter`: Long, total count of 'S' commands.
- `shield`: Long, the shield capacity for the current case.
- `code`: String, the command sequence being processed.
- `damage`: Long, total damage from all shots.
- `movements`: Long, count of swaps performed.
- `lastIterableElement`: Integer, tracks the rightmost position considered in the swap loop.

## Main Method Flow
1. Reads number of test cases.
2. Stores all cases in a 2D array.
3. Iterates through cases, calling `hackTheSystem` for each and printing results.

## hackTheSystem Method Flow

### Initialization
- Sets `shootDamage` to 1, `shootCounter` to 0, `damage` to 0, `movements` to 0.
- Parses shield from `softwareToHack[0]` and code from `softwareToHack[1]`.
- Sets `sizeScript` to code length minus 1.
- Sets `lastIterableElement` to `sizeScript`.

### First Pass - Calculate Initial Damage
- Iterates through each character of `code`:
  - If character is 'S': adds current `shootDamage` to `damage`, increments `shootCounter`.
  - If character is 'C': multiplies `shootDamage` by 2.

### Early Exit Conditions
- If `damage <= shield`: returns "0" (no swaps needed).
- If `shootCounter > shield`: returns "IMPOSSIBLE" (even with all shots at minimum damage, shield is insufficient).

### Swap Loop
- Outer loop: Iterates `i` from `sizeScript` down to 0.
- Inner loop: Iterates `j` from `sizeScript - 1` down to 0.

#### Loop Logic Branches:
1. **If both `code.charAt(j)` and `code.charAt(i)` are 'S'**:
   - Decrements `i` and continues to next outer iteration.

2. **If `code.charAt(i)` is 'C'**:
   - Divides `shootDamage` by 2.
   - Decrements `i` and `lastIterableElement`.
   - Continues to next outer iteration.

3. **If `code.charAt(j)` is 'C' and `code.charAt(i)` is 'S'**:
   - Increments `movements`.
   - Reduces `damage` by `shootDamage / 2`.
   - Converts `code` to character array.
   - If `damage <= shield` after reduction: returns current `movements` as string.
   - Swaps characters at positions `j` and `i` in the array.
   - Converts array back to string and updates `code`.
   - **Position adjustment logic**:
     - If `i == lastIterableElement`: divides `shootDamage` by 2, and if `i > 0`, decrements `i`.
     - Otherwise: increments `i` and increments `j` by 2.

### Final Return
- If loop completes without early return, returns `movements` as string.

## Data Dependencies
- `damage` depends on `shootDamage` and the sequence of 'S' and 'C' commands.
- `shootDamage` changes during processing when 'C' commands are encountered or when swaps occur.
- `movements` increments only when a swap is performed.
- The swap operation modifies `code`, which affects subsequent loop iterations.
- `lastIterableElement` tracks the boundary of processed 'C' commands.
