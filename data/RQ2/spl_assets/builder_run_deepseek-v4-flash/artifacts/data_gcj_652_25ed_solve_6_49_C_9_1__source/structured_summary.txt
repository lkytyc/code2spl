## Overview
This program solves a problem involving splitting a length `N` interval into smaller intervals over `K` steps, tracking the largest interval at each step. It uses a priority queue and a hash map to efficiently process intervals in descending order of size.

## Input
- First line: integer `T` (number of test cases)
- For each test case: two long integers `N` and `K` on a single line

## Output
For each test case, prints: `Case #X: L R` where `X` is the test case number (1-based), `L` is the floor of half the final interval size, and `R` is the floor of (final interval size - 1) divided by 2.

## Data Structures
- `PriorityQueue<Long>`: stores negative interval sizes (so the largest positive size is at the head)
- `HashMap<Long, Long>`: maps interval size to the count of intervals of that size currently in the queue

## Algorithm Flow

### Initialization
1. Read `T` from input
2. For each test case (loop from `C=1` to `T`):
   - Read `N` and `K`
   - Initialize queue with `-N` (negative of initial size)
   - Initialize count map with `{N: 1}`
   - Set `ans = 0`

### Main Processing Loop
The loop continues until a break condition is met:

1. **Extract largest interval**: Poll the queue (getting the most negative value, which represents the largest positive size), negate it to get `cur`, and retrieve its count `rest` from the map.

2. **Check termination conditions**:
   - If `K <= 1`: set `ans = cur` and break
   - Otherwise, subtract `rest` from `K`
   - If `K <= 0` after subtraction: set `ans = cur` and break

3. **Split the interval**:
   - Compute `large = cur / 2` (integer division)
   - Compute `small = (cur - 1) / 2` (integer division)
   - For each of `large` and `small`:
     - If the size already exists in the count map, add `rest` to its count
     - Otherwise, add the negative size to the queue and set its count to `rest`

### Output
After the loop breaks, print the result using the formula:
- Left value: `ans / 2`
- Right value: `(ans - 1) / 2`

## Key Control Flow Branches
- **Termination check 1**: `K <= 1` at the start of each iteration
- **Termination check 2**: `K <= 0` after subtracting the count of the current interval
- **Count map update**: Two separate branches for `large` and `small` sizes, each checking if the size already exists in the map

## Data Dependencies
- The count of each interval size is tracked to avoid processing each interval individually
- The priority queue ordering depends on the negative values stored (largest positive size = smallest negative value = head of queue)
- The `K` value is decremented by the count of intervals at each processed size level
- The final answer depends on which interval size causes `K` to reach zero or below

## Loop Structure
- Outer loop: iterates over test cases (`C` from 1 to `T`)
- Inner loop: `while(true)` with explicit break conditions, processing interval sizes in descending order until `K` is satisfied
