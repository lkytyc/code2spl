# Code Description

## Overview
This Java program reads test cases from standard input, separates input numbers into odd-indexed and even-indexed arrays, sorts each array, and checks whether the combined sequence would be non-decreasing if the arrays were interleaved.

## Inputs
- First integer: number of test cases
- For each test case:
  - An integer `n` representing the number of elements
  - `n` integers to be processed

## Outputs
For each test case, one of the following lines is printed:
- `Case #X: OK` if the interleaved sorted sequence is valid
- `Case #X: Y` where Y is the index of the first violation (0-based position in the original sequence)

## Main Control Flow

### Test Case Loop
- Iterates from `m=0` to `numberOfTests-1`
- For each test case:
  - Reads `n` from input
  - Calculates array sizes:
    - If `n` is odd: `a = n/2 + 1`, `b = n/2`
    - If `n` is even: `a = n/2`, `b = n/2`
  - Creates `oddArray` of size `a` and `evenArray` of size `a` (note: evenArray is always allocated with size `a`, not `b`)

### Input Reading Loop
- Iterates from `i=0` to `n-1`
- If index `i` is even: stores value in `oddArray` at position `c`, increments `c`
- If index `i` is odd: stores value in `evenArray` at position `d`, increments `d`

### Array Modification
- Sets the last element of `evenArray` to `Integer.MAX_VALUE`

### Sorting
- Creates a new `Solution` object
- Calls `sort(oddArray)` and `sort(evenArray)` on that object

### Validation Loop
- Iterates through `oddArray` indices from `h=0` to `oddArray.length-1`
- For each index `h`:
  - If `oddArray[h] <= evenArray[h]`:
    - If `h` is the last index: breaks out of loop (success)
    - If `evenArray[h] <= oddArray[h+1]`: continues to next iteration
    - Otherwise: prints `Case #(m+1): (2*h+1)` and increments violation counter `x`, then breaks
  - If `oddArray[h] > evenArray[h]`:
    - Prints `Case #(m+1): 2*h` and increments violation counter `x`, then breaks
- The `try-finally` block has an empty `finally` clause, so it doesn't affect control flow

### Final Check
- After the validation loop, if `x == 0` (no violation found), prints `Case #(m+1): OK`

## Merge Sort Implementation

### Public `sort` Method
- Takes an integer array as input
- Stores it in instance field `array`
- Sets `length` to array length
- Creates `tempMergArr` of same length
- Calls `doMergeSort(0, length-1)`

### Private `doMergeSort` Method
- Recursive method with parameters `lowerIndex` and `higherIndex`
- If `lowerIndex < higherIndex`:
  - Calculates middle index
  - Recursively sorts left half
  - Recursively sorts right half
  - Merges the two halves

### Private `mergeParts` Method
- Parameters: `lowerIndex`, `middle`, `higherIndex`
- Copies elements from `array` to `tempMergArr` for the range
- Uses three pointers (`i`, `j`, `k`) to merge:
  - While both halves have elements: compares and places smaller element back into `array`
  - Copies remaining elements from left half if any
  - Note: does not copy remaining elements from right half (they're already in place)

## Data Dependencies
- `oddArray` and `evenArray` contents depend on input values and their original positions
- The validation logic depends on both sorted arrays
- The violation index calculation depends on the loop position `h` and whether the violation is at an odd or even position
- The `sort` method modifies the input arrays in-place through the instance fields

## Notable Behaviors
- `evenArray` is always allocated with size `a` (same as `oddArray`), even when `n` is even and `b < a`
- The last element of `evenArray` is overwritten with `Integer.MAX_VALUE` as a sentinel
- The validation assumes `oddArray` and `evenArray` have the same length
