## Input

The program reads from standard input. The first line contains three integers: height `h`, width `w`, and a movement limit `k`. The second line contains four integers: starting row `y`, starting column `x`, target row `s`, and target column `t`. Then `h` lines follow, each containing a string of length `w` representing the grid. The character `@` denotes an obstacle; any other character denotes a passable cell.

## Output

The program prints a single integer: the minimum number of moves required to reach the target cell from the start cell, or `-1` if the target is unreachable.

## Data Structures

- A deque `q` stores states as tuples `(row, col, direction, remaining_steps)`.
- A 2D list `d` stores the minimum distance (number of moves) to each cell, initialized to infinity except the start cell which is 0.
- Four 2D lists `ri`, `le`, `do`, `up` store precomputed maximum movement distances in each direction (right, left, down, up) from each cell, capped at `k`.

## Preprocessing

For each cell, the program computes how far one can move in each of the four cardinal directions without hitting an obstacle, with the maximum distance capped at `k`:

- `ri[i][j]`: maximum steps right from cell `(i,j)` before hitting `@` or reaching `k`.
- `le[i][j]`: maximum steps left from cell `(i,j)`.
- `do[i][j]`: maximum steps down from cell `(i,j)`.
- `up[i][j]`: maximum steps up from cell `(i,j)`.

These are computed by scanning from the edges inward, using the previously computed neighbor values.

## Main Algorithm

The algorithm is a 0-1 BFS (breadth-first search) variant using a deque.

### Initialization

- The start cell `(y-1, x-1)` is pushed onto the deque with direction `-1` (no direction) and remaining steps `0`.
- The distance to the start cell is set to 0.

### BFS Loop

While the deque is not empty:

1. Pop the leftmost state `(y, x, p, l)`.
2. If this cell is the target `(s, t)`, print `d[s][t]` and return.

3. **Full-direction moves (cost 1):** For each of the four directions, compute the maximum jump distance from the current cell using the precomputed arrays. The new position is the current cell plus that jump. If the jump distance is zero (no movement), skip. If the new distance `nd = d[y][x] + 1` is less than the stored distance at the new cell, update the distance and push the new state to the **right** end of the deque with the direction index and the jump length as remaining steps.

4. **Continuation move (cost 0):** If the current state has a valid direction `p >= 0` and remaining steps `l > 1`, then the state represents being in the middle of a multi-step move. The next cell is one step further in that same direction. The distance remains the same (`nd = d[y][x]`). If this new distance is less than the stored distance, update and push this state to the **left** end of the deque with the same direction and `l-1` remaining steps.

### Termination

If the deque becomes empty without reaching the target, print `-1`.

## Key Control Flow

- The preprocessing loops iterate over rows and columns in specific orders (right-to-left for `ri`, left-to-right for `le`, bottom-to-top for `do`, top-to-bottom for `up`).
- The main BFS loop checks the target condition at the start of each iteration.
- The direction index mapping: 0 = up, 1 = down, 2 = left, 3 = right.
- The `dd` array contains unit direction vectors: up, down, left, right.

## Function Calls

- `LI()` reads a line and splits into integers.
- `I()` reads a single integer.
- `S()` reads a line as a list of characters, stripping the trailing newline.
- The main `solve()` function is called when the script is run directly.

## Dependencies

- The distance array `d` is updated both in the full-jump case and the continuation case.
- The precomputed direction arrays (`ri`, `le`, `do`, `up`) are used only in the full-jump case.
- The deque ordering (appendleft for cost-0 moves, append for cost-1 moves) ensures the BFS explores cheaper moves first.
