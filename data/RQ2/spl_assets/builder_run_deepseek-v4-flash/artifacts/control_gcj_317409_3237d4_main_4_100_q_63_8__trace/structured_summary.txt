# Code Description

## Overview
This Java program solves a problem involving tracking a moving target and determining if a pursuer can intercept it. The program reads multiple test cases, each containing a target's starting position and movement path, then calculates whether interception is possible and at what time.

## Input
- First line: integer T (number of test cases)
- For each test case:
  - Three values: X, Y (target's starting coordinates relative to origin), and M (string of movement directions)
  - M contains characters: N, S, E, W representing movement directions

## Output
- For each test case, outputs "Case #t: " followed by either:
  - An integer representing the interception time
  - "IMPOSSIBLE" if interception cannot occur

## Data Structures
- Grid: 2001×2001 integer array `g` marking target positions
- Grid: 2001×2001 boolean array `visited` for BFS traversal
- Grid: 2001×2001 boolean array `visited2` for second phase checking
- Tour list: List of coordinate pairs representing target's path
- Queue: LinkedList of Pair objects for BFS
- Pair class: Stores x, y coordinates and distance from start

## Main Algorithm

### Target Path Recording
1. Initialize target position at (1000, 1000) in grid coordinates
2. Mark starting position in grid `g`
3. For each character in movement string M:
   - Update position based on direction (N: y-1, S: y+1, E: x+1, W: x-1)
   - Mark new position in grid
   - Add position to tour list

### BFS Search Phase
1. Set pursuer starting position at (1000-X, 1000+Y)
2. Perform BFS from pursuer's start position
3. Search for nearest grid cell marked as target position
4. Track distance traveled (tmp) and coordinates of first target position found (nearX, nearY)
5. BFS explores 4-directional movement with boundary checking

### Interception Time Calculation
1. Find index `ti` in tour list matching the found target position
2. If BFS distance (tmp) ≤ tour index (ti):
   - Calculate interception time as: tmp + (ti - tmp + 1) / 2
3. If BFS distance > tour index:
   - Iterate through tour positions from index ti
   - For each position i, check if target's position at time (tmp + i - ti) has been visited
   - If match found, output time i
   - If no match found in valid range, output "IMPOSSIBLE"

## Control Flow Branches
- Main loop iterates through all test cases
- BFS loop continues until queue empty or target found
- Direction checking uses independent if statements (not else-if)
- Boundary validation prevents out-of-bounds access
- Two possible success paths for interception calculation
- Fallback to "IMPOSSIBLE" when no interception possible

## Key Dependencies
- BFS distance calculation depends on grid positions marked during target path recording
- Interception time calculation depends on both BFS results and tour path indices
- Second phase checking depends on comparing tour positions with visited positions from first phase
