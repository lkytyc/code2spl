# Code Description

## Program Overview
This is a Java program that solves a geometric optimization problem. It reads two integers representing the height and width of a rectangle, then determines the minimum possible difference between the largest and smallest areas when the rectangle is divided into three rectangular sections.

## Input/Output
- **Input**: Two integers read from standard input - the height (h) and width (w) of a rectangle
- **Output**: A single integer printed to standard output representing the minimum difference between the maximum and minimum areas of three rectangular partitions

## Main Method
The main method sets up standard input/output streams, creates an InputReader for parsing input, creates a PrintWriter for output, instantiates the TaskC solver class, calls its solve method with test number 1, and closes the output writer.

## TaskC.solve Method

### Initial Processing
1. Reads height (h) and width (w) from input
2. **Early exit condition**: If either h or w is divisible by 3, outputs 0 and returns immediately (since the rectangle can be divided into three equal-area sections)

### Variable Setup
- Sets an offset value of 2000 for search ranges
- Initializes minSum to the maximum integer value to track the minimum difference found

### First Search Pattern (Horizontal/Vertical Split)
Searches for a configuration where:
- First section spans full width with height `a`
- Second and third sections split the remaining height with a vertical division at width `b`

The search iterates:
- `a` from h/3 - 2000 to h/3 + 2000 (skipping values ≤ 0 or ≥ h)
- `b` from w/2 - 2000 to w/2 + 2000 (skipping values ≤ 0 or ≥ w)

For each valid combination, calculates:
- s1 = a × w (top section area)
- s2 = b × (h - a) (bottom-left section area)
- s3 = (h - a) × (w - b) (bottom-right section area)

Computes the difference between max and min of these three areas and updates minSum if smaller.

### Second Search Pattern (After Swapping Dimensions)
Swaps h and w, then repeats the same search pattern as above with the swapped dimensions.

### Third Search Pattern (Three Horizontal Strips)
Searches for a configuration with three horizontal strips:
- Iterates `a` from h/3 - 2000 to h/3 + 2000 (skipping values ≤ 0 or ≥ h)
- Iterates `b` from h/3 - 2000 to h/3 + 2000 (skipping values ≤ 0 or ≥ h)
- Skips combinations where a + b ≥ h

For valid combinations, calculates:
- s1 = a × w (top strip)
- s2 = b × w (middle strip)
- s3 = (h - a - b) × w (bottom strip)

Updates minSum with the difference between max and min of these areas.

### Fourth Search Pattern (After Swapping Dimensions Again)
Swaps h and w back, then repeats the three-horizontal-strips search pattern with the original dimensions.

### Output
Prints the final minSum value.

## InputReader Class
A utility class for reading input:
- **Constructor**: Takes an InputStream and wraps it in a BufferedReader
- **next() method**: Returns the next token from input. If no tokens remain in the current StringTokenizer, reads a new line from the buffered reader. Returns null if end of input is reached. Throws RuntimeException on IOException.
- **nextInt() method**: Parses the next token as an integer using Integer.parseInt

## Key Data Dependencies
- The solve method depends on the two input integers for all calculations
- The search ranges depend on the input values (centered around h/3 and w/2)
- The minSum variable accumulates the minimum difference across all search patterns
- The dimension swaps between search patterns affect subsequent calculations
