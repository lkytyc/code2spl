## Overview
This program solves a problem involving splitting a length `N` interval into smaller intervals over `K` steps, tracking the largest interval at each step. It uses a priority queue and a hash map to efficiently process intervals in descending order of size.

## Input
- First line: integer `T` (number of test cases)
- For each test case: two long integers `N` and `K` on a single line

## Output
For each test case, prints: `Case #X: L R` where `X` is the test case number (1-indexed), `L` is the larger half of the final interval, and `R` is the smaller half.

## Data Structures
- `PriorityQueue<Long>`: stores negative interval lengths (so the largest positive length is at the head)
- `HashMap<Long, Long>`: maps interval length to the count of intervals with that length

## Algorithm Flow

### Initialization
- Creates scanner and reads `T`
- For each test case:
  - Reads `N` and `K`
  - Initializes queue with `-N` and count map with `{N: 1}`
  - Sets `ans = 0`

### Main Processing Loop
The loop continues until a break condition is met:

1. **Extract current interval**: Pops the largest interval length from the queue (negated back to positive) and retrieves its count from the map.

2. **Check termination conditions**:
   - If `K <= 1`: the current interval is the answer; break
   - Otherwise, subtract the count of current intervals from `K`
   - If `K <= 0` after subtraction: the current interval is the answer; break

3. **Split the interval**:
   - `large = cur / 2` (integer division)
   - `small = (cur - 1) / 2` (integer division)
   - For each of `large` and `small`:
     - If the length already exists in the map, add the current count to its existing count
     - Otherwise, add the negative length to the queue and set its count to the current count

### Output
- Computes `ans / 2` and `(ans - 1) / 2` as the two halves
- Prints in the format `Case #C: large small`

## Key Control Flow Branches
- **Termination check**: Two separate checks for `K <= 1` and `K <= 0` after decrementing
- **Map update**: Conditional logic for whether a length already exists in the count map
- **Loop structure**: Infinite `while(true)` loop with explicit break statements

## Data Dependencies
- The count of each interval length is carried forward when splitting
- The value of `K` is decremented by the count of intervals processed at each step
- The final answer depends on which interval is being processed when `K` reaches its termination threshold

## Edge Cases
- When `N` is odd, `large` and `small` differ by 1
- When `N` is even, both halves are equal
- The algorithm processes intervals in descending order of size due to the negative-value priority queue
