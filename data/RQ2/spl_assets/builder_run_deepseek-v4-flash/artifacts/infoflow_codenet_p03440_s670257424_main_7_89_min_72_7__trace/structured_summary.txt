## Overview
This program reads a graph with n vertices and m edges, processes union operations to form connected components, and then computes a minimum-cost spanning structure under specific constraints. The output is either a numeric cost, "0", or "Impossible".

## Inputs
- First line: two integers `n` (number of vertices) and `m` (number of edges)
- Second line: `n` integers representing vertex weights stored in array `a`
- Following `m` lines: pairs of integers `x` and `y` representing edges between vertices

## Initialization
- Array `uni` is initialized so that `uni[i] = i` for all vertices, representing each vertex as its own component root
- Array `a` stores the vertex weights from input

## Union Operations (Main Processing Loop)
For each of the `m` edge inputs, the code performs a union operation with a specific pattern:

**Case 1: When `uni[x] != x`** (x is not a root):
- Saves the current root of y as `t`
- Sets `uni[y] = x` temporarily
- Follows the chain from y to find the actual root, storing it in `uni[y]`
- Scans all vertices: if a vertex's root equals the saved `t`, updates it to the new root of y

**Case 2: When `uni[x] == x`** (x is a root):
- Saves the current root of x as `t`
- Sets `uni[x] = y` temporarily
- Follows the chain from x to find the actual root, storing it in `uni[x]`
- Scans all vertices: if a vertex's root equals the saved `t`, updates it to the new root of x

This effectively merges two components, with the root being determined by the chain-following logic.

## Component Counting
After all unions, the code counts `num`, the number of vertices where `uni[i] == i` (roots of components).

## Decision Logic Based on Component Count
1. **If `num == 1`**: All vertices are connected. Output "0" and exit.
2. **If `num * 2 - 2 > n`**: Too many components relative to vertices. Output "Impossible" and exit.
3. **If `num * 2 - 2 == n`**: Exactly the boundary case. Sum all vertex weights and output that sum, then exit.

## Minimum Cost Calculation (for remaining cases)
- Initialize arrays `min` and `minn` with `inf` (a very large value) and zeros respectively
- For each vertex `i`, if `min[uni[i]] > a[i]`, update `min[uni[i]]` to `a[i]` and `minn[uni[i]]` to `i` (tracking minimum weight per component and its vertex index)
- Initialize `ssum` (sum) to 0 and `tnum` to `num - 2`
- For each component root `i`: if `min[i]` is not `inf`, add it to `ssum` and set the corresponding vertex's weight in `a` to `inf`
- Sort array `a` in ascending order using `qsort`
- Add the first `tnum` elements of the sorted array to `ssum`
- Output `ssum` as a long long integer

## Output
- "0" if all vertices are already connected
- "Impossible" if the component count makes the problem infeasible
- The sum of all weights if the boundary condition is met
- Otherwise, the computed minimum cost as a long long integer

## Key Data Dependencies
- The union operations determine component membership, which affects the minimum weight selection
- The component count `num` determines which output branch is taken
- The minimum weights per component and the sorted remaining weights determine the final cost
- The `inf` value (2e30+1) is used as a sentinel for "no value" or "already used"
