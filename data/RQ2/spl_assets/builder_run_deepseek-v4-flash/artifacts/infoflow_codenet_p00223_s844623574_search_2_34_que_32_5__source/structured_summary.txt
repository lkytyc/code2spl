### Inputs
- The program reads from standard input, expecting multiple test cases.
- Each test case begins with two integers `w` and `h` representing the width and height of the grid.
- If `w` is 0, the program terminates.
- For each test case, it reads two pairs of coordinates: `tx, ty` (starting position of the first object) and `kx, ky` (starting position of the second object).
- It then reads `h` lines, each containing `w` integers, representing the grid. A value of 0 indicates a passable cell, and any non-zero value indicates an obstacle.

### Outputs
- For each test case, the program prints either:
  - A positive integer representing the minimum number of moves required for both objects to reach the same cell simultaneously.
  - The string `"NA"` if the objects cannot meet within 99 moves or if no path exists.

### Control Flow and Logic

#### Main Function
- The `main()` function runs an infinite loop.
- It reads `w` and `h`; if `w` is 0, the loop breaks.
- It reads the starting coordinates for both objects.
- It constructs the grid `mp` with a border of obstacle cells (value 1) added on all four sides to simplify boundary checks.
- It calls `search(tx, ty, kx, ky, mp)` for each test case.

#### Search Function
- **Initialization**: 
  - Defines a tuple `direct` containing four movement directions. Each direction is a 4-tuple: (change in x for object 1, change in y for object 1, change in x for object 2, change in y for object 2). The directions are: up, down, left, right.
  - Creates a dictionary `dic` to track visited states, keyed by the tuple `(tx, ty, kx, ky)`.
  - Initializes the starting state with distance 0.
  - Uses a deque `que` for breadth-first search, storing tuples of `(distance, state)`.

- **BFS Loop**:
  - While the queue is not empty, it pops the leftmost element, extracting the distance and the current state.
  - It unpacks the state into `tx, ty, kx, ky`.
  - For each of the four movement directions:
    - **Object 1 movement**: Checks if the cell in the direction is passable (value 0). If so, updates its position; otherwise, it stays in place.
    - **Object 2 movement**: Similarly checks and updates its position, or stays in place if blocked.
    - **Meeting condition**: If the new positions of both objects are the same:
      - If the distance plus 1 is 100 or more, prints `"NA"` and returns.
      - Otherwise, prints the distance plus 1 and returns.
    - **State tracking**: If the new combined state has not been visited, it marks it as visited and adds it to the queue with an incremented distance.

- **Loop Completion**: If the BFS loop completes without finding a meeting point, the `else` clause of the `while` loop executes, printing `"NA"`.

### Data Dependencies
- The grid `mp` is used for all movement checks.
- The dictionary `dic` prevents revisiting the same combined state, ensuring the BFS terminates.
- The distance value in the queue tracks the number of moves taken.

### Key Behaviors
- Both objects move simultaneously in the same direction each step.
- If an object attempts to move into an obstacle or off the grid (prevented by the border), it remains in its current position.
- The search terminates as soon as both objects occupy the same cell, printing the move count.
- The search is limited to 99 moves; if the meeting would occur at move 100 or later, it prints `"NA"` instead.
