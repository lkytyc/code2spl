## Program Overview
This program reads multiple square matrices from standard input, computes a trace and duplicate detection metrics for each, and outputs formatted results. It processes each matrix independently.

## Input
- First integer `t`: number of test cases
- For each test case:
  - Integer `n`: matrix dimensions (n×n)
  - `n²` integers: matrix elements read row by row

## Output
For each test case, one line printed to standard output with format:
`Case #<caseNumber>: <trace> <rowDuplicates> <columnDuplicates>`

## Main Function Control Flow
1. Creates a Scanner for standard input
2. Reads test case count `t`
3. Loops while `t` is greater than zero (decrements after each iteration)
4. For each iteration:
   - Reads matrix size `n`
   - Creates n×n integer array
   - Nested loops read all matrix elements
   - Calls `vestigium(a, n)` with the matrix and size

## Vestigium Function Logic

### Trace Calculation
- Initializes `k` to 0
- Loops through diagonal elements (i from 0 to n-1), adding `a[i][i]` to `k`

### Matrix Transposition
- Creates new n×n array `b`
- Nested loops populate `b[i][j] = a[j][i]`, effectively transposing the original matrix

### Row Duplicate Detection
- Sorts each row of matrix `a` using `Arrays.sort()`
- For each row, compares adjacent elements after sorting
- Counts consecutive duplicates within each row
- Tracks maximum duplicate count across all rows using `Math.max()`
- Resets row counter after each row if duplicates were found

### Column Duplicate Detection
- Sorts each row of transposed matrix `b` (equivalent to sorting columns of original)
- Uses same adjacent comparison logic as rows
- Tracks maximum duplicate count across all columns

### Output Logic
- Initializes `counter` to 1
- Computes `r = count + 1` and `c = count1 + 1` (where count is row duplicates, count1 is column duplicates)
- Four conditional branches based on presence/absence of duplicates:
  1. No duplicates in rows or columns: outputs `k`, `count`, `count1`
  2. Duplicates in both rows and columns: outputs `k`, `r`, `c`
  3. Duplicates in rows only: outputs `k`, `r`, `count1`
  4. Duplicates in columns only: outputs `k`, `count`, `c`
- Increments counter after each output

## Data Dependencies
- Matrix `a` is modified in place during row sorting
- Matrix `b` depends on original matrix values before sorting
- Trace calculation uses original matrix before any sorting
- Row duplicate count depends on sorted rows
- Column duplicate count depends on sorted transposed matrix

## Notable Behavior
- The counter variable is local to `vestigium` and resets to 1 for each matrix, so all test cases will print "Case #1"
- The duplicate counting logic counts consecutive equal elements after sorting, which may overcount if duplicates appear in multiple groups within the same row/column
- The `+1` adjustment in `r` and `c` appears to be an attempt to convert duplicate count to row/column number, but may produce incorrect results depending on duplicate patterns
