# Structured Description

## Input
- Reads from standard input using `getchar_unlocked()`.
- First reads two integers: height `h` and width `w`.
- Then reads `h` rows of `w` characters. Each character is read as a digit (subtracting 48 from the ASCII value), followed by one separator character (which is read and discarded).

## Output
- First line: the number of moves `pos`.
- Then `pos` lines, each containing four integers separated by spaces: `old_y`, `old_x`, `i`, `j`.
- All integers are printed using the `pl` function, which handles zero specially and prints digits one by one.

## Main Data Structures
- `out`: static unsigned short array of size 1,000,000, used to store move quadruples (4 values per move).
- `a`: character array of size 501, used to store the current row's digit values.
- `haveCoin`: boolean flag (char) tracking parity state.
- `old_y`, `old_x`: short integers storing the previous position.

## Control Flow

### Integer Reading Function (`gl`)
- Loops indefinitely, reading characters and subtracting 48.
- Accumulates digits into an integer `x` while the character value is less than 10.
- Breaks when a non-digit character is encountered.
- Returns the accumulated integer.

### Output Function (`pl`)
- Takes an unsigned integer `s`.
- If `s` is zero, prints '0' and returns.
- Otherwise, converts digits into a local buffer by repeated modulo and division.
- Prints the buffered digits in order.

### Main Function
1. Reads `h` and `w` using `gl()`.
2. Initializes `pos` to 0 and `haveCoin` to 0.
3. For each row `i` from 1 to `h`:
   - For each column `j` from 1 to `w`:
     - Reads a digit character, subtracts 48, stores in `a[j]`.
     - Reads and discards one separator character.
   - If row index `i` is odd:
     - Iterates columns `j` from 1 to `w` (left to right).
     - If `haveCoin` is true, records a move: stores `old_y`, `old_x`, `i`, `j` in `out` at position `4*pos` and increments `pos`.
     - Updates `haveCoin` by XOR with `a[j] & 1` (parity of the digit).
     - Updates `old_y` and `old_x` to current position.
   - If row index `i` is even:
     - Iterates columns `j` from `w` down to 1 (right to left).
     - Same logic as odd rows: records move if `haveCoin`, updates `haveCoin` and position.

4. After processing all rows:
   - Prints `pos` followed by a newline.
   - For each move index from 0 to `pos-1`:
     - Prints the four stored values with spaces between them and a newline at the end.

## Key Logic
- The algorithm processes the grid in a serpentine (zigzag) pattern: odd rows left-to-right, even rows right-to-left.
- `haveCoin` tracks whether an odd number of odd-valued cells has been seen since the last recorded move.
- When `haveCoin` becomes true at a cell, a move is recorded from the previous position to the current position.
- The `old_y`/`old_x` pair always holds the most recently visited cell position.

## Data Dependencies
- `haveCoin` depends on the parity of previously visited cells.
- `old_y` and `old_x` are updated after every cell visit.
- The output array `out` is written sequentially based on `pos`.
- The reading of each row depends on the row index for direction of traversal.
