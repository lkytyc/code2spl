# Code Description

## Overview
This program implements a maximum flow algorithm on a directed graph with up to 120 vertices and 1200 edges. It reads graph data from standard input, computes flow using a recursive path-finding approach, and outputs either the total flow or an error message.

## Data Structures

### Edge Structure (TEdge)
- Contains three integer fields: `fmax` (maximum capacity), `flow` (current flow), and `n[2]` (an array of two integers representing the two endpoint vertices of the edge)

### Vertex Structure (TVertex)
- Contains an integer `num` (number of incident edges) and an array `e[1200]` of edge indices

### Global Arrays
- `e[1200]`: Array of all edges
- `v[120]`: Array of all vertices
- `et[120]`: Array used as a visited/exploration marker during traversal
- Global integers `V` (number of vertices) and `E` (number of edges)

## Input
- First line: two integers `V` and `E` (number of vertices and edges)
- Following `E` lines: three integers each representing an edge as `a b c` where:
  - `a` is the source vertex
  - `b` is the destination vertex  
  - `c` is the edge capacity

## Output
- If the algorithm finds positive flow in fewer than 3 iterations: prints the accumulated flow value
- If all 3 iterations return zero flow: prints "er" (error message)

## Main Function Logic

### Initialization Phase
1. Reads `V` and `E` from input
2. Initializes all vertex edge counts to zero
3. Sets `cmax` (maximum capacity) to zero

### Edge Processing Loop
For each of the `E` edges:
1. Reads source (`a`), destination (`b`), and capacity (`c`)
2. Stores the edge with endpoints `a` and `b`
3. Adds the edge index to both vertices' adjacency lists
4. Sets initial flow to zero
5. Special handling: if the destination is the last vertex (`V-1`), the edge is moved to the front of the source vertex's adjacency list and its capacity is added to `cmax`

### Flow Computation Phase
1. Initializes all exploration markers to zero
2. Runs the `route` function up to 3 times, each time starting from vertex 0 to vertex `V-1` with capacity `cmax`
3. If any iteration returns zero or negative flow, prints the accumulated result and exits
4. If all 3 iterations return positive flow, prints "er"

## Route Function (Recursive)

### Parameters
- `s`: current vertex
- `ed`: destination vertex
- `c`: available capacity

### Purpose
Attempts to find a path from vertex `s` to vertex `ed` and push up to `c` units of flow along it.

### Logic
1. Marks current vertex as visited in `et` array
2. Iterates through all edges incident to current vertex

#### Forward Edge Case (edge direction matches traversal)
- If the edge's first endpoint is the current vertex:
  - Checks if the other endpoint is unvisited
  - Checks if there is remaining capacity (fmax - flow > 0)
  - Calculates the minimum of available capacity and remaining edge capacity
  - If the other endpoint is the destination:
    - Pushes flow directly and updates accumulated result
    - Returns early if accumulated result meets or exceeds requested capacity
  - Otherwise:
    - Recursively calls `route` on the other endpoint
    - If recursion returns positive flow, updates edge flow and accumulated result
    - Returns early if accumulated result meets or exceeds requested capacity

#### Reverse Edge Case (edge direction opposite to traversal)
- If the edge's second endpoint is the current vertex:
  - Checks if the first endpoint is unvisited
  - Checks if there is positive flow on the edge (flow > 0)
  - Calculates the minimum of available capacity and current flow
  - Recursively calls `route` on the first endpoint
  - If recursion returns positive flow, reduces edge flow and updates accumulated result
  - Returns early if accumulated result meets or exceeds requested capacity

### Termination
- Unmarks the current vertex in `et` array
- Returns the accumulated flow result

## Control Flow Summary
- The main loop attempts exactly 3 flow augmentations
- Early termination occurs if any augmentation returns zero flow
- The "er" output indicates the algorithm couldn't complete within 3 augmentations
- The algorithm uses both forward and backward edges for flow adjustment (residual network concept)
