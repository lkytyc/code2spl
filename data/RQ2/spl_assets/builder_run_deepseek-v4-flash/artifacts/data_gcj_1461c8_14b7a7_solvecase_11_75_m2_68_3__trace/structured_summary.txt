# Code Description

## Overview
This code implements a solution for an interactive multi-day vase-filling problem. The program communicates with a judge system over standard input/output, making one move per day for 100 days across multiple test cases.

## Inputs
- First line: integer T (number of test cases)
- For each day (1-100): a line containing the day number
- When peeking (P=0): a line containing vase contents (first number is count, followed by vase contents)
- All inputs are read via `getints()` which splits lines and converts to integers

## Outputs
- Each day: prints "V P" where V is vase number (1-20) and P is either:
  - 0 (peek operation)
  - 100 (fill operation)
  - 1-99 (add token to vase)
- Debug information written to stderr

## Data Structures
- `vases`: list of 21 lists (index 1-20 used), each containing tokens placed in that vase
- `peektime`: tracks last day each vase was peeked at
- `stuffV`: candidate vase for stuffing (filling with tokens)
- `tokens`: counter for total tokens placed
- `target`: current target vase being monitored

## Main Loop (Days 1-100)
For each day:
1. Read and verify day number
2. Increment token counter
3. Determine vase (V) and action (P) based on day:

### Day 1-19:
- V = current day number, P = 100 (fill vase completely)

### Day 100:
- V = 20, P = 100 (fill final vase)

### Days 20-99 with stuffV set:
- V = stuffV initially
- If target vase hasn't been peeked in 5+ days: switch to target, P = 0 (peek)
- Else if current vase hasn't been peeked in 30+ days: P = 0 (peek)
- Otherwise: P = smallest positive integer not already in current vase (add token)

### Days 20-99 without stuffV:
- V = target, P = 0 (peek target vase)

## Post-Action Processing
After sending move:
- If P == 0 (peek): read response, filter out values >= 100, store in vase, update peektime
- If P != 100 and P != 0: add P to vase's token list, increment token counter

## Target Selection Logic
After each day's action:
- Calculate m = minimum size across all 20 vases
- If target vase has size == m:
  - Find vase with smallest size (excluding target), tie-broken by most recent peek
  - Set stuffV to that vase
- Otherwise:
  - Find new target = first vase with size == m

## Function Calls
- `printflush(x)`: prints and flushes stdout
- `getline()`: reads and splits stdin line
- `getints()`: converts line to integer list
- `solvecase()`: handles one complete test case (100 days)

## Control Flow
- Outer loop: iterates through T test cases
- Inner loop: iterates through 100 days per case
- Conditional branches based on day number, stuffV status, peek timing, and vase sizes
- While loop to find smallest unused token value for stuffing

## Data Dependencies
- Day number determines initial strategy (days 1-19, day 100, middle days)
- Peek timing affects whether to peek or stuff
- Vase sizes determine target selection and stuffing candidates
- Token values read from peeks affect future stuffing choices
