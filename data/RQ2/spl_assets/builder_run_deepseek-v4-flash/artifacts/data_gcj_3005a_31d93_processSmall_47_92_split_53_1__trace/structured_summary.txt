## Inputs
The program reads from standard input using a `BufferedReader`. The first line contains an integer `t` representing the number of test cases. For each test case, the first line contains two integers separated by a space: the number of rows and the number of columns of a grid. Following that, there are `n` lines (where `n` is the row count), each representing a row of the grid as a string of characters.

## Outputs
The program outputs one line per test case in the format `Case #X: POSSIBLE` or `Case #X: IMPOSSIBLE`, where `X` is the 1-based test case number.

## Main Control Flow
1. Parse the number of test cases `t` from the first input line.
2. For each test case:
   - Read the first line containing grid dimensions.
   - Parse the row count from the first number in that line.
   - Read that many subsequent lines as grid rows.
   - Store all lines for the test case in a list.
3. After reading all test cases, iterate through each stored test case:
   - Increment a counter for the case number.
   - Call `processCase` with the test case data.
   - Print "POSSIBLE" if `processCase` returns true, otherwise print "IMPOSSIBLE".
4. Catch and print stack traces for any `IOException` that occurs during input reading.

## ProcessCase Function
- Parses the first line of the test case into four integers: row count, column count, and two additional parameters.
- Checks a specific condition: if the column count is less than 10, the row count is less than 10, and both additional parameters equal 1, then it delegates to `processSmall`.
- Returns `false` for all other cases.

## ProcessSmall Function
- Scans the grid rows (starting from index 1 in the case list) to find all positions containing the `@` character.
- Records the row and column coordinates of each `@` position.
- Iterates through every possible grid position (every row and column combination).
- For each position, counts how many `@` chips fall into each of four quadrants relative to that position:
  - Bottom-left: chips with row ≤ current row and column ≤ current column
  - Bottom-right: chips with row ≤ current row and column > current column
  - Top-left: chips with row > current row and column < current column
  - Top-right: chips with row > current row and column ≥ current column
- If all four quadrant counts are equal, returns `true` immediately.
- If no position yields equal quadrant counts, returns `false`.

## Data Dependencies
- The grid dimensions from the first line of each test case determine how many subsequent lines are read.
- The `processCase` function depends on the first line's parsed values to decide whether to call `processSmall`.
- The `processSmall` function depends on the grid contents to locate `@` characters and on the grid dimensions to determine the search space for potential split points.

## Loops
- Outer loop over test cases for reading input.
- Inner loop for reading grid rows within each test case.
- Loop over stored test cases for processing and output.
- Nested loops in `processSmall`: one over grid rows, one over grid columns, and an inner loop over all chip coordinates for counting quadrants.

## Function Calls
- `Integer.parseInt` for converting string inputs to integers.
- `String.split` for parsing space-separated and character-separated input.
- `processCase` called from main for each test case.
- `processSmall` called from `processCase` under specific conditions.
