# Code Description

## Global Data
- A global 22×22 character array named `temp` is declared and used for flood-fill computations.

## Function: `compt(int y, int x)`
- **Input:** Row and column indices into the global `temp` array.
- **Behavior:** Recursively counts connected non-zero cells in `temp`.
  - If `temp[y][x]` is non-zero, it sets that cell to zero and returns 1 plus the sum of recursive calls to the four adjacent cells (up, down, left, right).
  - If `temp[y][x]` is zero, it returns 0.
- **Output:** An integer count of connected cells in the region containing the starting position.

## Main Function

### Input Processing
- Reads an unsigned long integer `no_cases` from standard input.
- Loops through each test case.

### Per-Case Setup
- Declares integer variables: `r`, `c`, `x`, `y`, `s`, and `best` (initialized to 0).
- Declares a 20×20 character array `grid`.
- Declares `extras` as a 6-element character array initialized to all zeros.
- Declares `quads` as a 16-element character array with initial values: index 0 = 1, index 15 = 1, all others = 0.

### Grid Reading
- Reads two integers `r` and `c` from input.
- For each row `y` from 0 to r-1:
  - Consumes characters until a newline is encountered.
  - Initializes `last` to 2.
  - For each column `x` from 0 to c-1:
    - Reads a character; if it equals 'W', sets `grid[y][x]` to 1, otherwise 0.
    - Sets `extras[last << 1 | this]` to 1 (recording adjacent-pair patterns).
    - Updates `last` to the current value.
  - Sets boundary cells in `temp` for this row to 0.

### Boundary Setup
- Sets top and bottom boundary rows of `temp` to 0.

### Pattern Recording
- Updates `quads[10]` if `extras[2]` is set (pattern 10 in binary).
- Updates `quads[5]` if `extras[1]` is set (pattern 01 in binary).
- For each 2×2 block in the grid (rows 1 to r-1, columns 1 to r-1):
  - Computes a 4-bit pattern from the four cells and marks that pattern in `quads`.
- For each vertical pair (rows 1 to r-1, columns 0 to r-1):
  - Computes a 2-bit pattern from the two cells, duplicates it to form a 4-bit pattern, and marks it in `quads`.

### Flood-Fill Search
- For each pattern `q` from 0 to 15 that is marked in `quads`:
  - For each possible division point `ydiv` from 0 to r and `xdiv` from 0 to c:
    - Fills `temp` (with 1-based indexing) such that each cell equals 1 if the grid cell matches the bit extracted from pattern `q` based on whether the cell is above/below `ydiv` and left/right of `xdiv`.
    - For each cell in the grid, calls `compt` to count connected regions and updates `best` if a larger count is found.

### Output
- Prints `Case #<case_no+1>: <best>` for each test case.

## Control Flow Summary
- Outer loop over test cases.
- Nested loops for grid reading.
- Nested loops for pattern recording.
- Triple-nested loops for flood-fill testing (pattern × y-division × x-division).
- Within flood-fill testing, double-nested loops for filling `temp` and for calling `compt`.

## Data Dependencies
- `grid` depends on input characters.
- `extras` depends on adjacent cell pairs in each row.
- `quads` depends on `extras` and on 2×2 and vertical-pair patterns from `grid`.
- `temp` is filled based on `grid` and the current pattern/division point.
- `best` accumulates the maximum connected region size found across all pattern/division combinations.
