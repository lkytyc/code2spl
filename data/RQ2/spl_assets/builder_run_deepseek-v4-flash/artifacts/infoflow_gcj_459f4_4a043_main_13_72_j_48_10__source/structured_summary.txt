# Code Description

## Global Data
- A global 22×22 character array named `temp` is declared and used for flood-fill computations.

## Function: `compt(y, x)`
- **Inputs:** Integer coordinates `y` and `x` into the global `temp` array.
- **Behavior:** 
  - Checks if `temp[y][x]` is non-zero.
  - If non-zero, sets `temp[y][x]` to 0 and recursively calls itself on the four adjacent cells (up, down, left, right), returning 1 plus the sum of those recursive calls.
  - If zero, returns 0.
- **Output:** Returns the size of the connected component of non-zero cells containing the starting position.

## Main Function

### Input Processing
- Reads an unsigned long integer `no_cases` from standard input.
- Loops through each test case.

### Per-Case Setup
- Declares integer variables: `r`, `c`, `x`, `y`, `s`, and `best` (initialized to 0).
- Declares a 20×20 character array `grid`.
- Declares `extras` as a 6-element character array initialized to all zeros.
- Declares `quads` as a 16-element character array with initial values: index 0 = 1, index 15 = 1, all others = 0.

### Grid Reading
- Reads two integers `r` and `c` from input.
- For each row `y` from 0 to r-1:
  - Consumes characters until a newline is encountered.
  - Initializes `last` to 2.
  - For each column `x` from 0 to c-1:
    - Reads a character; sets `grid[y][x]` to 1 if the character is 'W', otherwise 0.
    - Sets `extras[last << 1 | this]` to 1, where `this` is the current cell value.
    - Updates `last` to `this`.
  - Sets boundary cells in `temp` for this row to 0.

### Boundary Setup
- Sets top and bottom boundary cells in `temp` to 0 for all columns.

### Pattern Tracking
- Updates `quads[10]` if `extras[2]` is set (representing a 0→1 transition).
- Updates `quads[5]` if `extras[1]` is set (representing a 1→0 transition).
- For each 2×2 block of cells (rows 1 to r-1, columns 1 to r-1):
  - Computes a 4-bit value from the four cells and marks that pattern in `quads`.
- For each vertical pair of cells (rows 1 to r-1, columns 0 to r-1):
  - Computes a 2-bit value from the two cells, duplicates it to form a 4-bit pattern, and marks it in `quads`.

### Component Size Calculation
- For each pattern `q` from 0 to 15 that is marked in `quads`:
  - For each possible division point `ydiv` from 0 to r and `xdiv` from 0 to c:
    - Fills `temp` array: for each cell, sets `temp[y+1][x+1]` to 1 if the grid cell matches the bit from pattern `q` determined by whether the cell is above/below `ydiv` and left/right of `xdiv`, otherwise 0.
    - For each cell in the grid, calls `compt(y+1, x+1)` and updates `best` if the returned component size is larger.

### Output
- Prints `Case #<case_no+1>: <best>` for each test case.

### Termination
- Returns 0 after all cases are processed.

## Control Flow Summary
- Outer loop over test cases.
- Nested loops for grid reading.
- Nested loops for pattern detection.
- Triple-nested loops for component size calculation (pattern × y-division × x-division).
- Recursive flood-fill in `compt` function.

## Data Dependencies
- `grid` depends on input characters.
- `extras` depends on consecutive cell values in each row.
- `quads` depends on `extras` and 2×2/vertical patterns from `grid`.
- `temp` is populated based on `grid` and the current pattern/division.
- `best` accumulates the maximum component size found across all pattern/division combinations.
