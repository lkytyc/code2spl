## Overview
This program reads a description of a metal transmutation system and simulates a process to determine the final quantity of metal 0. It processes multiple test cases, each defining how metals can be transformed into other metals.

## Input Format
- First line: integer T (number of test cases)
- For each test case:
  - First line: integer M (number of metals, indexed 0 to M-1)
  - Next M lines: each contains two integers representing the two metals required to produce metal i (values are 1-based and converted to 0-based indexing)
  - Final line: M integers representing the initial quantities of each metal

## Output Format
For each test case, outputs: `Case #X: Y` where X is the test case number and Y is the final quantity of metal 0.

## Main Control Flow
1. Read T test cases
2. For each test case, call the solve function and print the result

## Solve Function Logic

### Initialization
- Read M (number of metals)
- Create three arrays of size M: part1, part2 (the two metals needed to produce each metal), and quantities (initial amounts)
- Read the M pairs of metal dependencies (converting from 1-based to 0-based indexing)
- Read the M initial quantities

### Transmutation Setup
- Initialize a map called `transmuted` that tracks which metals are currently being transmuted and their required quantities
- Initially, both part1[0] and part2[0] are set to require quantity 1 (these are the metals needed to make metal 0)

### Main Simulation Loop
The loop continues until `stuck` becomes true:

1. **Find minimum transmutation ratio**: For each metal in the transmuted map, calculate `quantities[metal] / required_quantity` and find the minimum value across all entries

2. **Apply transmutation**: 
   - Add the minimum value to quantities[0]
   - Subtract (minimum × required quantity) from each metal in the transmuted map

3. **Process transmutation requirements**: For each metal in the transmuted map:
   - If the required quantity exceeds the available quantity of that metal:
     - Check if this metal cannot be further decomposed (part1 or part2 is 0, or required quantity exceeds 1 billion)
     - If it cannot be decomposed, set stuck = true and break
     - Otherwise, decompose this metal into its two component metals:
       - Add the required quantity to the newTransmuted map for part1[metal]
       - Add the current quantity of metal to quantities[part1[metal]]
       - Add the required quantity to the newTransmuted map for part2[metal]
       - Add the current quantity of metal to quantities[part2[metal]]
       - Subtract the required quantity from the newTransmuted entry for the original metal
       - Set quantities[metal] to 0

4. **Merge newTransmuted into transmuted**: For each entry in newTransmuted:
   - If the metal already exists in transmuted, add the quantities
   - Otherwise, add a new entry
   - If the resulting quantity is 0, remove that metal from transmuted

### Termination
The loop ends when stuck is set to true (a metal cannot be decomposed further) or when all transmutation requirements are satisfied.

### Return Value
Returns the final value of quantities[0] as a string.

## Key Data Dependencies
- The transmuted map tracks which metals are needed and in what quantities
- The quantities array is modified throughout the process
- The part1 and part2 arrays define the decomposition rules for each metal
- The minimum calculation depends on both quantities and transmuted values
- The decomposition process modifies both quantities and the transmuted/newTransmuted maps

## Edge Cases and Special Conditions
- Metals with part1 or part2 equal to 0 cannot be decomposed (metal 0 is the target)
- A required quantity exceeding 1 billion triggers the stuck condition
- The transmuted map can have entries removed when their quantity reaches zero
- The initial transmuted map always contains exactly two entries (part1[0] and part2[0])
