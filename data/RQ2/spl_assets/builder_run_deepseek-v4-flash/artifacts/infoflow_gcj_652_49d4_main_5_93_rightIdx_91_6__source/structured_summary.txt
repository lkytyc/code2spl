## Overview
This program simulates the placement of people into stalls in a bathroom, following the logic of a Google Code Jam problem. It processes multiple test cases, each with a number of stalls and a number of people to place.

## Input
- First line: an integer T representing the number of test cases
- For each test case: a line with two space-separated integers N (number of stalls) and K (number of people to place)

## Output
For each test case, prints a line in the format: `Case #i: y z` where i is the test case number (1-indexed), y is the maximum of the left/right distances for the last placed person, and z is the minimum of those distances.

## Data Structures
- `stall_occupied`: boolean list representing stall occupancy, with sentinel True values at both ends (indices 0 and N+1)
- `Ls`: list tracking the number of empty stalls to the left of each stall
- `Rs`: list tracking the number of empty stalls to the right of each stall
- `Min_s`: list of minimum values between Ls and Rs for each stall
- `Max_s`: list of maximum values between Ls and Rs for each stall

## Initialization Phase
For each test case:
1. Parse N and K from input
2. Create stall_occupied with sentinel True values at both ends and False for all N actual stalls
3. For each stall position (0 to N+1):
   - If occupied (sentinel or actual occupied), set Ls and Rs to -1
   - If empty, set Ls to (position - 1) and Rs to (N - position)
   - Compute Min_s and Max_s for each position

## Main Placement Loop
The program iterates K times to place K people:

### Selection Logic
1. Find the maximum value in Min_s
2. If multiple stalls have this maximum Min_s value:
   - Among those stalls, find the one with the maximum Max_s value
   - If still tied, select the leftmost such stall
3. If only one stall has the maximum Min_s value, select that stall directly

### Placement and Update
For the selected stall index `idx`:
1. Record y = max(Ls[idx], Rs[idx]) and z = min(Ls[idx], Rs[idx])
2. Mark the stall as occupied
3. Set Ls[idx], Rs[idx], Min_s[idx], Max_s[idx] all to -1

### Left-side Update
Starting from idx-1 and moving left while position > 0:
- Stop if an occupied stall is encountered
- For each empty stall encountered, update Rs to (idx - position - 1)
- Recompute Min_s and Max_s for that position

### Right-side Update
Starting from idx+1 and moving right while position < N+2:
- Stop if an occupied stall is encountered
- For each empty stall encountered, update Ls to (position - idx - 1)
- Recompute Min_s and Max_s for that position

## Control Flow Details
- The main loop runs exactly K times per test case
- The left and right update loops terminate when hitting an occupied stall or reaching the boundaries
- The selection logic uses numpy arrays for finding indices when there are ties
- After each test case, output is flushed to stdout

## Dependencies
- Uses numpy for array operations in tie-breaking logic
- Uses sys for stderr output (eprint function, though not called in main flow) and stdout flushing

## Edge Cases
- The sentinel stalls at positions 0 and N+1 are always occupied and never selected
- When all stalls become occupied, the update loops will immediately terminate
- The program assumes K ≤ N (valid input)
