# Function: solve_case(in_times, edges)

## Inputs
- `in_times`: A list of integers representing initial time values for components
- `edges`: A list of tuples (a, b) representing connections between components

## Initialization
- Creates `latencies` list with length equal to number of edges, initialized to 1,000,000
- Converts all edge endpoints from 1-based to 0-based indexing
- Creates `abs_times` list with length equal to `in_times`, initialized to 1,000,000
- Copies positive values from `in_times` into `abs_times` at corresponding indices

## Processing Negative Times
- Collects all negative values from `in_times` as tuples of (absolute value, original index)
- Sorts these tuples in ascending order by absolute value

## Main Processing Loop
- Initializes `current_time` to 0 and `received` to 1
- Continues while there are pending negative-time entries

### Branch: When next pending time equals `received`
- Increments `current_time` by 1
- Counts all pending entries with this same time value
- Assigns `current_time` to `abs_times` at each corresponding index
- Removes processed entries from the pending list
- Updates `received` by adding the count of newly processed entries

### Branch: When next pending time does not equal `received`
- Collects all values from `abs_times` that are greater than `current_time`
- Sets `current_time` to the minimum of these collected values
- Counts how many entries in `abs_times` are less than or equal to this new `current_time`

## Post-Processing
- Prepends 0 to `abs_times` (shifting all indices by 1)
- Creates list of (time, component_index) pairs and sorts by time
- For each component (excluding the prepended 0 entry):
  - Iterates through all edges
  - If the component matches edge endpoint A:
    - If A's time exceeds B's time, calculates latency as the difference and breaks
  - If the component matches edge endpoint B:
    - If B's time exceeds A's time, calculates latency as the difference and breaks

## Output
- Returns a space-separated string of all latency values

# Function: main()

## Inputs
- Reads integer T from standard input (number of test cases)

## Processing
- For each test case (1 through T):
  - Reads two integers: `num_comps` and `num_edges`
  - Reads `in_times` as a list of integers
  - Reads `num_edges` lines, each containing a tuple of two integers
  - Calls `solve_case` with the collected data
  - Prints result formatted as "Case #X: result"

## Control Flow
- Single loop over test cases
- Nested loop for reading edges
- Calls `solve_case` once per test case

## Data Dependencies
- `solve_case` depends on both `in_times` and `edges` from main
- Latency calculations depend on the processed `abs_times` values
- Edge iteration order affects which latency value gets set when both endpoints match conditions
