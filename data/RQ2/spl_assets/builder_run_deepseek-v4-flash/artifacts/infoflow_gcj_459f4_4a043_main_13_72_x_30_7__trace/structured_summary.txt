# Code Description

## Global Data
- A global 22×22 character array named `temp` is declared and used for flood-fill computations.

## Function: `compt(int y, int x)`
- **Input:** Row and column indices into the global `temp` array.
- **Behavior:** Recursively counts connected non-zero cells in `temp`.
  - If `temp[y][x]` is non-zero, it sets that cell to zero and returns 1 plus the sum of recursive calls to the four adjacent cells (up, down, left, right).
  - If `temp[y][x]` is zero, it returns 0.
- **Output:** An integer count of connected cells in the region starting at the given position.

## Main Function

### Input Processing
- Reads an unsigned long integer `no_cases` from standard input.
- Loops through each test case.

### Per-Case Variables
- Integer variables: `r` (rows), `c` (columns), `x`, `y`, `s` (size), `best` (best size found).
- Character arrays: `grid` (20×20), `extras` (size 6, initialized to zeros), `quads` (size 16, initialized with 1 at index 0 and index 15, zeros elsewhere).

### Grid Reading
- Reads two integers `r` and `c` from input.
- For each row `y` from 0 to r-1:
  - Consumes characters until a newline is encountered.
  - For each column `x` from 0 to c-1:
    - Reads a character; if it equals 'W', sets `grid[y][x]` to 1, otherwise 0.
    - Updates `extras` array based on transitions between consecutive cells (using bit-shifting of previous and current values).
  - Sets boundary cells in `temp` for this row to 0.

### Boundary Setup
- Sets top and bottom boundary rows of `temp` to 0.

### Pattern Tracking
- Updates `quads` array based on `extras` values (indices 2 and 1).
- For each 2×2 block in the grid (rows 1 to r-1, columns 1 to r-1), computes a 4-bit pattern from the four cells and marks that pattern as present in `quads`.
- For each vertical pair of cells (rows 1 to r-1, columns 0 to r-1), computes a 2-bit pattern and marks the corresponding doubled pattern in `quads`.

### Main Search Loop
- For each pattern `q` from 0 to 15 that is marked as present in `quads`:
  - For each possible division point `ydiv` from 0 to r and `xdiv` from 0 to c:
    - Builds a temporary grid in `temp` (offset by 1 in both dimensions) where each cell is 1 if the original grid cell matches the bit from pattern `q` determined by whether the cell is above/below `ydiv` and left/right of `xdiv`.
    - For each cell in the temporary grid, calls `compt` to find the size of the connected region containing that cell.
    - Updates `best` if any region size is larger.

### Output
- Prints `Case #<case_no+1>: <best>` for each test case.

## Control Flow Summary
- Outer loop over test cases.
- Nested loops for grid reading.
- Nested loops for pattern detection.
- Triple-nested loops for division points and grid scanning.
- Recursive calls in `compt` for flood-fill.

## Data Dependencies
- `grid` depends on input characters.
- `extras` depends on consecutive cell values in each row.
- `quads` depends on `extras` and 2×2/vertical patterns from `grid`.
- `temp` is rebuilt for each pattern/division combination from `grid` and `q`.
- `best` accumulates the maximum region size across all pattern/division combinations.
