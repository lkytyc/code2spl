# Code Description

## Overview
This program processes multiple test cases involving a pursuit scenario on a 2001×2001 grid. It reads input containing coordinates and a movement string, then determines whether and when an interception is possible.

## Inputs
- First line: integer T (number of test cases)
- For each test case:
  - Three values on one line: integers X, Y, and string M
  - X, Y represent target coordinates (with sign conventions)
  - M is a string of directional characters (N, S, E, W)

## Outputs
- For each test case, outputs "Case #t: " followed by either:
  - An integer representing the time of successful interception
  - "IMPOSSIBLE" if interception cannot occur

## Main Data Structures
- Direction arrays dx, dy for four cardinal movements
- 2001×2001 integer grid `g` marking target positions
- 2001×2001 boolean grids `visited` and `visited2` for BFS tracking
- List of coordinate pairs `tour` tracking target movement path
- Queue of Pair objects for BFS traversal

## Processing Flow

### Target Path Construction
1. Initialize target starting position at grid center (1000, 1000)
2. Mark this position in grid `g` and add to tour list
3. For each character in movement string M:
   - Update position based on direction (N decreases y, S increases y, E increases x, W decreases x)
   - Mark new position in grid and add to tour

### BFS Search for Nearest Target Position
1. Set starting position for searcher at (1000-X, 1000+Y)
2. Perform breadth-first search from this position
3. Search continues until finding a grid cell marked as 1 (target visited position)
4. Records distance (`tmp`) and coordinates (`nearX`, `nearY`) of first target position found
5. If no target position found, result is IMPOSSIBLE

### Time Comparison and Result Determination
1. Find index `ti` in tour list matching the found target position
2. If BFS distance ≤ tour index:
   - Calculate result as `tmp + (ti - tmp + 1) / 2`
3. If BFS distance > tour index:
   - Iterate through tour positions from index `ti`
   - For each position, check if the corresponding future target position (at index `tmp + i - ti`) has been visited
   - If a match is found, output the current index `i`
   - If no match found in loop, output IMPOSSIBLE

## Key Logic Details
- The BFS explores all four cardinal directions from each position
- Boundary checking prevents movement outside the 2001×2001 grid
- The `visited` array prevents revisiting cells during BFS
- The second `visited2` array tracks which future target positions have been checked
- The Pair class stores x, y coordinates and distance from start

## Control Flow Branches
- Main loop iterates through all test cases
- BFS loop continues until queue is empty or target found
- Inner loop checks all four directions with boundary validation
- Conditional logic determines whether interception time is based on direct meeting or future path crossing
- Final conditional outputs either success time or IMPOSSIBLE
