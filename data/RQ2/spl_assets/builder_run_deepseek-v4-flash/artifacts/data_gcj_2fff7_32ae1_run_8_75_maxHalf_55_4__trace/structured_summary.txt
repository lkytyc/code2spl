## Overview
This program reads multiple test cases from standard input, processes geometric rectangle dimensions, and outputs formatted results. It appears to calculate maximum possible perimeter increases for rectangles under certain constraints.

## Input
- First line: integer `numCases` indicating number of test cases
- For each test case:
  - Integer `n` (number of rectangles)
  - Double `p` (target perimeter)
  - For each of `n` rectangles: two integers representing rectangle dimensions

## Output
- For each test case, a line formatted as `Case #X: ` followed by either:
  - A decimal value with 7 decimal places
  - An empty line (just newline)

## Processing Logic

### Data Preparation
For each test case:
1. Read `n` and `p`
2. For each rectangle:
   - Store dimensions with smaller value first, larger second
   - Accumulate `minP` = sum of 2 × (first + second) for all rectangles

### Uniformity Check
- Check if all rectangles have identical dimensions by comparing each rectangle's dimensions to the first rectangle
- Set `small` flag to true if all match, false otherwise

### Main Decision Branch
**Branch 1: If `minP` equals `p`**
- Output `p` formatted to 7 decimal places

**Branch 2: If `minP` is less than `p`**
- Calculate `maxRem` = `p` - `minP` (remaining perimeter to distribute)

**Sub-branch A: If all rectangles are identical (`small` is true)**
1. First loop: Count how many rectangles can receive a full 2 × smaller-dimension increase
   - While `maxRem` ≥ 2 × smaller dimension, subtract that amount and increment counter
2. If `maxRem` becomes exactly 0:
   - Output `p` formatted to 7 decimal places
3. Otherwise:
   - Calculate `maxAdd` = diagonal length minus smaller dimension (using Pythagorean theorem)
   - Second loop: Count how many rectangles can receive 2 × `maxAdd` increase
   - If not all counted rectangles can receive full increase, subtract one more `maxAdd` × 2 from `maxRem` (with floor at 0)
   - Output `p` minus remaining `maxRem`, formatted to 7 decimal places

**Sub-branch B: If rectangles are not all identical (`small` is false)**
- Output just a newline (empty result)

## Key Dependencies
- The `small` flag determines which calculation path is taken
- `minP` calculation depends on all rectangle dimensions
- The `maxRem` value is modified through the loops and affects final output
- The `maxAdd` calculation depends on the first rectangle's dimensions (valid only when all rectangles are identical)

## Control Flow Summary
- Outer loop iterates through test cases
- Inner loop reads rectangle dimensions
- Conditional branching based on:
  - Whether `minP` equals `p`
  - Whether all rectangles are identical
  - Whether `maxRem` reaches zero during calculations
- Two sequential loops for counting rectangles that can receive increases
- Final output uses `System.out.printf` with the accumulated string builder
