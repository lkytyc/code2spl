# Code Description

## Overview
This program processes multiple test cases involving a grid-based movement problem. It reads input from standard input and produces output to standard output.

## Input
- First line: integer T (number of test cases)
- For each test case:
  - Three values on one line: integers X, Y, and string M
  - X and Y represent target coordinates
  - M is a string of directional characters (N, S, E, W)

## Output
- For each test case, outputs "Case #t: " followed by either:
  - An integer representing the minimum time to meet
  - The string "IMPOSSIBLE"

## Data Structures
- Direction arrays: dx = {0, 1, 0, -1}, dy = {1, 0, -1, 0}
- Grid g: 2001x2001 integer array marking visited positions
- Grid visited: 2001x2001 boolean array for BFS tracking
- Grid visited2: 2001x2001 boolean array for second phase tracking
- Tour list: List of coordinate pairs representing a path
- Queue for BFS: LinkedList of Pair objects
- Pair class: immutable object with x, y, and dist fields

## Main Algorithm Flow

### Initialization
- Scanner reads from standard input
- StringBuilder accumulates all output
- T test cases are processed in a loop

### Per Test Case Processing

#### Path Construction
1. Read X, Y, and movement string M
2. Initialize grid g with all zeros
3. Set starting position at (1000, 1000)
4. Mark starting position in grid g
5. Process each character in M:
   - 'N': decrease y-coordinate
   - 'S': increase y-coordinate
   - 'E': increase x-coordinate
   - 'W': decrease x-coordinate
   - Mark each new position in grid g
   - Add each position to tour list

#### BFS Search
1. Set starting position at (1000-X, 1000+Y)
2. Initialize BFS queue with starting position and distance 0
3. While queue is not empty:
   - Dequeue current position
   - If current position is marked in grid g, record distance and coordinates, then break
   - Mark position as visited
   - For each of 4 directions:
     - Calculate new coordinates
     - Skip if out of bounds (0 to 2000)
     - Skip if already visited
     - Add new position to queue with distance+1

#### Result Determination
1. If BFS found no match (tmp == -1), output "IMPOSSIBLE"
2. Otherwise, find index ti in tour where coordinates match the BFS result
3. If BFS distance (tmp) is less than or equal to ti:
   - Output tmp + (ti - tmp + 1) / 2
4. If BFS distance is greater than ti:
   - Iterate from index ti through tour
   - For each index i, mark the position from tour at index (tmp + i - ti) in visited2
   - Check if the current tour position at index i is in visited2
   - If found, output index i and mark success
   - If no match found, output "IMPOSSIBLE"

## Control Flow Branches
- Main loop iterates T times
- Movement processing branches on each character in M
- BFS has conditional checks for grid matches, bounds, and visited status
- Result determination has two main branches based on comparison of tmp and ti
- Second branch has inner loop with success/failure conditions

## Function Calls
- Scanner methods: nextInt(), next()
- StringBuilder methods: append()
- Queue methods: offer(), poll(), isEmpty()
- List methods: add(), get(), size()
- String method: charAt(), length()

## Data Dependencies
- Grid g depends on movement string M
- BFS results depend on grid g and starting position (derived from X, Y)
- Final answer depends on BFS results and tour list
- visited2 array depends on tour positions and BFS distance
