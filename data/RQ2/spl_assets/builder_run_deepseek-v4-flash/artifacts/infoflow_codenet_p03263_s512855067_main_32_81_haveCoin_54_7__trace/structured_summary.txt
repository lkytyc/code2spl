# Code Description

## Input
- Reads two integers from standard input using a custom fast integer parser (`gl`), representing height `h` and width `w`.
- Then reads `h * w` pairs of characters from standard input. Each pair consists of a digit character (0-9) followed by a separator character (which is read and discarded). The digit represents a cell value.

## Output
- Prints the count of generated line segments, followed by a newline.
- Then prints each segment as four space-separated integers (y1, x1, y2, x2) on its own line.

## Helper Functions

### `gl()` - Fast Integer Reader
- Reads characters from standard input using `getchar_unlocked()`.
- Subtracts 48 (ASCII '0') from each character.
- Continues reading while the resulting value is less than 10 (i.e., while it's a digit).
- Accumulates the digits into an integer value (multiplying by 10 and adding each digit).
- Returns the accumulated integer when a non-digit character is encountered.

### `pl(unsigned int s)` - Fast Integer Printer
- Converts an unsigned integer to its decimal string representation.
- If the value is 0, prints '0' directly and returns.
- Otherwise, extracts digits from least significant to most significant into a local buffer.
- Prints the digits in correct order using `putchar_unlocked()`.

## Main Algorithm

### Data Structures
- `out`: Static array of 1,000,000 unsigned shorts, used to store segment endpoints (4 values per segment).
- `a`: Character array of size 501, used to store one row of cell values at a time.
- `haveCoin`: Boolean flag (0 or 1) tracking parity state.
- `old_y`, `old_x`: Coordinates of the last processed cell.

### Processing Loop
1. Read grid dimensions `h` and `w`.
2. Initialize `pos` (segment counter) to 0 and `haveCoin` to 0.

3. For each row `i` from 1 to `h`:
   - Read `w` cell values into array `a` (reading and discarding the separator character after each).
   - If row index is odd:
     - Process columns left to right (j from 1 to w).
   - If row index is even:
     - Process columns right to left (j from w down to 1).

4. For each cell processed (in the appropriate direction):
   - If `haveCoin` is true (1), record a segment:
     - Store `old_y`, `old_x`, current row `i`, current column `j` into the output array at position `4*pos` through `4*pos+3`.
     - Increment `pos`.
   - Toggle `haveCoin` by XORing with the least significant bit of the current cell value (`a[j] & 1`).
   - Update `old_y` and `old_x` to the current cell coordinates.

### Output Generation
- Print the total number of segments (`pos`) followed by a newline.
- For each segment index from 0 to `pos-1`:
  - Print the four stored values (y1, x1, y2, x2) separated by spaces, followed by a newline.

## Control Flow Summary
- The main loop iterates through all grid cells in a serpentine (zigzag) pattern: odd rows left-to-right, even rows right-to-left.
- The `haveCoin` flag toggles based on the parity of each cell value.
- Segments are generated whenever `haveCoin` is true when entering a new cell, connecting the previous cell to the current one.
- The algorithm processes the entire grid in a single pass, storing all segments before outputting them.
