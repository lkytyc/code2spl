# Code Description

## Overview
This program solves a Rock-Paper-Scissors tournament problem. It reads multiple test cases, each containing a set of robot programs (strings of R, P, S characters), and determines a single winning sequence of moves that beats all robots, or reports "IMPOSSIBLE" if no such sequence exists.

## Input
- First line: integer T (number of test cases)
- For each test case:
  - First line: integer A (number of robots)
  - Next A lines: each contains a string of characters from {R, P, S} representing a robot's cyclic move pattern

## Output
- For each test case: "Case #i: " followed by either:
  - A string of moves (characters from {R, P, S}) that beats all robots
  - "IMPOSSIBLE" if no such string exists

## Main Control Flow

### Top-Level Loop
- Reads T from standard input
- Iterates through each test case (1 to T)
- For each test case:
  - Reads A (number of robots)
  - Reads each robot's pattern string C[j] and stores its length L[j]
  - Prints "Case #i: " prefix
  - Calls solve(A, C, L)

### solve Function
- Initializes an empty answer string `ans` and position counter `pos` = 0
- Creates boolean array `isAlive` of length A, all initially True
- Enters an infinite loop that continues until a result is produced

#### Loop Body:
1. **Initialize possibilities dictionary** with keys 'R', 'S', 'P' all set to 0
2. **Initialize prediction lists** predR, predS, predP as empty lists
3. **Check termination**: If no robots are alive, print current `ans` and return
4. **Process each alive robot**:
   - Determine robot's move at current position: C[i][pos % L[i]]
   - Mark that move as possible (set possibilities value to 1)
   - Add robot index to corresponding prediction list
   - If all three moves (R, S, P) are possible among alive robots, print "IMPOSSIBLE" and return

5. **Extract counts** (r, s, p) from possibilities dictionary

6. **Handle single-move cases** (only one move type possible):
   - Only R possible: append "P" to ans, print ans, return
   - Only S possible: append "R" to ans, print ans, return
   - Only P possible: append "S" to ans, print ans, return

7. **Length limit check**: If ans length reaches 500, print "IMPOSSIBLE" and return

8. **Handle two-move cases**:
   - R and S possible: kill all robots in predS, append "R" to ans
   - R and P possible: kill all robots in predR, append "P" to ans
   - S and P possible: kill all robots in predP, append "S" to ans

9. **Increment position** pos by 1 and repeat loop

### isCycleCorrect Function (defined but not called in main flow)
- Takes parameters A, C, L, and ans
- Checks if answer string `ans` beats all robots
- For each robot i:
  - Compares robot's moves against ans moves position by position
  - Uses modulo arithmetic for cyclic patterns
  - Returns False if robot beats ans at any position
  - Returns True only if all robots are beaten by ans
- Contains debug print statements controlled by global `debug` flag

## Key Data Dependencies
- Robot patterns C and lengths L are read from input and passed to solve
- The `isAlive` array tracks which robots remain in consideration
- The `possibilities` dictionary tracks which move types are present among alive robots
- Prediction lists (predR, predS, predP) track which robots play each move at current position
- The answer string `ans` accumulates the winning move sequence

## Game Logic Rules
- Rock (R) beats Scissors (S)
- Scissors (S) beats Paper (P)
- Paper (P) beats Rock (R)
- The program constructs ans by choosing moves that eliminate robots while avoiding impossible situations

## Global Settings
- Recursion limit set to 100000
- Debug flag set to False (controls debug print statements throughout)
