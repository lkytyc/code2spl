# Code Description

## Overview
This program processes multiple test cases involving a pursuit scenario on a 2001×2001 grid. It reads input containing coordinates and a movement string, then determines whether and when an interception is possible.

## Inputs
- First line: integer T (number of test cases)
- For each test case:
  - Three values: X, Y (integers), and M (string of directional characters N, S, E, W)

## Outputs
- For each test case, outputs "Case #t: " followed by either:
  - An integer representing the time of interception
  - "IMPOSSIBLE" if interception cannot occur

## Data Structures
- Direction arrays dx = {0, 1, 0, -1} and dy = {1, 0, -1, 0} representing E, S, W, N movements
- Grid g (2001×2001) marking positions visited by the target
- Tour list storing the target's path as coordinate pairs
- Visited arrays for BFS tracking
- Pair class storing x, y coordinates and distance

## Main Processing Flow

### Initialization
- Creates scanner for input and StringBuilder for output
- Reads number of test cases T

### Per Test Case Processing

#### Target Path Construction
- Reads X, Y, and movement string M
- Initializes target position at grid center (1000, 1000)
- Marks starting position in grid g
- For each character in M:
  - Updates position based on direction (N decreases y, S increases y, E increases x, W decreases x)
  - Marks new position in grid
  - Adds position to tour list

#### BFS Search for Nearest Target Position
- Sets starting position for pursuer at (1000-X, 1000+Y)
- Performs breadth-first search from pursuer's start position
- Searches for the first grid cell marked by the target's path
- Tracks distance traveled and coordinates of first target position found
- BFS explores 4-directional neighbors, skipping out-of-bounds and visited cells

#### Decision Logic
- If no target position found (tmp = -1): outputs "IMPOSSIBLE"
- Otherwise:
  - Finds the index in tour where the found target position occurs
  - If BFS distance ≤ tour index: calculates answer as tmp + (ti-tmp+1)/2
  - If BFS distance > tour index: 
    - Iterates through tour positions from the found index
    - For each position, marks the corresponding future target position as visited
    - Checks if current tour position has been visited
    - If match found: outputs the tour index as answer
    - If no match found: outputs "IMPOSSIBLE"

## Key Control Flow Branches
- Direction handling uses independent if statements (not else-if)
- BFS continues until queue empty or target found
- Boundary checking prevents out-of-bounds access
- Two different calculation methods depending on whether BFS distance is less than or greater than tour index

## Function Calls
- Scanner methods: nextInt(), next()
- StringBuilder: append()
- Queue operations: offer(), poll(), isEmpty()
- List operations: add(), get(), size()

## Data Dependencies
- Grid g depends on target's movement path
- Tour list mirrors grid positions in order
- BFS result depends on grid g and starting position
- Final answer depends on BFS distance, tour index, and position matching
