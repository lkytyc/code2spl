## Overview
This program reads test cases from standard input and outputs a computed answer for each case. It processes arrays of integers and determines a minimum number of cuts needed based on specific conditions involving duplicate values and doubling relationships.

## Input
- First line: integer `t` (number of test cases)
- For each test case:
  - One line with two integers: `n` (array size) and `d` (target count)
  - One line with `n` space-separated integers (the array values)

## Output
- For each test case, a line in the format: `Case #z: answer`
- The answer is always 0, 1, or 2

## Data Structures
- `Pair` class: stores a value and its frequency count; sorts by count in descending order
- `array`: sorted array of input values
- `ps`: array of Pair objects representing unique values and their frequencies

## Processing Logic

### Initial Setup
- Read test case count
- For each test case, read `n` and `d`, then read the array values
- Sort the array in ascending order

### Special Cases for n=1
- If `n==1` and `d==3`: output 2
- If `n==1` and `d==2`: output 1

### Frequency Counting
- Count consecutive duplicates in the sorted array
- Create Pair objects for each unique value with its frequency
- Sort the Pair array by frequency (descending)

### Decision Logic
The program checks conditions in order:

1. **If highest frequency ≥ d**: Output 0 (no cuts needed)

2. **If d==2 and highest frequency is 1**: Output 1

3. **If d==3 and highest frequency is 2**:
   - If the most frequent value is not the largest array value: Output 1
   - If the most frequent value is the largest array value:
     - If second highest frequency is also 2: Output 1
     - Otherwise, check if any value in the array is exactly double another value (either direction). If found: Output 1
     - If no doubling relationship found: Output 2

4. **If d==3 and highest frequency is 1**:
   - Check if any value in the array is exactly double another value (either direction). If found: Output 1
   - If no doubling relationship found: Output 2

## Control Flow Details
- The doubling check uses nested loops over all array elements (O(n²) complexity)
- The `outer` label allows breaking out of both loops when a match is found
- A boolean flag tracks whether a doubling relationship was found

## Function Calls
- Uses standard Java I/O classes (BufferedReader, StringTokenizer)
- Uses Arrays.sort for sorting
- Uses StringBuffer for output accumulation

## Data Dependencies
- The frequency counting depends on the sorted array order
- The decision logic depends on both frequency counts and the actual array values
- The doubling check depends on the original array values (not just frequencies)
