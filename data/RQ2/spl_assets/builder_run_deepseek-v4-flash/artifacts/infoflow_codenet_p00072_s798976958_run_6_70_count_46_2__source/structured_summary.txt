## Overview
This program reads multiple test cases from standard input, processes a graph with weighted edges, and outputs a computed count value for each test case. The computation involves finding minimum edge weights in a specific pattern and accumulating a derived value.

## Input
- Multiple test cases are read until end of input
- Each test case begins with an integer `n` (number of nodes)
- If `n` is 0, processing stops
- Next integer `m` specifies number of edges
- Then `m` lines follow, each containing three comma-separated integers: node `a`, node `b`, and edge weight `c`

## Output
- For each test case, a single integer is printed on its own line

## Processing Logic

### Data Structure Initialization
- An `n × n` cost matrix is created and initialized with `Integer.MAX_VALUE` for all entries
- This represents an adjacency matrix where missing edges have maximum value

### Edge Reading
- For each of the `m` edges:
  - Parse the three comma-separated values
  - Set `cost[a][b] = c` and `cost[b][a] = c` (undirected graph)

### First Pass (Rows 0 to n-2)
- For each row `i` from 0 to n-2:
  - Find the minimum cost edge in that row among columns `j` where `j > i`
  - Skip entries with `Integer.MAX_VALUE`
  - Track the minimum value and its coordinates (`ti`, `tj`)
  - If a valid minimum is found (not 0):
    - Add `(min/100 - 1)` to the running count
    - Mark both nodes `ti` and `tj` as "flagged" in boolean array `fl`

### Second Pass (Unflagged Nodes)
- For each node `i` from 0 to n-1:
  - Skip if already flagged
  - Find the minimum cost edge in column `i` among rows `j` where `j < i`
  - Skip entries with `Integer.MAX_VALUE`
  - If a valid minimum is found (not 0):
    - Add `(min/100 - 1)` to the running count

### Count Accumulation
- The count starts at 0 for each test case
- Each contribution is `min/100 - 1` where `min` is the minimum edge weight found
- Integer division is used for `min/100`

## Control Flow
- Outer `while` loop continues while input has more tokens
- `break` exits when `n == 0`
- Nested loops iterate through matrix rows and columns
- Conditional checks skip `Integer.MAX_VALUE` entries and handle zero-minimum cases

## Data Dependencies
- The second pass depends on which nodes were flagged in the first pass
- The first pass processes only upper-triangular entries (where column > row)
- The second pass processes only lower-triangular entries (where row < column)
- The final count depends on both passes' accumulated values
