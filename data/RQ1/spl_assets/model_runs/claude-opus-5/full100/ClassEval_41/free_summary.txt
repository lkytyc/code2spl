`GomokuGame` implements the board and turn logic for a two-player Gomoku game. Here's what it does:

**State**: It holds a square grid of a configurable size, initialized with empty spaces, and tracks whose turn it is, alternating between `'X'` and `'O'` starting with `'X'`.

**Making a move** (`make_move`): Takes a row and column. If the cell is empty, it places the current player's symbol there, flips the active player, and returns `True`. If the cell is already occupied, it does nothing and returns `False`.

**Checking for a winner** (`check_winner`): Scans every non-empty cell on the board and checks four directions from it — horizontal, vertical, and both diagonals. If any direction yields five consecutive matching symbols, it returns that symbol (`'X'` or `'O'`). If no winner is found, it returns `None`.

**Five-in-a-row detection** (`_check_five_in_a_row`): A private helper that walks up to four steps in a given direction from a starting cell, verifying that each subsequent cell holds the same symbol. Returns `True` only if all four steps stay in bounds and match, giving a count of exactly 5.

A few behavioral notes worth flagging:

- There's no draw detection — a full board with no winner is not handled.
- The winner check looks for exactly 5 in a row, but doesn't exclude longer runs (6+), which standard Gomoku rules may treat differently depending on the ruleset.
- There's no bounds checking in `make_move` — passing an out-of-range row or column will raise an `IndexError`.
