`CalendarUtil` is a simple in-memory calendar manager. Here's what it does:

**Storage**
It holds a flat list of event dictionaries in `self.events`. Each event is expected to have at least `date`, `start_time`, and `end_time` keys (all `datetime` objects).

**Core operations**
- `add_event` / `remove_event` — append or remove an event dict from the list. Removal silently does nothing if the event isn't present.
- `get_events(date)` — returns all events whose `date` field (date portion only) matches the given date.
- `is_available(start_time, end_time)` — checks whether a proposed time range overlaps any existing event using standard overlap logic (`start < other_end AND end > other_start`). Returns `True` if no conflict is found.
- `get_available_slots(date)` — divides a full day (midnight to 23:59) into 60-minute windows and returns every slot for which `is_available` returns `True`. The last window starts at 23:00 and ends at 24:00, so 23:00–23:59 is effectively excluded due to the loop condition.
- `get_upcoming_events(num_events)` — walks the event list in insertion order and collects events whose `start_time` is at or after the current moment, stopping once `num_events` are gathered. Because it doesn't sort first, it returns the first *n* future events by insertion order, not necessarily the next *n* chronologically.

**Notable gaps / behaviors**
- No sorting is applied anywhere, so `get_upcoming_events` can miss earlier future events that were added later.
- Events are compared by object identity in `remove_event`, so passing a reconstructed dict won't match an existing one.
- There's no input validation or timezone awareness.
