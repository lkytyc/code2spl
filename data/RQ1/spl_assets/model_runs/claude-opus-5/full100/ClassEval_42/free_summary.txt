The `Hotel` class models a simple hotel room booking system with four operations.

**State:** Each hotel instance tracks two dictionaries — `available_rooms`, which maps room types (e.g. `'single'`, `'double'`) to a count of available rooms, and `booked_rooms`, which maps room types to a nested dict of guest name → number of rooms booked.

**`book_room(room_type, room_number, name)`** attempts to reserve `room_number` rooms of a given type under a guest's name. It returns `False` if the room type doesn't exist at all, returns the remaining availability count if the request exceeds availability but some rooms are still free, returns `False` if the type exists but is fully booked, and returns `"Success!"` on a successful booking — decrementing `available_rooms` and recording the booking under the guest's name.

**`check_in(room_type, room_number, name)`** processes a guest arriving. It returns `False` if the room type has no bookings or the guest has no booking under that type. If the guest tries to check in more rooms than they booked, it returns `False`. If the count matches exactly, the booking record is removed entirely. If the count is less than booked, only that many are deducted from the booking (partial check-in). Note: this method has no explicit return for the success cases, so it returns `None`.

**`check_out(room_type, room_number)`** adds rooms back to `available_rooms` when a guest leaves. It handles both types that already exist in the availability dict and new types that don't.

**`get_available_rooms(room_type)`** returns the current availability count for a given room type.

One notable gap: `check_out` doesn't verify that rooms being returned were ever booked, so it can inflate availability beyond the original count. Similarly, `check_in` doesn't restore `available_rooms` when a guest checks in — the room count was already decremented at booking time, so rooms only return to the pool via `check_out`.
