`MetricsCalculator2` is a stateless utility class with two static methods, `mrr` and `map`, that compute standard information retrieval metrics.

Both methods share the same input contract. They accept either:
- a single tuple of `(sub_list, total_num)`, where `sub_list` is a binary relevance array (1 = relevant, 0 = not) and `total_num` is the count of total relevant items, or
- a list of such tuples for batch evaluation.

Both return a `(score, [per-query scores])` pair.

**`mrr` — Mean Reciprocal Rank**

For a single query, it builds a reciprocal rank array (`1/1, 1/2, 1/3, ...`) and multiplies it element-wise against the relevance list. It then scans for the first non-zero product and returns that value as the reciprocal rank of the first relevant result. For a batch list, it repeats this per query and returns the mean across all queries alongside the individual scores. If `total_num` is zero or the input is empty, it returns `0.0`.

**`map` — Mean Average Precision**

For a single query, it builds the same reciprocal rank array, then constructs a `right_ranking_list` that counts only the relevant hits seen so far (assigning 0 to non-relevant positions and an incrementing count to relevant ones). The average precision is the dot product of that count list and the reciprocal rank array, divided by `total_num`. For a batch, it averages the per-query AP values. Empty input or `total_num == 0` returns `0.0`.

One subtle point: `mrr` effectively ignores `total_num` entirely — it only uses `sub_list` — so that parameter has no effect on the MRR result beyond the zero guard. The `map` method uses `total_num` as the normalizing denominator, so passing an incorrect value there will silently skew results.
