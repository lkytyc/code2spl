The `Order` class manages a simple restaurant ordering workflow with three main data structures: a `menu` list (available dishes with names, prices, and stock counts), a `selected_dishes` list (what the customer has chosen), and a `sales` dictionary (presumably discount or multiplier factors per dish, though it's never populated by any method in this code).

**`add_dish(dish)`** takes a dish dict with a name, price, and requested count. It scans the menu for a matching dish name and checks whether enough stock exists. If not, it returns `False`. If so, it decrements the menu stock by the requested count, appends the dish to `selected_dishes`, and returns `True`. Note: if the dish name isn't found in the menu at all, the loop exits without matching and the dish is still appended — that looks like a bug.

**`calculate_total()`** sums up the cost of all selected dishes. For each dish it multiplies price × count × the corresponding value from `sales`. Since `sales` is always an empty dict, this will raise a `KeyError` at runtime unless something outside this class populates it first.

**`checkout()`** returns `False` if the cart is empty. Otherwise it calls `calculate_total()`, clears `selected_dishes`, and returns the total.

The main gap is that `sales` is never populated internally — the total calculation depends on it but nothing in the class sets it up, so `calculate_total` will fail unless the caller fills `sales` externally before checkout.
