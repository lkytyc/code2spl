`ExpressionCalculator` evaluates a mathematical expression string and returns a float result. Here's what it does:

**Entry point: `calculate(expression)`**

Calls `transform` to clean up the input, then `prepare` to convert it to postfix (Reverse Polish Notation), then walks the postfix queue to evaluate the result. The final `eval("*".join(result_stack))` handles the edge case where the result stack has more than one element — though in normal usage the stack should reduce to one value.

**`transform(expression)`**

Preprocesses the raw string: strips whitespace, removes a trailing `=`, then replaces unary minus signs with `~` to distinguish them from binary subtraction. A leading `~(` case is converted to `0-(` so the shunting-yard algorithm can treat it as a binary operation.

**`prepare(expression)`**

Implements the shunting-yard algorithm to convert the infix expression to postfix notation, populating `self.postfix_stack`. It tracks multi-character tokens (numbers, decimals) by index-and-count rather than splitting on characters, then pushes operators using precedence comparison via `compare`.

**`compare(cur, peek)`**

Determines whether the operator on top of the stack has higher or equal precedence than the current one, using a lookup into `operat_priority` keyed by ASCII offset from `(`. `%` is treated as having the same precedence as `/`.

**`_calculate(first, second, op)`**

Performs the actual arithmetic using `Decimal` for precision, supporting `+`, `-`, `*`, `/`, and `%`. Raises `ValueError` on an unrecognized operator.

**Supported input:** infix arithmetic expressions with `+`, `-`, `*`, `/`, `%`, parentheses, integers, and decimals. Unary minus on a leading number or after an operator is handled. Scientific notation (`E`/`e`) is partially accounted for in `transform` but not fully implemented in the evaluator.

**Key limitation:** there is no division-by-zero handling and no validation that the expression is well-formed before evaluation.
