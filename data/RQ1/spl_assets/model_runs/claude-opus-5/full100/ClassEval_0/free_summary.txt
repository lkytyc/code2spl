`AccessGatewayFilter` is a request gateway that decides whether an incoming HTTP request should be allowed through.

**`filter(request)`** is the main entry point. It takes a request dict with at least a `path`, `method`, and `headers` field. It grants access via two paths:

1. **Open routes** — if the URI starts with `/api` or `/login`, it passes immediately without any token check.
2. **Token-based access** — it extracts a JWT token from `Authorization`, reads the user object inside it, and allows the request only if `user['level'] > 2`. On success it logs the user. Any exception (missing header, bad token structure, expired token) causes a silent `False` return.

**`get_jwt_user(request)`** pulls the token from the request headers. If the token's JWT string starts with the user's name, it splits that prefix off and parses the remainder as a `%Y-%m-%d` date. If that date is 3 or more days in the past, it returns `None` (treating the token as expired). Otherwise it returns the whole token dict.

**`set_current_user_info_and_log(user)`** logs the user's name, address, and the current timestamp at log level 1.

A few notable behaviors worth flagging:
- The expiry check only fires when the JWT string starts with the username — if it doesn't, no expiry is enforced at all.
- Returning `None` from `get_jwt_user` doesn't raise an exception on its own, but accessing `token['user']` on `None` in `filter` will, which is caught and returns `False`.
- The `method` field is extracted in `filter` but never used.
- Exceptions are swallowed silently, so malformed tokens and missing headers all produce the same `False` result with no distinction between them.
