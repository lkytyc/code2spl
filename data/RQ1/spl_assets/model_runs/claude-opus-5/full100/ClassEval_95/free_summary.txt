The `Warehouse` class manages a simple inventory and order system using two in-memory dictionaries.

**Inventory management**

Products are stored by ID, each holding a name and quantity. `add_product` inserts a new product or increments its quantity if it already exists. `update_product_quantity` adjusts an existing product's quantity by a given amount (positive or negative). `get_product_quantity` returns the current quantity for a product, or `False` if the product doesn't exist.

**Order management**

`create_order` checks whether the requested quantity is available, deducts it from inventory via `update_product_quantity`, and records the order with its product ID, quantity, and a hardcoded initial status of `"Shipped"`. If stock is insufficient, it returns `False`. There is no order ID collision check — a duplicate order ID silently overwrites the previous one.

`change_order_status` updates the status string on an existing order, returning `False` if the order ID isn't found.

`track_order` returns the current status string for an order, or `False` if the order doesn't exist.

**Notable behaviors**

- Quantity adjustments are always additive, so passing a negative value to `update_product_quantity` is how stock gets reduced — which is exactly what `create_order` does.
- All "not found" cases return `False` rather than raising an exception, and `create_order` has no explicit return on the success path, so it implicitly returns `None` on success.
- No persistence — all state is lost when the object is destroyed.
