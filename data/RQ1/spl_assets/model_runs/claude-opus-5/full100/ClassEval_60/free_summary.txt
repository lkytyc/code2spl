`MovieTicketDB` is a simple SQLite-backed data layer for managing movie ticket records. Here's what it does:

**Setup:** When you instantiate the class with a database filename, it opens a connection, creates a cursor, and ensures a `tickets` table exists. The table stores an auto-incrementing ID, movie name, theater name, seat number, and customer name.

**Core operations:**

- `insert_ticket` adds a new ticket row given those four fields. It uses parameterized queries, so it's safe from SQL injection.
- `search_tickets_by_customer` looks up all tickets associated with a given customer name and returns every matching row as a list of tuples.
- `delete_ticket` removes a single ticket by its numeric ID.

All write operations commit immediately after execution, so changes are persisted to disk right away.

**What it doesn't do:** There's no connection cleanup method (no `close()`), no duplicate seat checking, no update operation, and no error handling — exceptions from SQLite would propagate uncaught to the caller.
