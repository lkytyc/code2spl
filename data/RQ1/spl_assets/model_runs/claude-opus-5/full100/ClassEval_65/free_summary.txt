`NumberWordFormatter` converts a number (or numeric string) into its English words equivalent, formatted as you might see on a check or formal financial document.

**Input:** A number or string passed to `format()` or `format_string()`. The number can have a decimal portion representing cents.

**Output:** An uppercase English string like `"ONE HUNDRED AND TWENTY THREE AND CENTS FORTY FIVE ONLY"`, or `"ZERO ONLY"` for a zero/empty value.

**How it works:**

The class holds four lookup tables at init time — single digits, teens, tens (twenty through ninety), and magnitude labels (thousand, million, billion).

`format()` is the public entry point. It coerces the input to a string and delegates to `format_string()`, returning an empty string for `None`.

`format_string()` splits on the decimal point to separate the whole and fractional parts. It reverses the integer portion and slices it into three-digit groups (padding to a multiple of three first), then processes each group right-to-left with `trans_three()` and appends the appropriate magnitude label via `parse_more()` — so hundreds get no suffix, thousands get "THOUSAND", and so on, up to four groups (billions). Groups of all zeros are skipped for the label but still handled, which keeps the concatenation clean.

`trans_three()` handles a single three-digit group: if the hundreds digit is nonzero it prepends "X HUNDRED AND", then delegates the last two digits to `trans_two()`.

`trans_two()` handles zero-padded two-digit strings, covering the zero case, teens, round tens, and two-digit combinations.

If a fractional part exists, it is processed through `trans_two()` and appended as `"AND CENTS XX"`.

The final string closes with `"ONLY"`.

One thing worth noting: `NUMBER_SUFFIX` is defined in `__init__` but never referenced anywhere in the class — it appears to be dead code left over from a different formatting path.
