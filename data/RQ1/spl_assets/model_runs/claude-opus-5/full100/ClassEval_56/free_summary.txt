`MetricsCalculator` is a class for tracking binary classification performance across one or more batches of predictions.

**State:** It maintains four running counters — true positives, false positives, false negatives, and true negatives — initialized to zero at construction.

**Inputs:** All public methods accept `predicted_labels` and `true_labels`, both expected to be iterables of binary values (0 or 1) of equal length.

**Core behavior — `update`:** Iterates through paired predicted and true labels, incrementing the appropriate counter based on each combination. This method is the only place counters change.

**Metrics methods:** `precision`, `recall`, `f1_score`, and `accuracy` each call `update` internally before computing their result, which means calling any of them adds the supplied labels to the running totals rather than computing a stateless result. Each guards against division by zero by returning `0.0` when the denominator would be zero.

**Notable interaction issue:** `f1_score` calls `update` once itself, then calls `precision` and `recall`, each of which calls `update` again with the same data — so a single call to `f1_score` adds the input data to the counters three times. Similarly, calling `precision` and `recall` independently on the same data double-counts it. This means the running totals are not reliable if more than one metric method is called per batch, or if `f1_score` is used at all.

**Output:** Each metric method returns a single float between 0.0 and 1.0.
