`WeatherSystem` is a simple class for looking up weather data for a city from a pre-built dictionary.

**Initialization** — you create an instance by passing a city name. It stores that city and initializes `temperature`, `weather`, and `weather_list` as empty/None.

**Core method: `query(weather_list, tmp_units)`** — this is where the real work happens. It accepts a dictionary (keyed by city name, with each entry containing `'temperature'`, `'weather'`, and `'temperature units'`) and an optional target unit (`'celsius'` by default).

- If the city isn't in the dictionary, it returns `False`.
- Otherwise it pulls the temperature and weather condition for the city.
- If the stored unit doesn't match the requested unit, it converts — Fahrenheit to Celsius or Celsius to Fahrenheit — and returns the converted value alongside the weather condition.
- If units already match, it returns the raw temperature and weather condition.

**Unit conversion** — `celsius_to_fahrenheit` and `fahrenheit_to_celsius` are straightforward math methods operating on `self.temperature`. They're called internally by `query` but could also be called independently after a `query` run.

**`set_city`** — lets you change the target city on an existing instance without creating a new one.

One thing worth noting: the return value from `query` is inconsistent. It returns a plain `False` on a missing city, a tuple on success, but nothing explicitly on a conversion path mismatch (e.g., if `tmp_units` is neither `'celsius'` nor `'fahrenheit'`, the method returns `None` implicitly).
