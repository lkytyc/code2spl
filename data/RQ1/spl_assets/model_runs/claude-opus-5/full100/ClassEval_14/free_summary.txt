`BookManagementDB` is a simple SQLite-backed library management class. Here's what it does:

**Setup:** On instantiation, it opens (or creates) a SQLite database file by name and ensures a `books` table exists with columns for id, title, author, and an availability flag (integer, 0 or 1).

**Core operations:**
- `add_book(title, author)` — inserts a new book record, marking it available (1) by default.
- `remove_book(book_id)` — deletes a book by its integer id.
- `borrow_book(book_id)` — sets a book's `available` flag to 0, indicating it's checked out.
- `return_book(book_id)` — sets the flag back to 1, marking it available again.
- `search_books()` — returns all rows from the table with no filtering.

**Notable behaviors and gaps:**
- All write operations commit immediately; there's no batching or transaction management beyond that.
- None of the methods check whether a book actually exists before operating on it, so `borrow_book` or `remove_book` on a nonexistent id silently does nothing.
- `search_books` retrieves every book regardless of availability — it's really a "list all" function rather than a true search.
- There's no method to close the connection, which can matter in long-running processes.
