`DocFileHandler` wraps read and write operations on a single `.docx` file whose path is set at construction time.

**Reading** — `read_text` opens the file, iterates over every paragraph, collects the plain text of each, and returns them joined with newlines. Formatting and styles are discarded.

**Writing** — `write_text` creates a brand-new document (discarding any existing content at the path), adds a single paragraph containing the provided string, sets the font size in points (default 12), applies an alignment (default left), and saves. It returns `True` on success or `False` if any exception occurs. The bare `except` means any error is silently swallowed.

**Appending a heading** — `add_heading` opens the existing file, appends a heading at the specified level (default 1), and saves it back. Returns `True`/`False` the same way.

**Appending a table** — `add_table` opens the existing file, creates a table sized to match the rows and columns of the provided 2D list, fills every cell by converting its value to a string, and saves. Returns `True`/`False`.

**Alignment helper** — `_get_alignment_value` maps the strings `'left'`, `'center'`, and `'right'` to the corresponding `python-docx` alignment constants, falling back to left for anything unrecognized.

One notable behavioral quirk: `write_text` always creates a fresh document, so calling it on an existing file replaces all prior content. The append methods (`add_heading`, `add_table`) load and save the existing file, so they stack on top of whatever is already there — including content written by a previous `write_text` call.
