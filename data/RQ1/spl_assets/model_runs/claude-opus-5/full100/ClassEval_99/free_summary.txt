`ZipFileProcessor` is a class that wraps Python's `zipfile` module to provide four basic zip file operations, all centered around a zip file path stored at construction time (`file_name`).

**`read_zip_file`** opens the zip in read mode and returns the raw `ZipFile` object to the caller. Notably, it doesn't use a context manager, so the caller is responsible for closing it. Any error silently returns `None`.

**`extract_all`** extracts every file in the archive to a given `output_path` directory. Returns `True` on success, `False` on any error.

**`extract_file`** extracts a single named file from the archive to `output_path`. Same success/failure return pattern.

**`create_zip_file`** takes a list of file paths and writes them into a new zip archive at `output_file_name`. It uses the default compression (stored, no compression) since no `compression` argument is passed to `ZipFile`. Returns `True` on success, `False` on failure.

A few things worth noting about the design: all four methods use bare `except:` clauses, so they swallow every exception including `KeyboardInterrupt` and `SystemExit`. The `read_zip_file` method is the odd one out — it leaves the file handle open, which risks resource leaks if callers forget to close it. The other three methods use `with` blocks correctly. There's no logging anywhere, so failures are silent.
