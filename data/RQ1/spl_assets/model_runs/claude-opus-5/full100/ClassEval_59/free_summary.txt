`MovieBookingSystem` manages a simple in-memory movie catalog with seat booking. Here's what it does:

**Data model**
Each movie is a dictionary holding its name, ticket price, start and end times (parsed from `HH:MM` strings), and a 2D NumPy array of seats initialized to zeros. The seat grid is square — `n × n` — where `0` means available and `1` means booked.

**Adding movies** (`add_movie`)
Takes a name, price, start time, end time, and grid size `n`, constructs the movie dict, and appends it to the internal list.

**Booking seats** (`book_ticket`)
Looks up a movie by name. For each `(row, col)` coordinate in the provided list, it checks whether that seat is free. If all requested seats are free, it marks them all as booked and returns a success message. If any single seat is already taken, it immediately returns a failure message — but notably does not roll back seats it already marked in that same call, so a partial booking is possible on failure. If no movie with that name exists, it returns "Movie not found."

**Finding available movies** (`available_movies`)
Accepts a time window as start and end strings. Returns the names of all movies whose showtime fits entirely within that window — meaning the movie's start is at or after the requested start, and the movie's end is at or before the requested end.

**Notable gaps**
- Price is stored but never used in any method.
- The partial-booking bug on failure is the most significant behavioral issue.
- There's no persistence, concurrency control, or duplicate-name handling.
