`AssessmentSystem` manages a collection of students and their course scores, supporting several reporting operations.

**Data model:** Each student is stored in a dictionary keyed by name, with fields for name, grade, major, and a nested dictionary mapping course names to numeric scores.

**Adding data:**
- `add_student` registers a new student with their grade and major, initializing an empty courses dict.
- `add_course_score` appends or updates a score for a named course on an existing student. It silently does nothing if the student doesn't exist.

**Queries:**
- `get_gpa` returns the arithmetic mean of all course scores for a student, or `None` if the student is missing or has no courses.
- `get_all_students_with_fail_course` returns a list of student names where at least one course score is below 60. It stops checking further courses for a student once one failing score is found.
- `get_course_average` computes the mean score for a given course across all students who have that course recorded, skipping `None` scores. Returns `None` if no valid scores exist.
- `get_top_student` iterates all students, calls `get_gpa` for each, and returns the name of the student with the highest average. Returns `None` if no students have courses. In the case of a tie, the first student encountered with the top GPA wins, since the comparison is strictly greater-than.

**Notable behaviors and gaps:**
- There's no duplicate-student check in `add_student` — adding the same name twice silently overwrites the existing record.
- Scores are never validated, so negative values or values above 100 are accepted without error.
- `get_top_student` initializes `top_gpa` at 0, meaning a student whose GPA is exactly 0 will not be returned even if they are the only student with courses.
