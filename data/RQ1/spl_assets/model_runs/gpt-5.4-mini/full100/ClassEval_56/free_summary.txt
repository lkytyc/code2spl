This code defines a `MetricsCalculator` class for evaluating binary classification results.

It keeps running counts of four outcomes:
- true positives
- false positives
- false negatives
- true negatives

### How it works
- The constructor initializes all four counters to zero.
- The `update(predicted_labels, true_labels)` method compares two sequences of labels element by element using `zip(...)`. For each pair, it increments the appropriate counter based on whether the prediction and truth are `1` or `0`.

### Metrics methods
Each metric method takes the same kind of inputs: `predicted_labels` and `true_labels`.

- `precision(...)`:
  - Calls `update(...)`
  - Returns `true_positives / (true_positives + false_positives)`
  - If that denominator is zero, returns `0.0`

- `recall(...)`:
  - Calls `update(...)`
  - Returns `true_positives / (true_positives + false_negatives)`
  - If that denominator is zero, returns `0.0`

- `f1_score(...)`:
  - Calls `update(...)`
  - Computes precision and recall by calling the other two methods
  - Returns the harmonic mean of precision and recall
  - If precision and recall sum to zero, returns `0.0`

- `accuracy(...)`:
  - Calls `update(...)`
  - Computes `(true_positives + true_negatives) / total`
  - If no labels have been counted, returns `0.0`

### Important interaction
A notable detail is that the metric methods all call `update(...)`, so the internal counters keep accumulating across calls. Also, `f1_score(...)` calls `precision(...)` and `recall(...)`, which themselves call `update(...)` again, so a single F1 computation updates the counters multiple times.
