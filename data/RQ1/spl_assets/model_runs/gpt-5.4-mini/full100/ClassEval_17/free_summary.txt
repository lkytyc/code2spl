This code defines a `CalendarUtil` class that stores calendar events in an in-memory list and provides a few simple scheduling queries.

Behavior and inputs:
- Creating a `CalendarUtil` instance initializes an empty event list.
- `add_event(event)` adds an event object to the internal list.
- `remove_event(event)` removes that event from the list if it is present.
- The code assumes events are dictionary-like objects with at least `date`, `start_time`, and `end_time` fields.

Queries and outputs:
- `get_events(date)` returns a list of all stored events whose `date` falls on the same calendar day as the provided `date` argument.
- `is_available(start_time, end_time)` checks whether a proposed time range overlaps any existing event. It returns `False` if there is overlap, otherwise `True`.
- `get_available_slots(date)` scans one-hour intervals across the given day, from midnight through 11:59 PM, and returns a list of `(start_time, end_time)` pairs for each hour-long slot that is free according to `is_available`.
- `get_upcoming_events(num_events)` returns up to `num_events` events whose `start_time` is at or after the current time.

Important interactions and details:
- `get_available_slots` depends on `is_available` to decide whether each hourly slot is open.
- `get_upcoming_events` uses the current system time from `datetime.now()`.
- Event ordering is not explicitly managed, so `get_upcoming_events` returns the first matching events in the order they happen to appear in the internal list, not necessarily in chronological order.
