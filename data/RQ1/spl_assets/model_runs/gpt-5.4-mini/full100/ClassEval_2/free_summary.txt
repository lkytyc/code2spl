This code defines a small command-line argument parser class called `ArgumentParser`.

It keeps three pieces of state:
- `arguments`: a dictionary of parsed argument names to values
- `required`: a set of argument names that must be present
- `types`: a dictionary mapping argument names to functions or types used to convert string values

Main behavior:
- `add_argument(arg, required=False, arg_type=str)` registers an argument name, optionally marks it as required, and stores the type conversion to use for that argument.
- `parse_arguments(command_string)` takes a full command string, splits it on spaces, ignores the first token, and treats the rest as arguments.
  - Long-form arguments starting with `--` are handled either as `--name=value` or as a flag `--name` with value `True`.
  - Short-form arguments starting with `-` are handled either as `-n value` or as a flag `-n` with value `True`.
  - If an argument has a registered type, the parser tries to convert the value using that type.
  - After parsing, it checks whether any required arguments were missing. If so, it returns `False` and the set of missing argument names.
  - If all required arguments are present, it returns `True` and `None`.
- `get_argument(key)` returns the stored value for a parsed argument, or `None` if it was not provided.

Important interaction:
- `parse_arguments` relies on `_convert_type`, which uses the type information previously registered by `add_argument`.
- If conversion fails because the type is unknown or the value cannot be converted, the original string value is kept.

Outputs:
- `parse_arguments` returns a tuple indicating success or failure and, on failure, which required arguments are missing.
- `get_argument` returns an individual parsed value from the internal dictionary.
