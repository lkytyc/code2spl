Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

Class specification:

# Class: UrlPath
# Fields: with_end_tag, segments
# Calls: parse→fix_path

## __init__()
Summary: Initialize the object with an empty segments list and disable the end tag flag by default.
1. Assign an empty list to self.segments to initialize the segment collection. → self.segments
2. Assign False to self.with_end_tag to disable end-tag handling by default. → self.with_end_tag

## add(self: object, segment: any)
Summary: Appends a fixed or normalized version of the given segment to the segments collection.
#   self: object — Instance containing the segments collection and the path-fixing helper.
#   segment: any — The segment value to be normalized and appended.
1. Call self.fix_path with the provided segment to compute its normalized form. → fixed_segment
2. Append the normalized segment to self.segments. → self.segments

## fix_path(path: string) → string
Summary: Return an empty string for a falsy path, otherwise return the path with leading and trailing slashes removed.
#   path: string — Input path string to normalize.
#   → result: string — The normalized path without leading or trailing slash characters, or an empty string when the input path is falsy.
1. Check whether the input path is falsy. → path_truthy_check
2. If the path is falsy, return an empty string immediately. → ''
3. Otherwise, remove any leading and trailing '/' characters from the path by calling strip('/'). → segment_str
4. Return the normalized segment string. → segment_str
   ? Return an empty string without performing any stripping operation.

## parse(path: string, charset: string)
Summary: Normalize a non-empty path, record whether it ends with a slash, split it into segments, URL-decode each segment, and append the decoded values to self.segments.
#   path: string — Input path to normalize, inspect for a trailing slash, and split into segments.
#   charset: string — Character encoding used when URL-decoding each path segment.
1. If path is truthy, continue with path processing; otherwise skip all remaining steps. → path_guard
2. Within the truthy path branch, if path ends with '/', set self.with_end_tag to True. → self.with_end_tag
3. Within the truthy path branch, replace path with the result of self.fix_path(path). → path
4. Within the truthy path branch after normalization, if path is still truthy, split it on '/' and store the segments. → split
5. Within the normalized non-empty path branch, for each seg in split, decode seg with urllib.parse.unquote using encoding=charset. → decoded_seg
6. Within the normalized non-empty path branch, append each decoded segment to self.segments. → self.segments
