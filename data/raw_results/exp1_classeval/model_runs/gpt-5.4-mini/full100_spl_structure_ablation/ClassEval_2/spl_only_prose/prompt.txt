Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

## _convert_type(self: object, arg: any, value: any) → any
Summary: Attempts to convert a value using the type mapping for the given argument key and falls back to returning the original value when the conversion fails or the key is missing.
#   self: object — Instance containing the type mapping used for conversion.
#   arg: any — Key used to select the converter from the type mapping.
#   value: any — Input value to be converted.
#   → result: any — The converted value, or the original value if conversion cannot be performed.
1. Try to convert the input value by looking up the converter for the given argument key in the type mapping and applying it to the value. → converted_value
2. If the conversion succeeds, return the converted result. → converted_value
3. If a ValueError or KeyError occurs during lookup or conversion, return the original input value unchanged. → value

## add_argument(self: object, arg: any, required: bool, arg_type: type) → null

## get_argument(self: object, key: any) → any
Summary: Returns the value stored under the given key from the instance argument mapping.
#   self: object — The instance containing the argument mapping.
#   key: any — The lookup key to retrieve from the argument mapping.
#   → result: any — The value associated with key in self.arguments, or None if the key is absent.

## parse_arguments()
Summary: Parses command-line arguments from a command string, storing long and short options as converted values or boolean flags and returning whether all required arguments are present.
1. Split the command string on whitespace, discard the first token, and store the remaining tokens in args. → args
2. Iterate over args by index from 0 to len(args) - 1, and assign the current token to arg. → arg
3. If arg starts with "--", treat it as a long option, remove the leading "--", and split the remainder on '='. → key_value
4. If the long option split produces exactly two parts, store the first part as the key in self.arguments and store the second part converted by _convert_type using the key. → self.arguments[key_value[0]]
5. If the long option split does not produce exactly two parts, store the long option name as a key in self.arguments with the value True. → self.arguments[key_value[0]]
6. Else if arg starts with "-", treat it as a short option and remove the leading "-" to get the key. → key
7. Within the short option branch, if the next token exists and does not start with "-", convert that next token with _convert_type and store it under the short option key. → self.arguments[key]
8. Within the short option branch, if there is no next token or the next token starts with "-", store the short option key in self.arguments with the value True. → self.arguments[key]
9. After processing all tokens, compute missing_args as the set difference between self.required and the keys currently present in self.arguments. → missing_args
