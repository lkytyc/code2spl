Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

# Class: PDFHandler
# Fields: readers, filepaths

1. Store the provided filepaths argument on self.filepaths. → self.filepaths

## extract_text_from_pdfs(self: object) → list
Summary: Iterate through every PDF reader and every page in each reader, extract text from each page, and return the collected texts as a list.
#   self: object — Instance containing a readers collection, where each reader exposes a pages sequence.
#   → result: list — A list containing the extracted text from every page of every reader, in traversal order.
1. Initialize pdf_texts as an empty list to collect extracted page text. → pdf_texts
2. For each reader in self.readers, iterate through all pages using page indices from 0 to len(reader.pages) - 1. → reader,
3. Within the outer loop over each reader, fetch the page at the current page_num index from reader.pages. → page
4. Within the nested loops, extract text from the current page and append the extracted text to pdf_texts. → pdf_texts
5. After processing every reader and every page, return pdf_texts. → pdf_texts

## merge_pdfs(self: object, output_filepath: str) → str
Summary: Merge all pages from every PDF reader in self.readers into a single PDF file saved to the given output path.
#   self: object — Instance providing the readers collection to merge.
#   output_filepath: str — Destination file path where the merged PDF will be written.
#   → result: str — Confirmation message stating where the merged PDFs were saved.
1. Create a new PyPDF2.PdfWriter instance and store it in pdf_writer. → pdf_writer
2. For each reader in self.readers, iterate through every page index from 0 to len(reader.pages) - 1 using range(len(reader.pages)). → reader,page_num
3. Within the inner loop for the current reader, get the page at reader.pages[page_num] and store it in page. → page
4. Within the nested loops, add the current page to pdf_writer with add_page. → pdf_writer
5. After all readers and pages have been processed, open output_filepath in binary write mode as out. → out
6. Write the accumulated pdf_writer content to out and close the file when the context ends. → written_file
7. Return the message Merged PDFs saved at the output_filepath. → result
