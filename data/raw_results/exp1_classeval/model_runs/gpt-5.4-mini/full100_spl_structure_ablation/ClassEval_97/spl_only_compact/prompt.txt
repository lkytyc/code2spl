Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

## is_valid_input(self: object, textnum: string) → boolean
Summary: Normalize hyphenated text into space-separated words, then verify that each token is either an accepted ordinal word or a numeric word after optional ordinal-suffix replacement.
#   self: object — Instance providing ordinal_words, ordinal_endings, and numwords lookup collections.
#   textnum: string — Text containing number-related words to validate.
#   → result: boolean — True if every token is recognized as valid, otherwise False.
1. Replace every hyphen in the input text with a space and assign the normalized string back to textnum. → textnum
2. Split textnum into words and iterate over each word in order. → word
3. Within the outer loop, if the current word is already present in self.ordinal_words, skip any further processing for that word and continue with the next token. → continue
4. Within the outer loop, for each configured ordinal ending and replacement in self.ordinal_endings, if the current word ends with that ending, rewrite the word by removing the ending and appending the replacement. → word
5. Still within the outer loop, after any suffix normalization, if the current word is not present in self.numwords, return False immediately. → False
6. If every token passes the ordinal-word check or numeric-word membership check, return True after the loop completes. → True

## text2int(textnum: string) → string
Summary: Convert a hyphen-normalized text string into a mixed output string by parsing recognized number and ordinal words into numeric values while passing through non-number tokens unchanged.
#   textnum: string — Input text containing number words, ordinal forms, and ordinary tokens.
#   → result: string — The transformed string with recognized numeric phrases converted into digits and other text preserved.
1. Replace every hyphen in the input text string with a space, then initialize the numeric accumulators and output buffer to zero, empty string, and false. → textnum,
2. For each word from splitting the normalized input on whitespace, process the token in order and keep parsing state across iterations. → word
3. Within the outer token loop, if the current word is found in the ordinal word mapping, treat it as a direct ordinal value by setting scale to 1, adding the mapped increment into the running current value, and marking that a number is in progress. → current,
4. Within the outer token loop, if the current word is not an ordinal word, iterate through each ordinal ending replacement pair and, for any matching suffix, rewrite the word by removing the ending and appending the replacement. → word
5. After ordinal suffix normalization, if the current word is not in the number-word mapping, then if a number phrase was active append the accumulated numeric value plus the current value and a trailing space to the output, append the non-number word plus a trailing space, and reset result, current, and the number state. → curstring,

After ordinal suffix normalization, if the current word is in the number-word mapping, add the mapped scale and increment into the running current value; when the scale is greater than 100, fold the current value into result and reset current to zero, then mark that a number is in progress. → current,
7. After all words have been processed, if a number phrase is still active, append the final accumulated numeric value to the output buffer without a trailing space. → curstring
8. Return the constructed output string. → curstring
