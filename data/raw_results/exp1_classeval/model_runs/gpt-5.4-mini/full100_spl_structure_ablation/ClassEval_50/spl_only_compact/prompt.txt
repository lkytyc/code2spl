Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

# Class: JSONProcessor

## process_json(file_path: path, remove_key: any) → int
Summary: Load JSON from a file, return 0 for invalid sentinel values, delete a requested key when present, persist the updated JSON, and return a status code indicating whether removal occurred.
#   file_path: path — Path to the JSON file to read and possibly update.
#   remove_key: any — Key to remove from the loaded JSON object if present.
#   → result: int — Returns 1 when the key is removed and the file is rewritten; otherwise returns 0.
1. Read JSON data from file_path using self.read_json and store the result in data. → data
2. If data is 0 or -1, return 0 immediately without making any changes. → 0
3. If remove_key exists in data, delete data[remove_key], write the updated data back to file_path using self.write_json, and return 1. → 1
4. If remove_key does not exist in data, return 0 without writing the file. → 0
   ? Stop processing immediately and return 0.
   ? Do not modify data or write the file, and return 0.

## read_json(file_path: str) → object or int
Summary: Read and parse a JSON file from the given path, returning 0 if the path does not exist and -1 if any error occurs during file access or parsing.
#   file_path: str — Path to the JSON file to read.
#   → result: object or int — Parsed JSON data on success, 0 when the file path does not exist, or -1 if an exception occurs.
1. Check whether the file path exists; if it does not exist, return 0 immediately. → return_0
2. Open the existing file at file_path in read mode, load its JSON content, and store the parsed data. → data
3. Return the parsed JSON data. → data
   ? Return 0 without attempting to open or parse the file.
   ? Return -1 as the fallback error value.

## write_json(self: object, data: any, file_path: string) → int
Summary: Serialize the provided data object to the given file path as JSON and return 1 on success or -1 if any error occurs.
#   self: object — Instance reference.
#   data: any — The data structure to be written as JSON.
#   file_path: string — Path to the target file to open for writing.
#   → result: int — Returns 1 when the JSON write succeeds, otherwise returns -1 if an exception is caught.
1. Try to open the target file path in write mode and bind the handle to file. → file
2. Serialize the provided data into the open file using json.dump. → written_json
3. Return 1 to indicate the write completed successfully. → 1
   ? Catch the exception and stop normal processing.
   ? Return -1 to indicate failure.
