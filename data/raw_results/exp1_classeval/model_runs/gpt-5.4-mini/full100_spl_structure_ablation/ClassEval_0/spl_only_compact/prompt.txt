Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

## get_jwt_user(self: object, request: dict) → object or None
Summary: Extract the authorization token and user from the request, reject JWTs whose embedded date is at least 3 days old when the JWT starts with the user name, and otherwise return the token.
#   self: object — Instance reference.
#   request: dict — Incoming request containing a headers Authorization object with token data.
#   → result: object or None — Returns the token object when it is accepted, or None when the embedded JWT date is at least 3 days old after matching the user name prefix.
1. Read the Authorization token from request['headers']['Authorization'] and assign it to token. → token
2. Extract token['user'] and assign it to user. → user
3. Check whether token['jwt'] starts with user['name']. → jwt_prefix_matches_user_name
4. If token['jwt'] starts with user['name'], split token['jwt'] by user['name'] and take the substring at index 1 as jwt_str_date. → jwt_str_date
5. If token['jwt'] starts with user['name'], parse jwt_str_date with datetime.datetime.strptime using the format "%Y-%m-%d" to produce jwt_date. → jwt_date
6. Within the branch where token['jwt'] starts with user['name'], compute datetime.datetime.today() - jwt_date and check whether the result is greater than or equal to datetime.timedelta(days=3). → is_jwt_at_least_3_days_old
7. If the JWT date is at least 3 days old, return None immediately. → None
8. If the JWT prefix check fails or the JWT date is less than 3 days old, return token. → token

## is_start_with(self: object, request_uri: string) → boolean
Summary: Checks whether the given request URI starts with any prefix in a fixed list and returns true on the first match, otherwise returns false.
#   self: object — Instance context used to call the method.
#   request_uri: string — URI string to test against the configured prefixes.
#   → result: boolean — True if request_uri starts with '/api' or '/login'; otherwise false.
1. Initialize start_with as a fixed list containing the two prefixes '/api' and '/login'. → start_with
2. Within the outer for loop over start_with, examine each prefix s one at a time. → s
3. Within the loop, if request_uri starts with the current prefix s, return true immediately and stop processing further prefixes. → true
4. If no prefix in start_with matches request_uri, return false after the loop completes. → false
