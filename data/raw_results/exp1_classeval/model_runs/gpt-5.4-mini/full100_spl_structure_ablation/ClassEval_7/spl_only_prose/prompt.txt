Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

Class specification:

# Class: BalancedBrackets
# Fields: right_brackets, left_brackets, stack, expr
# Calls: check_balanced_brackets→clear_expr

## __init__(expr: string)
Summary: Initializes the object with an empty stack, matching bracket lists, and the provided expression string.
#   expr: string — The expression to store on the instance.
1. Create an empty stack and assign it to the instance state. → self.stack
2. Assign the list of left brackets containing '(', '{', and '[' to the instance state. → self.left_brackets]
3. Store the input expression on the instance for later use. → self.expr

## check_balanced_brackets() → boolean
Summary: Validate whether the expression has properly matched and nested parentheses, braces, and brackets using a stack-based scan.
#   → result: boolean — True when all brackets are balanced and correctly nested; otherwise False.
1. Clear the current expression state before validation. → self.clear_expr()
2. Within the full left-to-right scan of self.expr, inspect each character Brkt in order. → loop_over_expression
3. Within the loop, if Brkt is an opening bracket from self.left_brackets, push Brkt onto self.stack. → self.stack
4. Within the loop, if Brkt is not an opening bracket, pop the most recent opening bracket from self.stack into Current_Brkt. → Current_Brkt
5. Within the loop, if Current_Brkt is "(", require Brkt to be ")"; otherwise return False immediately. → false_on_parenthesis_mismatch
6. Within the loop, if Current_Brkt is "{", require Brkt to be "}"; otherwise return False immediately. → false_on_brace_mismatch
7. Within the loop, if Current_Brkt is "[", require Brkt to be "]"; otherwise return False immediately. → false_on_bracket_mismatch
8. After the loop finishes, if self.stack is not empty, return False because unmatched opening brackets remain. → false_on_remaining_stack
9. If no mismatch is found and the stack is empty, return True. → true

## clear_expr()
Summary: Filters self.expr so it retains only characters that are present in either self.left_brackets or self.right_brackets.
1. Read the current value of self.expr and iterate through its characters one by one. → character_stream
2. Keep only characters c for which c is contained in self.left_brackets or self.right_brackets, using a short-circuit OR condition. → filtered_characters
3. Join the retained characters into a new string. → new_expr
4. Assign the newly constructed string back to self.expr, replacing the original expression content. → self.expr
