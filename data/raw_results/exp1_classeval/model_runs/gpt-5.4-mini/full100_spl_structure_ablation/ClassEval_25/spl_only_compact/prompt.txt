Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

#   cookies_file: any — The source value assigned directly to the instance cookies_file field.

2. Initialize the instance field self.cookies to None as an unset default value. → self.cookies

## _save_cookies() → bool
Summary: Saves the current cookies dictionary to the configured cookies file as JSON and returns true on success, or false if any error occurs.
#   → result: bool — True when the cookies are saved successfully; false if any exception occurs.

2. Serialize and write self.cookies to the open file as JSON. → json.dump(self.cookies,
3. Return true after successfully saving the cookies. → True
   ? Handle the exception without re-raising it.
   ? Return false to indicate the cookies were not saved.

## get_cookies(reponse: mapping)

#   reponse: mapping — A dictionary-like response object expected to contain a 'cookies' key.
1. Read the value associated with the 'cookies' key from reponse and assign it to self.cookies. → self.cookies
2. Call self._save_cookies() to persist the updated cookies state. → self._save_cookies()

## load_cookies(self: object) → dict
Summary: Loads and returns JSON cookie data from the configured cookies file, falling back to an empty dictionary if the file does not exist.
#   self: object — Instance containing the cookies_file path.
#   → result: dict — The parsed cookies data from the file, or an empty dictionary when the file is missing.
1. Enter a try block and open the configured cookies file at self.cookies_file in read mode. → file
2. Parse the file contents as JSON into cookies_data. → cookies_data
3. Return cookies_data immediately after successful parsing. → cookies_data

## set_cookies(self: object, request: dict)
Summary: Build a cookie header string from self.cookies and assign it to request['cookies'].
#   self: object — Instance containing the cookies mapping used to build the header string.
#   request: dict — Request object that will receive the cookies header value.
1. Read all key-value pairs from self.cookies. → cookies_items
2. Format each key-value pair as "key=value" using the current key and value. → formatted_cookies
3. Join the formatted cookie strings with "; " as the separator. → cookies_header
4. Assign the joined cookie header string to request['cookies'], overwriting any existing value. → request
