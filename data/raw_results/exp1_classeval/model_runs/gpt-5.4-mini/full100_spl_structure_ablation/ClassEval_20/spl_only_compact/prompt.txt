Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

# Class: Chat
# Fields: users

## __init__()
Summary: Initializes the instance by creating an empty users dictionary as the default user store.
1. Assign an empty dictionary to the instance attribute users to initialize the user collection. → self.users

## add_user(self: object, username: str) → bool
Summary: Adds a username to the user registry only if it is not already present, returning False for duplicates and True after creating an empty entry for a new user.
#   self: object — Instance containing the users collection.
#   username: str — Username to check and add.
#   → result: bool — False if the username already exists; otherwise True after insertion.
1. Check whether username is already present in self.users. → exists
2. If username is already present, return False immediately without modifying self.users. → False
3. Otherwise, create a new entry in self.users for username with an empty list as its value. → self.users[username]
4. Return True after successfully adding the new username. → True

## get_messages(self: object, username: string) → list
Summary: Returns an empty list for unknown usernames, otherwise returns the stored messages for the given username from self.users.
#   self: object — Instance containing the users mapping.
#   username: string — The username used to look up messages in self.users.
#   → result: list — An empty list if the username is not found; otherwise the value stored in self.users for that username.
1. Check whether username is present in self.users. → membership_check
2. If username is not present in self.users, return an empty list immediately. → empty_list_return
3. Otherwise, retrieve and return self.users[username] directly with no further transformation. → messages

## remove_user(self: object, username: key) → boolean
Summary: Removes a username from the users mapping when present and returns whether the deletion succeeded.
#   self: object — Instance containing the users collection.
#   username: key — Username to check for and delete from the users collection.
#   → result: boolean — True if the username was found and deleted; otherwise False.
1. Check whether username exists as a key in self.users. → membership_check
2. If username is present in self.users, delete self.users[username]. → deletion_done
3. After deleting the entry, return True immediately. → true
   ? Return False immediately without modifying self.users.

## send_message(self: object, sender: any, receiver: any, message: any) → bool
Summary: Stores a message with a current timestamp for both sender and receiver after verifying that both users exist.
#   self: object — Instance containing the users collection.
#   sender: any — Identifier for the user sending the message.
#   receiver: any — Identifier for the user receiving the message.
#   message: any — Message content to store.
#   → result: bool — True when the message is stored for both users; otherwise False.
1. Check whether sender and receiver both exist in self.users. → user_existence_check
2. If either sender or receiver is missing from self.users, return False immediately. → False
3. Generate the current local timestamp as a string formatted as YYYY-MM-DD HH:MM:SS. → timestamp
4. Create message_info as a dictionary containing sender, receiver, message, and the generated timestamp. → message_info
5. Append message_info to self.users[sender]. → sender_message_list
6. Append the same message_info to self.users[receiver]. → receiver_message_list
7. Return True to indicate successful storage. → True
