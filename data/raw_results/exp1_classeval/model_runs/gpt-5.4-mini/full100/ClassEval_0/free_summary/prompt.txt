This code defines a small access-control filter class named `AccessGatewayFilter` that decides whether an incoming request should be allowed through.

Behavior and inputs:
- The main entry point is `filter(request)`.
- It expects `request` to be a dictionary with at least:
  - `path`
  - `method`
  - `headers`, containing an `Authorization` entry
- The `Authorization` value is expected to be a token-like dictionary containing:
  - `user`
  - `jwt`

What it does:
- It first checks the request path.
- If the path starts with `/api` or `/login`, it immediately allows the request by returning `True`.
- Otherwise, it tries to extract a token and user from the request.
- It then checks `user['level']`.
  - If the level is greater than `2`, it logs some user information and allows the request by returning `True`.
- If anything goes wrong during token parsing or user checking, it returns `False`.

Token handling:
- `get_jwt_user(request)` reads the authorization token from `request['headers']['Authorization']`.
- It checks whether the `jwt` string starts with the user’s name.
- If so, it takes the remaining part of the string, interprets it as a date in `YYYY-MM-DD` format, and compares it with the current date.
- If the date is 3 or more days old, it returns `None`.
- Otherwise it returns the token.

Logging:
- `set_current_user_info_and_log(user)` logs a message built from:
  - the user’s name
  - the user’s address
  - the current timestamp

Important interaction:
- `filter()` depends on `is_start_with()` for public paths and `get_jwt_user()` for token validation.
- If the user is accepted and has a sufficiently high level, `filter()` calls `set_current_user_info_and_log()` before approving the request.
