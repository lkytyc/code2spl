Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

## find_blank(state: list[list[int]]) → tuple[int, int] or None
Summary: Scans the 3x3 state grid row-major and returns the row and column of the first cell whose value is zero.
#   state: list[list[int]] — A 3x3 two-dimensional list of integers representing the grid.
#   → result: tuple[int, int] or None — The row and column indices of the first zero cell, or None if no zero cell is found.
1. For row index i from 0 to 2 inclusive, iterate over each row of the 3x3 state grid. → row_index_i
2. Within the outer loop over i, for column index j from 0 to 2 inclusive, iterate over each column in the current row. → column_index_j
3. Within the inner loop over j, check whether state[i][j] equals 0. → is_zero_cell
4. If is_zero_cell is true, immediately return the tuple (i, j) as the first blank position and stop scanning. → blank_position
5. If both loops finish without finding any zero cell, return None implicitly. → no_blank_result

## get_possible_moves(state: list) → list
Summary: Determines the valid sliding directions for the blank tile in a 3x3 puzzle state by locating the blank position and checking row and column boundaries.
#   state: list — Current puzzle state used by find_blank to locate the blank tile position.
#   → moves: list — List of valid move direction strings among 'up', 'down', 'left', and 'right'.
1. Initialize an empty list named moves. → moves
2. Call self.find_blank(state) and unpack the returned two-element iterable into i and j. → i,
3. If i > 0, append the string 'up' to moves. → moves
4. If i < 2, append the string 'down' to moves. → moves
5. If j > 0, append the string 'left' to moves. → moves
6. If j < 2, append the string 'right' to moves. → moves
7. Return moves. → moves

## move(state: 2D list, direction: string) → 2D list
Summary: Moves the blank tile in a puzzle state one step in the given direction by swapping it with the adjacent cell and returns the resulting state.
#   state: 2D list — Current puzzle state whose blank position is used to perform the swap and whose rows are copied into a new state.
#   direction: string — Direction in which to move the blank: 'up', 'down', 'left', or 'right'. No boundary validation is performed, and any other value leaves the copied state unchanged.
#   → new_state: 2D list — The resulting state after swapping the blank with the adjacent cell in the requested direction, or an unchanged row-wise copy if the direction does not match a supported move.
1. Call self.find_blank(state) and unpack the returned row and column into i and j. → i,
2. Create new_state by copying each row of state into a new row list. → new_state
3. Within the direction conditional chain, without boundary checking, if direction equals 'up', simultaneously swap new_state[i][j] with new_state[i - 1][j]. → new_state
4. Within the direction conditional chain, without boundary checking, else if direction equals 'down', simultaneously swap new_state[i][j] with new_state[i + 1][j]. → new_state
5. Within the direction conditional chain, without boundary checking, else if direction equals 'left', simultaneously swap new_state[i][j] with new_state[i][j - 1]. → new_state
6. Within the direction conditional chain, without boundary checking, else if direction equals 'right', simultaneously swap new_state[i][j] with new_state[i][j + 1]. → new_state
7. If none of the four supported directions matches, leave new_state unchanged. → new_state
8. Return new_state. → new_state

## solve()
Summary: Performs a breadth-first search from the initial state to the goal state by exploring moves in FIFO order and returns the first discovered sequence of moves, or None if the goal is unreachable.
1. Initialize open_list to a new list containing one tuple whose first element is self.initial_state and whose second element is a new empty list representing the initial path. → open_list
2. Initialize closed_list to a new empty list. → closed_list
3. While open_list is not empty, pop the element at index 0 from open_list and unpack it into current_state and path. → current_state
4. Within the while open_list loop, append current_state to closed_list. → closed_list
5. Within the while open_list loop, if current_state equals self.goal_state, return path immediately. → path
6. Within the while open_list loop, for each move returned by self.get_possible_moves(current_state), compute new_state by calling self.move(current_state, move). → new_state
7. Within the for each move loop and while open_list loop, if new_state is not in closed_list, append a tuple containing new_state and the path list with the current move appended to open_list; do not check whether new_state is already in open_list. → open_list
8. After the while open_list loop exits without returning, return None. → None
