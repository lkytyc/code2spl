Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

# Class: BitStatusUtil

## add(states: int, stat: int) → int
Summary: Validates two integer bit status values and returns their bitwise OR as a combined bitmask.
#   states: int — The first bit status or flag mask to merge.
#   stat: int — The second bit status or flag mask to merge.
#   → result: int — The combined bitmask produced by the bitwise OR of states and stat.
1. Call BitStatusUtil.check with [states, stat] to validate the input bit statuses before merging. → check_result
2. After validation passes, return the bitwise OR of states and stat as the combined bitmask. → result

## check(args: list[int])
Summary: Validates that every element in args is a non-negative even integer, raising ValueError for negative or odd values.
#   args: list[int] — Collection of integer values to validate.
1. For each arg in args, validate the value in order. → arg
2. Within the for loop over args, check whether arg is less than 0; if true, the corresponding exception flow is triggered. → negative_check
3. Within the for loop over args, after the negative check, check whether arg modulo 2 is not equal to 0; if true, the corresponding exception flow is triggered. → even_check
4. If neither exception condition is triggered for any arg, the loop completes and the method returns successfully. → validation_status
   ! log: "<arg> must be greater than or equal to 0"
   ! raise: ValueError "Raised when a negative value is encountered."
   ! log: "<arg> not even"
   ! raise: ValueError "Raised when an odd integer is encountered."

## has(states: int, stat: int) → boolean
Summary: Checks whether the stat bitmask is a bitwise subset of states after validating the arguments.
#   states: int — Integer bit flags to check against.
#   stat: int — Integer bitmask to verify as a subset of states.
#   → result: boolean — True if every bit set in stat is also set in states; otherwise false.
1. Call BitStatusUtil.check([states, stat]) to validate the arguments. → check_result
2. Compute the bitwise AND of states and stat. → and_result
3. Return whether and_result equals stat; this is true when stat is a bitwise subset of states, including the stat == 0 case. → result

## remove(states: integer, stat: integer) → integer
Summary: Removes the stat status flag from the states bitmask when it is present, and otherwise returns states unchanged.
#   states: integer — Current bitmask containing status flags.
#   stat: integer — Status flag bit or bits to remove from states.
#   → result: integer — Updated bitmask after removing stat if it was present; otherwise the original states.
1. Call BitStatusUtil.check with a two-element list containing states and stat to validate the inputs before making changes. → validation_result
2. Evaluate whether the stat flag is present in states by calling BitStatusUtil.has(states, stat). → has_flag
3. When has_flag is false, return the original states unchanged. → result
   ? Return states XOR stat to clear the stat flag from states.
