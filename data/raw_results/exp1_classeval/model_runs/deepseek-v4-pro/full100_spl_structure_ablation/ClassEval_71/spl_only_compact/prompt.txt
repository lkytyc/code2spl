Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

## __init__(map: object)

## check_win() → boolean
Summary: Count how many boxes are on targets and mark the game as over when the number of boxes on targets equals the target count.
#   → is_game_over: boolean — Indicates whether the game has been marked as over after checking whether all targets are covered by boxes.
1. Initialize box_on_target_count to the integer constant 0. → box_on_target_count
2. For each box in self.boxes: if box is in self.targets, increment box_on_target_count by 1; otherwise do nothing and continue to the next box. → box_on_target_count
3. After the loop, if box_on_target_count equals self.target_count, set self.is_game_over to True; if the condition is false, leave self.is_game_over unchanged. → is_game_over
4. Return self.is_game_over. → is_game_over

## init_game()
Summary: Initialize the game state by scanning the map grid to locate the player start, target positions, and box positions.
1. For each row in range(len(self.map)): → row
2. Within the outer for loop over row, for each col in range(len(self.map[row])): → col
3. Within the outer for loop over row and inner for loop over col, if self.map[row][col] equals "O", assign row to self.player_row and col to self.player_col. → self.player_row
4. Within the outer for loop over row and inner for loop over col, else if self.map[row][col] equals "G", append (row, col) to self.targets and increment self.target_count by 1. → self.targets
5. Within the outer for loop over row and inner for loop over col, else if self.map[row][col] equals "X", append (row, col) to self.boxes. → self.boxes

## move(direction: str) → bool
Summary: Attempts to move the player in the given direction, pushing a box when the target cell contains one and the box destination is not a wall, and returns the result of check_win.
#   direction: str — One-character movement direction: 'w' up, 's' down, 'a' left, 'd' right; any other value leaves the proposed coordinates unchanged.
#   → result: bool — The return value from self.check_win() after the attempted move.
1. Initialize new_player_row from self.player_row and new_player_col from self.player_col. → new_player_coords
2. Determine the proposed player coordinates by checking direction: if direction equals 'w', decrement new_player_row by 1; else if direction equals 's', increment new_player_row by 1; else if direction equals 'a', decrement new_player_col by 1; else if direction equals 'd', increment new_player_col by 1; otherwise leave both new_player_row and new_player_col unchanged. → proposed_player_coords
3. If self.map[new_player_row][new_player_col] is '#', skip the player and box update logic; otherwise enter the target-cell-clear branch. → wall_check
4. Within the target-cell-clear branch, if (new_player_row, new_player_col) is present in self.boxes, compute new_box_row = new_player_row + (new_player_row - self.player_row) and new_box_col = new_player_col + (new_player_col - self.player_col); otherwise enter the empty-cell branch. → box_check
5. Within the target-cell-clear branch and box-present branch, if self.map[new_box_row][new_box_col] is '#', skip the box push and player update; otherwise remove (new_player_row, new_player_col) from self.boxes, append (new_box_row, new_box_col) to self.boxes, set self.player_row = new_player_row, and set self.player_col = new_player_col. → box_push_attempt
6. Within the target-cell-clear branch and empty-cell branch, set self.player_row = new_player_row and self.player_col = new_player_col. → player_move
7. Return self.check_win(). → move_result
