Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

# Class: SQLQueryBuilder

## delete(table: str, where: dict) → str
Summary: Constructs a DELETE SQL statement from a table name and optional WHERE equality conditions.
#   table: str — Target table name for the DELETE statement.
#   where: dict — Optional dictionary of column names to values used as equality filters in the WHERE clause; defaults to None.
#   → query: str — The constructed DELETE SQL statement.
1. Assign query to the DELETE FROM statement formed by interpolating table into the SQL text. → query
2. If where is truthy, append ' WHERE ' plus the conjunction of key='value' pairs from where.items() joined by ' AND ' to query. → query
3. Return query. → query

## insert(table: str, data: dict) → str
Summary: Builds an SQL INSERT statement by formatting dictionary keys as comma-separated columns and dictionary values as comma-separated single-quoted literals for a given table.
#   table: str — The target SQL table name.
#   data: dict — A dictionary-like object whose keys are column names and whose values are row values to insert.
#   → insert_statement: str — The generated SQL INSERT statement string.
1. Extract the dictionary keys from data using data.keys(). → key_view
2. Join the extracted keys into a single comma-separated string using ', ' as the separator. If data is empty, the result is an empty string; if any key is not a string, the join operation raises TypeError. → keys
3. Extract the dictionary values from data using data.values(). → value_view
4. For each value v in value_view, format it as a single-quoted string by surrounding v with single quotes without escaping any single quotes inside v. → quoted_values
5. Join the quoted values into a single comma-separated string using ', ' as the separator. If data is empty, the result is an empty string. → values
6. Return an INSERT statement string composed from the given table, the joined keys as the column list, and the joined quoted values as the value list. → insert_statement

## select(table: string, columns: string or iterable, where: dict or None) → string
Summary: Builds a SQL SELECT query string from a table name, an optional column list or '*', and optional equality WHERE conditions.
#   table: string — Name of the target table.
#   columns: string or iterable — Column selection; the string '*' or an iterable of column names.
#   where: dict or None — Optional mapping of column names to values used to build equality WHERE conditions.
#   → query: string — The generated SQL SELECT query string.
1. If columns is not equal to the string '*', replace columns with the result of joining the columns iterable using ', '. → columns
2. Construct query as the string 'SELECT {columns} FROM {table}' using the current columns and table values converted to strings. → query
3. If where is truthy, append ' WHERE ' plus the string formed by joining each key='value' item from where.items() with ' AND '. → query
4. Return query. → query

## update(table: str, data: dict, where: dict) → str
Summary: Builds and returns a SQL UPDATE statement from a table and data mapping, optionally adding a WHERE clause from a where mapping.
#   table: str — Target table name inserted directly into the SQL UPDATE statement.
#   data: dict — Mapping of column names to values used to construct the SET clause; values are formatted directly without escaping.
#   where: dict — Optional mapping of column names to values used to construct the WHERE clause. Defaults to None. If falsy, no WHERE clause is added.
#   → query: str — Generated SQL UPDATE statement.
1. Construct update_str by formatting each data item in iteration order as key='value' and joining the fragments with ', '; if data is empty, update_str is an empty string. → update_str
2. Build query as 'UPDATE {table} SET {update_str}' using the provided table and update_str. → query
3. If where is truthy, append ' WHERE ' plus the fragments from formatting each where item in iteration order as key='value' joined by ' AND ' to query. → query
4. Return query. → query
