Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

# Class: CookiesUtil
# Fields: cookies_file, cookies
# Calls: get_cookies→_save_cookies

## __init__(cookies_file: object)
Summary: Initializes cookie state by storing the provided cookies file reference and resetting the loaded cookies to None.
#   cookies_file: object — Reference to the file path or file object used for loading cookies; stored unchanged on the instance.
1. Store the input parameter cookies_file directly into the instance attribute self.cookies_file without transformation. → self.cookies_file
2. Set the instance attribute self.cookies to the literal constant None, representing the default unloaded state. → self.cookies

## _save_cookies() → boolean
Summary: Save the current cookies to the configured cookies file as JSON, returning True on success and False on any failure.
#   → success: boolean — True if the cookies were saved successfully, False if any exception occurred during saving.
1. Open self.cookies_file in write mode and assign the opened file handle to file. → file
2. Write self.cookies to the opened file as JSON using json.dump. → dump_result
3. Return True after the JSON dump completes successfully. → return_value
   ? Return False from the exception handler.

## get_cookies(reponse: dict)
Summary: Retrieves the 'cookies' value from the response mapping, assigns it to the instance attribute self.cookies, and then calls self._save_cookies() to persist the cookies.
#   reponse: dict — A mapping-like object containing the key 'cookies' whose value is assigned to self.cookies.
1. Assign self.cookies to the value of reponse['cookies'], preserving the reference and any None or falsey value unchanged. → self.cookies
2. Call self._save_cookies() without capturing its return value. → _save_cookies_return_value

## load_cookies() → dict
Summary: Loads JSON cookie data from the configured cookies file and returns it as a dictionary, returning an empty dictionary if the file is not found.
#   → result: dict — Parsed JSON cookies data as a dictionary, or an empty dictionary when the cookies file is not found.
1. Inside the try block, attempt to open the file specified by self.cookies_file in read mode. → file
2. Inside the try block, parse the JSON content from the opened file into a dictionary. → cookies_data
3. Inside the try block, return the parsed cookies_data dictionary. → return
   ? Return an empty dictionary as the fallback result.

## set_cookies(request: dict)
Summary: Builds a semicolon-separated cookie header string from all key-value pairs in self.cookies and assigns it to request['cookies'].
#   request: dict — The request object or dictionary where the generated cookie header is written under the key 'cookies'.
1. Retrieve the key-value pairs from self.cookies using its items() method, preserving the mapping's insertion order. → cookie_items
2. For each key and value in cookie_items, format the pair as a single string in the form key=value using the f-string f'{key}={value}', without escaping, quoting, or encoding the raw values. → formatted_pairs
3. Join all elements of formatted_pairs into one string using the separator '; '; when formatted_pairs is empty, produce an empty string. → cookie_header
4. Assign cookie_header to request['cookies'], overwriting any previous value at that key. → request
