Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

Class specification:

# Class: PDFHandler
# Fields: filepaths, readers

## __init__(filepaths: Iterable[str])
Summary: Stores the provided file paths and initializes an ordered list of PDF reader objects by applying PyPDF2.PdfReader to each path in the input iterable.
#   filepaths: Iterable[str] — An iterable of file paths that will be stored directly and used to create one PyPDF2.PdfReader object per path.
1. Assign the parameter filepaths directly to self.filepaths without copying or transforming it. → self.filepaths
2. Within the list comprehension, for each element fp in the filepaths iterable, create PyPDF2.PdfReader(fp), collect the resulting reader objects in the same order as the input iterable, and assign the new list to self.readers. If filepaths is an empty iterable, self.readers becomes an empty list; if filepaths is a single string, it is iterated character-by-character; no None handling is performed. → self.readers

## extract_text_from_pdfs() → List[str]
Summary: Extracts text from every page of every reader in self.readers and returns the collected page texts in deterministic order.
#   → pdf_texts: List[str] — A list of extracted page texts, ordered by reader order and ascending page index.
1. Initialize an empty list named pdf_texts. → pdf_texts
2. For each reader in self.readers, in the order they appear, execute the following page loop. If self.readers is empty, skip the loop body. → reader
3. Within the outer loop over reader, for each page_num from 0 to len(reader.pages)-1 inclusive, in ascending order, set page = reader.pages[page_num]. If reader.pages is empty, skip the inner loop body. → page
4. Within the same inner loop, append page.extract_text() to pdf_texts. → pdf_texts
5. After all readers and pages have been processed, return pdf_texts. → pdf_texts

## merge_pdfs(output_filepath: string) → string
Summary: Merges all pages from each PDF reader in self.readers into a single PDF written to output_filepath and returns a confirmation message.
#   output_filepath: string — File path where the merged PDF will be written.
#   → return_value: string — Confirmation message containing the output file path.
1. Create a new PyPDF2.PdfWriter instance with no constructor arguments and assign it to pdf_writer. → pdf_writer
2. For each reader in self.readers, iterate over the readers in their existing order. → reader
3. Within the outer loop over reader, for each page_num from 0 to len(reader.pages) - 1 inclusive, retrieve page = reader.pages[page_num] and append it to pdf_writer using pdf_writer.add_page(page). → pdf_writer
4. Using a with block, open output_filepath in binary write mode as out and write the contents of pdf_writer to out. → out
5. Return the string f"Merged PDFs saved at {output_filepath}". → return_value
