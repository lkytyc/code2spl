`Words2Numbers` is a class that converts English number words embedded in arbitrary text into their numeric equivalents, leaving non-numeric words untouched.

**Setup (constructor)**

On instantiation it builds a lookup table (`numwords`) mapping every recognized English number word to a pair: a scale multiplier and an additive increment. Units ("one" through "nineteen") and tens ("twenty" through "ninety") get a scale of 1 with their numeric value as the increment. Scale words ("hundred", "thousand", "million", etc.) get a large multiplier and zero increment. The word "and" is also registered as a no-op passthrough. It also stores a small dictionary of irregular ordinal forms ("first", "second", "third", etc.) and a list of ordinal suffix rules for stripping endings like "-ieth" → "-y" and "-th" → "".

**Conversion (`text2int`)**

Takes a string, replaces hyphens with spaces, then walks it word by word. For each word:
- If it's a known irregular ordinal, it uses the mapped value directly.
- Otherwise it tries to strip recognized ordinal suffixes to recover the base cardinal form.
- If the resulting word isn't in the lookup table, any accumulated numeric value is flushed to the output string as a digit string, the non-numeric word is passed through as-is, and the running accumulator resets.
- If it is in the table, the scale and increment are applied: for sub-hundred scales, the current value is multiplied and incremented; for scales above 100 (thousand and up), the current value is added into a higher-level result bucket and the current accumulator resets.

At the end, any remaining accumulated value is appended. The return value is a string with number-word spans replaced by digit strings and all other words preserved.

**Validation (`is_valid_input`)**

Runs the same tokenization and ordinal-stripping logic but only checks whether every word is recognized. Returns `True` if all words map to known number words (or ordinals), `False` the moment any unrecognized word is encountered. This means it only accepts strings that are purely numeric in word form — any embedded non-numeric word causes it to return `False`, unlike `text2int` which handles mixed input.

**Notable behaviors and edge cases**

- Mixed text like "I have twenty three apples" comes out as "I have 23 apples".
- Ordinal words ("third", "forty-fifth") are normalized before lookup, so they convert correctly.
- There's no handling for negative numbers or decimals.
