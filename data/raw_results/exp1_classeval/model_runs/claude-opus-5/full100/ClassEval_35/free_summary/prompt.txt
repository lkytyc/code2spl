`EightPuzzle` is a class that represents and solves the classic sliding tile puzzle on a 3×3 grid, where tiles numbered 1–8 plus a blank (represented as `0`) must be rearranged to reach the ordered goal state.

**Setup**

The constructor takes an initial board state (a 3×3 nested list) and stores the fixed goal state `[[1,2,3],[4,5,6],[7,8,0]]`.

**Core operations**

- `find_blank` scans the board to return the row and column of the `0` tile.
- `move` takes a state and a direction string (`'up'`, `'down'`, `'left'`, `'right'`) and returns a new state with the blank swapped in that direction. The directions describe where the blank moves, so `'up'` swaps the blank with the tile directly above it. No bounds checking is done here — the caller is expected to only pass valid directions.
- `get_possible_moves` returns the list of valid directions given the blank's current position, preventing it from moving off the edge of the board.

**Solver**

`solve` runs a breadth-first search (BFS). It maintains an open list of `(state, path)` pairs, starting from the initial state with an empty path. On each iteration it takes the front item, checks whether it matches the goal, and if not generates all successor states from valid moves. Already-visited states (tracked in a closed list) are skipped. When the goal is found, it returns the list of move strings that led there. If the open list empties without finding a solution, it returns `None`.

The path returned is an ordered sequence of direction strings representing each move made to reach the goal from the initial state.

**Notable limitation**: the closed list is a plain Python list checked with `not in`, which does an O(n) linear scan on every visited-state lookup. For large search spaces this becomes slow; a set of hashable state representations would be the typical fix.
