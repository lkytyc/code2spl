`ArgumentParser` is a simple command-line argument parser that handles two common argument styles: `--key=value` / `--flag` (long form) and `-key value` / `-flag` (short form).

**Setup** — before parsing, callers register expected arguments via `add_argument`, optionally marking them as required and specifying a type (default: `str`). These are stored in `self.types` and `self.required`.

**Parsing** — `parse_arguments` takes a full command string, discards the first token (the program name), then walks the remaining tokens:
- A token starting with `--` is split on `=`. If it has both a key and value, the value gets type-converted; if it's just a flag name with no `=`, it's stored as `True`.
- A token starting with `-` treats the next token as its value (if that next token doesn't itself start with `-`); otherwise it's stored as `True`.
- Parsed results land in `self.arguments`.

After walking all tokens, it checks whether any registered required arguments are missing. It returns a `(True, None)` tuple on success, or `(False, set_of_missing_keys)` on failure.

**Type conversion** — `_convert_type` looks up the registered type for a key and calls it on the string value. If the key was never registered or the conversion raises a `ValueError`, it falls back to returning the raw string.

**Retrieval** — `get_argument` is a thin wrapper around a dict `.get()`, returning `None` for unknown keys.

One notable limitation: the short-form parser (`-key value`) doesn't advance the index past the consumed value token, so the value token will also be processed as a potential key on the next iteration if it happens to start with `-`. For typical non-flag values this doesn't cause issues, but it's a subtle bug for edge cases.
