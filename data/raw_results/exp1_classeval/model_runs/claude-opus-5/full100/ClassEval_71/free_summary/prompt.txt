`PushBoxGame` is a Sokoban-style puzzle game engine. Here's what it does:

**Initialization**

The constructor takes a 2D grid (`map`) of characters and scans it to find three things: the player's starting position (`O`), target squares (`G`), and box positions (`X`). Wall cells are `#`. These are stored as instance state.

**Movement (`move`)**

Accepts a direction string — `w`, `a`, `s`, `d` for up/left/down/right — and computes where the player would step. The move is allowed only if the destination is not a wall. If a box is sitting on the destination cell, the code checks the cell one step further in the same direction; if that cell is also not a wall, the box slides into it and the player steps forward. If the box can't move (wall behind it), neither the player nor the box moves. Returns the result of `check_win`.

**Win condition (`check_win`)**

Counts how many boxes currently occupy a target cell. If that count equals the total number of targets, `is_game_over` is set to `True`. The game doesn't enforce a stop after that — it just flags it and returns the boolean.

**Key behaviors and limitations**

- Boxes are stored as a plain list of tuples, so the collision check is an `in` lookup on that list — fine for small grids but O(n) per move.
- There's no bounds checking on player movement; moving into the edge of the map will raise an `IndexError`.
- There's no undo, reset, or rendering — this is purely the game state and logic layer.
- A box can be pushed onto another box's cell without blocking, because the "is there a box here?" check only looks at the immediate destination, not the cell the pushed box would land on if another box is already there. That's a bug for levels with adjacent boxes.
