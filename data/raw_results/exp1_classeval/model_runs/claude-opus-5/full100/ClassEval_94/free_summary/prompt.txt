`VendingMachine` models a simple vending machine with an inventory and a running customer balance.

**State**
- `inventory`: a dict mapping item names to their price and quantity.
- `balance`: the amount of money the customer has inserted so far.

**Key behaviors**

- `add_item(name, price, quantity)` adds a new item only if it doesn't already exist. If the item is already in inventory, it delegates to `restock_item` instead, which just increments the quantity — the price is not updated.

- `restock_item(name, quantity)` adds stock to an existing item and returns `True`. Returns `False` if the item isn't in inventory. This is also used internally by `add_item` as a guard.

- `insert_coin(amount)` adds to the balance and returns the new total.

- `purchase_item(name)` checks that the item exists, has stock, and that the balance covers the price. On success it deducts the price, decrements quantity by one, and returns the remaining balance. Returns `False` if the item is unknown, out of stock, or the balance is insufficient — with no distinction between those cases.

- `display_items()` returns a formatted string listing each item with its price and remaining quantity, one per line. Returns `False` if inventory is empty.

**Notable design points**
- There's no change-dispensing or refund method; balance just accumulates across purchases.
- `purchase_item` returns `False` on any failure, so the caller can't tell whether the item was missing, empty, or unaffordable.
- `add_item` silently ignores a price update for an existing item because it short-circuits to `restock_item`.
