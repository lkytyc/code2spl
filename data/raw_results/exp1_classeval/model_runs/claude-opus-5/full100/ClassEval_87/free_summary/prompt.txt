`TimeUtils` is a utility class for common datetime operations, built around a single `datetime` object captured at instantiation time.

**Initialization**
When created, it records the current timestamp once via `datetime.datetime.now()`. All time-based methods operate on this snapshot, not a live clock.

**Methods**

- `get_current_time()` — returns the snapshot time as an `HH:MM:SS` string.
- `get_current_date()` — returns the snapshot date as a `YYYY-MM-DD` string.
- `add_seconds(seconds)` — adds a given number of seconds to the snapshot and returns the resulting time as `HH:MM:SS`. The original snapshot is unchanged.
- `string_to_datetime(string)` — parses a `"YYYY-MM-DD HH:MM:SS"` string into a `datetime` object. Used internally by `get_minutes`.
- `datetime_to_string(datetime)` — formats any `datetime` object back to a `"YYYY-MM-DD HH:MM:SS"` string.
- `get_minutes(string_time1, string_time2)` — accepts two datetime strings, parses them via `string_to_datetime`, subtracts the first from the second, and returns the difference in whole minutes (rounded). It uses only the `.seconds` component of the timedelta, which means it ignores any day-level difference — a potential bug if the two times span midnight or are more than 24 hours apart.
- `get_format_time(year, month, day, hour, minute, second)` — constructs a `datetime` from discrete components and returns it as a `"YYYY-MM-DD HH:MM:SS"` string. It does not use the instance snapshot at all.

**Key observations**
The instance snapshot is fixed at construction — calling `get_current_time()` later will not reflect the actual current time at that point. The `datetime_to_string` method shadows the built-in `datetime` parameter name with its own local argument, which could cause confusion but works correctly in isolation. The `get_minutes` calculation using `.seconds` instead of `.total_seconds()` is a latent correctness issue for inputs spanning multiple days.
