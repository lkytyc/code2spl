Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

# Class: VendingMachine

Summary: Initializes a new instance by setting up an empty inventory dictionary and a zero-valued balance counter to establish the object's default starting state.
1. Bind self.inventory to a new empty dictionary literal, establishing the instance attribute with no entries and a falsy initial value; no computation occurs and each instantiation allocates a fresh dict object → self.inventory
2. Bind self.balance to the integer literal 0, establishing the instance attribute as a numeric scalar with value zero; because integers are immutable, future increments or decrements will rebind the attribute to a new object rather than mutating in place → self.balance

## add_item(item_name: string, price: number, quantity: integer)

#   item_name: string — The name of the item to add or update in the inventory
#   price: number — The unit price of the item
#   quantity: integer — The quantity of the item to add
1. Call self.restock_item with item_name and quantity to attempt restocking the item → restock_result
2. Evaluate the boolean result of restock_result; if it is truthy, restocking succeeded and no further action is needed — skip the alternative flow → restock_succeeded

## display_items()
Summary: Checks whether the inventory is populated and, if so, formats each item as a 'name - $price [quantity]' string and returns them joined by newlines; returns false immediately if the inventory is empty or missing.
1. Evaluate whether self.inventory is falsy (None, empty dict, or any other falsy value) → inventory_is_empty
2. If inventory_is_empty is True, return False immediately and exit the method → early_exit_false
3. Initialize an empty list named items to accumulate formatted entry strings → items
4. Iterate over every key-value pair in self.inventory using .items(), binding each key to item_name and each value dict to item_info → inventory_iterator
5. Within the for loop, for each iteration format item_name, item_info['price'], and item_info['quantity'] into the string '{item_name} - ${item_info["price"]} [{item_info["quantity"]}]' and append it to items → formatted_entry
6. After the loop completes, join all entries in items with a newline character '\n' as the separator → joined_string
7. Return joined_string as the final result of the method → return_value
   ? Return the boolean value False immediately without building the items list or iterating

## insert_coin(amount: number) → number

#   amount: number — The monetary amount to add to the balance
#   → balance: number — The updated balance after adding the inserted amount
1. Add amount to self.balance, storing the result back in self.balance → self.balance
2. Return self.balance as the result of the method → return_value

## purchase_item(item_name: string) → float or bool
Summary: Attempts to purchase a named item by verifying it exists in inventory, confirming sufficient stock and balance, then deducting the price and decrementing quantity before returning the updated balance, or returning False on any failure.
#   item_name: string — The key used to look up the item in the inventory dictionary
#   → result: float or bool — The updated balance after a successful purchase, or False if the item does not exist, is out of stock, or the balance is insufficient
1. Check whether item_name exists as a key in self.inventory → item_exists
2. If item_exists is True, retrieve the item dict from self.inventory using item_name as the key and assign it to item → item
3. Within the item-exists branch, evaluate the compound condition: item['quantity'] is strictly greater than 0 AND self.balance is greater than or equal to item['price']; due to short-circuit evaluation, the balance check is skipped entirely when quantity is 0 → can_purchase
4. If can_purchase is True, subtract item['price'] from self.balance and store the result back in self.balance → self.balance
5. Within the same can_purchase branch, decrement item['quantity'] by 1 in place → item['quantity']
6. Return self.balance as the result of a successful transaction → return_value
   ? Return False immediately without modifying self.balance or item['quantity']
   ? Return False immediately without accessing or modifying any inventory entry or self.balance

## restock_item(item_name: string, quantity: number) → boolean
Summary: Increments the quantity of an existing inventory item by a given amount, returning true on success or false if the item does not exist in the inventory.
#   item_name: string — The key identifying the item to restock within the inventory dictionary
#   quantity: number — The amount to add to the item's existing quantity
#   → result: boolean — True if the item was found and its quantity successfully incremented; False if the item does not exist in the inventory
1. Check whether item_name exists as a key in self.inventory using a membership test → item_exists
2. If item_exists is true, access self.inventory[item_name] and increment its 'quantity' field in-place by adding quantity to the current value → updated_quantity
3. Return True to signal that the restock operation succeeded → success_flag
   ? Return False immediately without modifying any state, signalling that the item does not exist in the inventory
