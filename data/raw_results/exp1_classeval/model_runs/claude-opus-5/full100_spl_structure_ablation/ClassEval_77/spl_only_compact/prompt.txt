Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

#   SCREEN_HEIGHT: numeric — Height of the game screen in pixels; used both to cache as an instance attribute and to compute the initial vertical center position
#   BLOCK_SIZE: numeric — Size of one grid block in pixels; cached as an instance attribute but not used in any computation within this method
#   food_position: any — Initial position of the food item; cached as an instance attribute but not used in any computation within this method
1. Set self.length to the integer literal 1 → self.length
2. Set self.score to the integer literal 0 → self.score
3. Set self.SCREEN_WIDTH to the value of the SCREEN_WIDTH parameter → self.SCREEN_WIDTH
4. Set self.SCREEN_HEIGHT to the value of the SCREEN_HEIGHT parameter → self.SCREEN_HEIGHT
5. Set self.BLOCK_SIZE to the value of the BLOCK_SIZE parameter → self.BLOCK_SIZE
6. Compute the horizontal center as SCREEN_WIDTH divided by 2 using true division (result is float) and the vertical center as SCREEN_HEIGHT divided by 2 using true division (result is float); construct a single-element list containing one tuple of those two float values and assign it to self.positions → self.positions
7. Set self.food_position to the value of the food_position parameter → self.food_position

## eat_food()
Summary: Increases the snake's length by 1 and score by 100, then repositions the food at a new random location on the board.
1. Increment self.length by 1 → self.length
2. Increment self.score by 100 → self.score
3. Call self.random_food_position() to place food at a new random position → food_position

## move()
Summary: Updates the snake's head position by advancing one grid cell in the given direction with screen-wrapping, then either resets the game on self-collision, eats food if the new position matches it, or slides the body forward by prepending the new head and trimming the tail to maintain the snake's current length.
1. Read self.positions[0] into cur, representing the current head position as a (x, y) tuple → cur
2. Unpack direction into scalar components x and y → x,
3. Compute new head position: new_x = (cur[0] + x * self.BLOCK_SIZE) % self.SCREEN_WIDTH and new_y = (cur[1] + y * self.BLOCK_SIZE) % self.SCREEN_HEIGHT, assembling both into a 2-tuple; the modulo ensures wrapping at screen boundaries in both axes and always yields a valid on-screen grid coordinate → new
4. If new equals self.food_position, call self.eat_food() → food_check
5. Evaluate the collision guard: check len(self.positions) > 2 (short-circuit guard, skips membership test when the list has 2 or fewer elements) AND new in self.positions[2:] (new head lands on a body segment beyond the neck) → collision
6. If collision is true, call self.reset() to restart the game; execution of the move ends here for this branch → reset_result
7. Otherwise (collision is false), insert new at index 0 of self.positions, making it the new head → positions_after_insert
8. If len(self.positions) strictly exceeds self.length after the insert, call self.positions.pop() to remove the last (tail) element, keeping the list exactly self.length entries long → positions_after_trim
   ? Call self.eat_food() to handle food consumption; execution then continues to the collision check without returning early
   ? The short-circuit in the collision condition (len > 2) evaluates to false immediately, so the membership test is skipped entirely and the else branch (normal movement) is always taken
   ? Skip the pop() call; the positions list grows by one, which happens when the snake has eaten food and its length has increased

## random_food_position(self: object)
Summary: Repeatedly generates a random grid-aligned (x, y) coordinate for food placement until the chosen position does not coincide with any of the snake's current body segment positions.
#   self: object — The game instance, providing food_position (current food coordinate tuple), positions (collection of occupied grid coordinates representing the snake body), SCREEN_WIDTH, SCREEN_HEIGHT, and BLOCK_SIZE constants
1. Check whether self.food_position is a member of self.positions; if it is not, skip the loop body entirely and return without changes → loop_condition_initial
2. While self.food_position is contained in self.positions, generate a new candidate x-coordinate by drawing a random integer in the inclusive range [0, SCREEN_WIDTH // BLOCK_SIZE - 1] and multiplying by BLOCK_SIZE to snap to a valid grid column → candidate_x
3. Within the same loop iteration, generate a new candidate y-coordinate by drawing a random integer in the inclusive range [0, SCREEN_HEIGHT // BLOCK_SIZE - 1] and multiplying by BLOCK_SIZE to snap to a valid grid row → candidate_y
4. Assign the tuple (candidate_x, candidate_y) to self.food_position, replacing the previous candidate → self.food_position
5. Re-evaluate the loop condition; repeat the three steps above if the new self.food_position is still contained in self.positions, otherwise exit the loop → loop_exit
   ? Skip the loop body entirely; self.food_position remains unchanged and the method returns immediately

## reset()
Summary: Resets the snake's state to its initial values by setting length to 1, centering the starting position on screen, zeroing the score, and placing food at a new random location.
1. Set self.length to the scalar integer 1, establishing the minimum entity size → self.length
2. Set self.positions to a single-element list containing one tuple; compute the x-coordinate as self.SCREEN_WIDTH divided by 2 and the y-coordinate as self.SCREEN_HEIGHT divided by 2, placing the head at the center of the screen → self.positions
3. Set self.score to the scalar integer 0, resetting the accumulator to its baseline value → self.score
4. Call self.random_food_position() to place food at a new random location on the board → food_position_side_effect
