Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

#   predicted_labels: array — Sequence of labels predicted by the model

## precision(predicted_labels: array, true_labels: array) → float

#   predicted_labels: array — Model-predicted labels or scores for the current batch, supplied by the caller at runtime

## recall(predicted_labels: array, true_labels: array) → float
Summary: Computes the recall metric (TP / (TP + FN)) for a batch of predictions by first accumulating state via update, then guarding against zero-denominator before returning the ratio.
#   predicted_labels: array — Model output values (class indices, probabilities, or logits) for the current batch; no default value, must be supplied by the caller
#   true_labels: array — Ground-truth target labels for the current batch; no default value, must be supplied by the caller
#   → recall_score: float — Recall value in the range [0.0, 1.0], or 0.0 when no actual positive samples exist
1. Call self.update with predicted_labels and true_labels to accumulate batch statistics into the instance's internal accumulators (self.true_positives, self.false_negatives, and related state); no value is returned from this call → state_updated
2. Read self.true_positives and self.false_negatives from instance state and compute their sum to form the recall denominator → denominator
3. If denominator equals exactly 0 (inclusive equality, fires only when both true_positives and false_negatives are simultaneously zero), return the float literal 0.0 immediately as an early exit; no further statements execute → early_return_zero
4. Divide self.true_positives (numerator) by denominator (self.true_positives + self.false_negatives); self.true_positives feeds both numerator and denominator, so it has a non-linear influence on the result, while self.false_negatives affects only the denominator → recall_score
5. Return recall_score to the caller → return_value
   ? Return the float literal 0.0 immediately, bypassing the division expression entirely

## update(predicted_labels: iterable, true_labels: iterable)
Summary: Iterates over paired predicted and true binary labels to accumulate the four cells of a confusion matrix — true positives, false positives, false negatives, and true negatives — on the enclosing metrics object.
#   predicted_labels: iterable — Sequence of predicted binary class labels, each expected to be 0 or 1
#   true_labels: iterable — Sequence of ground-truth binary class labels, each expected to be 0 or 1, paired positionally with predicted_labels
1. Iterate over each (predicted, true) pair produced by zipping predicted_labels with true_labels → current_pair
2. Within the loop, if predicted equals 1 and true equals 1, increment self.true_positives by 1 → self.true_positives
3. Within the loop, else if predicted equals 1 and true equals 0, increment self.false_positives by 1 → self.false_positives
4. Within the loop, else if predicted equals 0 and true equals 1, increment self.false_negatives by 1 → self.false_negatives
5. Within the loop, else if predicted equals 0 and true equals 0, increment self.true_negatives by 1 → self.true_negatives
   ? No branch matches; the pair is silently skipped and no counter is incremented for that iteration
