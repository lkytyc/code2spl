Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

# Class: JSONProcessor

## process_json(file_path: string, remove_key: string) → integer
Summary: Removes a specified key from a JSON file's data dictionary and persists the change to disk, returning 1 on successful deletion, or 0 if the file could not be read or the key was not present.
#   file_path: string — Path to the JSON file to read and potentially modify
#   remove_key: string — The dictionary key to remove from the loaded JSON data
#   → result: integer — Returns 1 if the key was found and successfully removed and written back to disk; returns 0 if the file could not be read or the key was not present in the data
1. Call read_json with file_path and store the result in data → data
2. If data equals 0 or data equals -1, return 0 immediately to signal a read failure → early_return_0
3. Check whether remove_key exists as a key in data → key_present
4. If remove_key is present in data, delete that key from data in place → data_mutated
5. Call write_json with the mutated data and file_path to persist the updated dictionary to disk → write_result
6. Return 1 to signal that the key was found, removed, and the file was written successfully → return_1
   ? Return 0 to signal that no deletion occurred and the file was not modified

## read_json(file_path: str)
Summary: Attempts to load and return parsed JSON data from a file at the given path, returning 0 if the file does not exist and -1 if any error occurs during reading or parsing.
#   file_path: str — Filesystem path to the JSON file to be read
1. Check whether the file at file_path exists on the filesystem using os.path.exists → file_exists
2. Open the file at file_path in read mode → file_handle
3. Parse the open file handle as JSON using json.load → data
4. Return data to the caller → data
   ? Return the integer 0 immediately as an early exit sentinel indicating the file is absent
   ! log: "An error occurred while opening or parsing the JSON file at file_path"
   ! raise: caught_silently "The bare except clause suppresses all exceptions and causes the function to return -1 as an error sentinel instead of propagating the exception"

## write_json(data: any, file_path: str) → int
Summary: Serializes a data object to a JSON file at the specified path, returning 1 on success or -1 if any exception occurs during the operation.
#   data: any — The Python object to serialize as JSON
#   file_path: str — The filesystem path of the output file to write
#   → result: int — Returns 1 if the file was written successfully, or -1 if any exception was raised during opening or writing
1. Open the file at file_path in write mode → file_handle
2. Serialize data to JSON and write it to the open file using json.dump → write_result
3. Return 1 to indicate success → return_value
   ? Return -1 to indicate failure
   ! log: "Exception caught by bare except clause; no exception details are logged or re-raised"
   ! raise: ExceptionName "Exception description"
