Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

## extract_text_from_pdfs(self: object) → list
Summary: Iterates over all PDF readers held by the instance, extracts the text from every page of each reader in document order, and returns a flat list of per-page text strings spanning all loaded PDFs.
#   self: object — Instance owning self.readers, a collection of PDF reader objects each exposing a pages sequence whose items support extract_text()
#   → pdf_texts: list — Flat list of strings (or None for image-only pages) where each element is the extracted text of one page, ordered by reader then by ascending page index
1. Initialize pdf_texts as an empty list to accumulate per-page text results → pdf_texts
2. Begin outer for loop: iterate over each reader object in self.readers; for each reader, begin inner for loop iterating page_num from 0 to len(reader.pages) - 1 inclusive (range upper bound is exclusive, so every valid page index is visited exactly once) → reader,
3. Within the outer loop over reader and the inner loop over page_num, retrieve the page object by direct index subscript: page = reader.pages[page_num] → page
4. Within the same nested loop body, call extract_text() on page and append the return value to pdf_texts; the return value may be None for scanned or image-only pages, which is appended without a guard → pdf_texts
5. After both loops have exhausted all readers and all pages, return pdf_texts → pdf_texts
   ? Return pdf_texts as an empty list without entering either loop
   ? Skip the inner loop for that reader and advance the outer loop to the next reader, leaving pdf_texts unchanged for this iteration

## merge_pdfs(output_filepath: str) → str
Summary: Merges all pages from every PDF reader in the instance's reader collection into a single output file written to the specified filepath.
#   output_filepath: str — Filesystem path where the merged PDF output file will be written
#   → result: str — Confirmation message string indicating the filepath where the merged PDF was saved
1. Instantiate a new empty PyPDF2.PdfWriter object with zero pages and assign it to pdf_writer → pdf_writer
2. For each reader in self.readers, iterate over all page indices from 0 through len(reader.pages) - 1 inclusive → reader,
3. Within the outer for loop over reader, for each page_num, retrieve the page object at reader.pages[page_num] and assign it to page → page
4. Within the outer for loop over reader, for each page_num, call pdf_writer.add_page(page) to append the retrieved page to the writer; repeat unconditionally for every page of every reader in order → pdf_writer
5. Open the file at output_filepath in binary write mode ('wb') as out, then call pdf_writer.write(out) to serialize all accumulated pages to disk → out
6. Return the formatted string f"Merged PDFs saved at {output_filepath}" as the method result → result
