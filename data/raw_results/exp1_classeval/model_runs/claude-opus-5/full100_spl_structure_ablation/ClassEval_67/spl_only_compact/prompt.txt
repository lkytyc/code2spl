Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

# Class: Order
# Fields: sales, selected_dishes, menu
# Calls: checkout→calculate_total

## __init__()
Summary: Initializes a restaurant ordering system instance by setting up an empty menu list, an empty selected-dishes list, and an empty sales dictionary to hold inventory, active order selections, and aggregated sales data respectively.
1. Initialize self.menu to an empty list; this list will later hold dish records where each record is a dict with keys 'dish' (string), 'price' (numeric), and 'count' (integer representing available inventory or order quantity) → self.menu
2. Initialize self.selected_dishes to an empty list; this list will later hold user-selected dish records where each record is a dict with keys 'dish' (string), 'count' (integer representing user-selected quantity), and 'price' (numeric) → self.selected_dishes
3. Initialize self.sales to an empty dict; this dict will later accumulate sales data keyed by dish name or session identifier, supporting aggregated revenue or order-count lookups → self.sales

## add_dish(self: object, dish: dict) → bool
Summary: Attempts to add a dish to the selected dishes list by finding it in the menu and decrementing its available count by the requested quantity, returning False immediately if stock is insufficient.
#   self: object — The instance containing the menu list and selected_dishes list
#   dish: dict — A dictionary with at least a 'dish' key (name) and a 'count' key (requested quantity)
#   → result: bool — False if the matching menu item has a count strictly less than the requested dish count; True after successfully appending the dish to selected_dishes
1. Iterate over each item in self.menu, binding the current item to menu_dish → menu_dish
2. Within the for loop, check whether dish['dish'] equals menu_dish['dish'] to determine if the current menu item matches the requested dish by name → name_match
3. Within the for loop, when name_match is True, check whether menu_dish['count'] is strictly less than dish['count'] to determine if available stock is insufficient → stock_insufficient
4. Within the for loop, when name_match is True and stock is not insufficient (menu_dish['count'] >= dish['count']), decrement menu_dish['count'] by dish['count'] in place, then break out of the loop → updated_menu_dish_count
5. After the for loop completes (either via break or full iteration), append dish to self.selected_dishes → updated_selected_dishes
6. Return True to signal that the dish was successfully added → return_value
   ? Return False immediately, exiting the method without appending to selected_dishes

## calculate_total() → number
Summary: Iterates over each selected dish and accumulates a weighted total price by multiplying each dish's unit price by its count and its corresponding sales multiplier.
#   → total: number — The accumulated sum of (price * count * sales_multiplier) for every dish in selected_dishes; returns 0 if selected_dishes is empty
1. Initialize local variable total to the integer value 0 → total
2. For each dish object in self.selected_dishes, retrieve dish['price'], dish['count'], and self.sales[dish['dish']], multiply all three together, and add the product to total → total
3. Return total → return_value

## checkout()
Summary: Validates that at least one dish has been selected, computes the order total from the current selection, clears the selection, and returns the total.
1. Get the count of items in self.selected_dishes → selected_dishes_count
2. Call self.calculate_total() and store the return value in total → total
3. Reset self.selected_dishes to an empty list (length 0, no elements), permanently discarding all current dish references → self.selected_dishes
4. Return total → return_value
   ? Return False immediately, skipping total computation and list reset
