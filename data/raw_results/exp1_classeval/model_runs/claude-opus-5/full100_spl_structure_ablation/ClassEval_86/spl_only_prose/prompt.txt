Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

## check_winner(self: object) → string or None
Summary: Scans all eight win lines of a 3x3 tic-tac-toe board (three rows, three columns, two diagonals) and returns the winning player's token if any line is fully occupied by the same non-space mark, or None if no winner exists yet.
#   self: object — Instance of the game class; provides access to self.board, a 3x3 list-of-lists where each cell holds 'X', 'O', or ' '
#   → winner: string or None — The winning player's token ('X' or 'O') if a winning line is found; None if no winner exists
1. Iterate over each row in self.board; for each row evaluate the chained comparison row[0] == row[1] == row[2] != ' ' (equivalent to: row[0] equals row[1], AND row[1] equals row[2], AND row[2] is not a space); if the condition holds, immediately return row[0] as the winning token (early exit) → winner_from_row_or_continue
2. Iterate over column indices 0, 1, 2 via range(3); for each col evaluate the chained comparison self.board[0][col] == self.board[1][col] == self.board[2][col] != ' ' (equivalent to: board[0][col] equals board[1][col], AND board[1][col] equals board[2][col], AND board[2][col] is not a space); if the condition holds, immediately return self.board[0][col] as the winning token (early exit) → winner_from_col_or_continue
3. Check the main diagonal by evaluating self.board[0][0] == self.board[1][1] == self.board[2][2] != ' '; if true, immediately return self.board[0][0] as the winning token (early exit) → winner_from_main_diagonal_or_continue
4. Check the anti-diagonal by evaluating self.board[0][2] == self.board[1][1] == self.board[2][0] != ' '; if true, immediately return self.board[0][2] as the winning token (early exit) → winner_from_anti_diagonal_or_continue
5. If none of the eight win-line checks triggered an early return, return None to indicate no winner has been found → none_result
   ? During the row-scanning loop, the first row satisfying row[0] == row[1] == row[2] != ' ' causes an immediate return of row[0]; the column loop, diagonal checks, and final return None are never executed

## is_board_full(self: object) → boolean
Summary: Scans every row of the game board and returns False immediately upon finding any empty cell (space character), or True if no row contains a space, indicating the board is completely filled.
#   self: object — Instance of the game class providing access to self.board, a 2D iterable where each row is a list or string of cell values
#   → result: boolean — False if at least one empty cell (space character) exists anywhere on the board; True if every cell in every row is occupied
1. Iterate over each row in self.board, binding the current row to the variable row on each iteration → current_row
2. Within the for loop, check whether a space character (' ') is present anywhere in current_row using the membership operator, which short-circuits on the first match found → has_empty_cell
3. Within the for loop, if has_empty_cell is True, immediately return False from the method, exiting both the loop and the method without inspecting any remaining rows or cells → early_return_false
4. After the for loop completes without triggering an early return, return True to indicate that no empty cell was found in any row and the board is fully occupied → return_true
   ? On the very first membership check, has_empty_cell is True; return False immediately without iterating further
   ? The for loop completes all O(m x n) membership checks with no early return triggered; fall through to the post-loop return True statement

## make_move(row: int, col: int) → bool

4. Return True to indicate the move was successfully accepted and applied → move_accepted
