Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

## add_white_list(addr: any)
Summary: Adds an address to the whitelist if it is not already present, returning False on duplicate or the updated whitelist on success.
#   addr: any — The address to add to the whitelist
1. Check whether addr is already a member of self.white_list → is_duplicate
2. If is_duplicate is True, return False immediately without mutating self.white_list → early_return_false
3. Append addr to self.white_list → updated_white_list
4. Return self.white_list (the full updated list) as the result of the method → return_updated_white_list
   ? Return False immediately; no mutation of self.white_list occurs

## del_white_list(addr: any) → list or bool
Summary: Removes a given address from the whitelist if it exists, returning the updated list, or returns False if the address is not present.
#   addr: any — The address value to remove from the whitelist
#   → result: list or bool — The modified whitelist after removal if addr was present, or False if addr was not found
1. Check whether addr is absent from self.white_list using a membership test → membership_check
2. If addr is not in self.white_list, return False immediately as an early-exit failure signal without modifying the list → early_return_false
3. If addr is present in self.white_list, call self.white_list.remove(addr) to mutate the list by removing the first occurrence of addr → removal_result
4. Return the live self.white_list object (not a copy) to the caller after the removal → return_white_list
   ? Return False immediately; skip all mutation steps and do not touch self.white_list

## recv(info: dict) → any
Summary: Validates an incoming message dict, rejects senders not on the whitelist with False, caches the message on the instance, and returns the message content to authorized callers.
#   info: dict — A dictionary expected to contain at least the keys 'addr' (sender address) and 'content' (message payload)
#   → result: any — Returns -1 on malformed input, False when the sender is not on the whitelist, or the message content value when the sender is authorized
1. Check whether info is a dict and contains both 'addr' and 'content' keys; if any condition fails, return -1 immediately (short-circuit OR guard) → validation_check
2. Extract info['addr'] into local variable addr → addr
3. Extract info['content'] into local variable content → content
4. Check whether addr is present in self.white_list → whitelist_check
5. Store the dict {'addr': addr, 'content': content} into self.receive_struct, overwriting any previously cached message → self.receive_struct
6. Return self.receive_struct['content'], which equals content → return_value
   ? Return -1 immediately without further processing
   ? Return False immediately, skipping the cache write and content return

## send(info: dict) → string
Summary: Validates that the input is a dict containing both 'addr' and 'content' keys, then snapshots those two fields into the instance's send_struct attribute; returns an error string immediately if validation fails.
#   info: dict — Caller-supplied payload expected to contain string keys 'addr' and 'content'; any other type or missing keys triggers an early return

   ? Return the string 'info structure is not correct' immediately, skipping all remaining steps

## show(type: string)
