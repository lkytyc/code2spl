Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

## compute_idf_weight_dict(total_num: int, number_dict: dict) → dict
Summary: Converts a dictionary of term counts into a smoothed IDF weight dictionary by mapping each term to its log-transformed inverse document frequency, using a +1 smoothing offset to avoid division by zero.
#   total_num: int — Total number of documents, used as the numerator baseline in the IDF formula
#   number_dict: dict — Mapping from term keys to their document frequency counts
#   → result: dict — Mapping from the original term keys to their smoothed IDF weight values as float scalars
1. Initialize an empty dict index_2_key_map, an integer counter index set to 0, and an empty list count_list → index_2_key_map,
2. Iterate over each (key, count) pair in number_dict.items() in insertion order; on each iteration store index_2_key_map[index] = key to record the positional-to-key mapping, append count to count_list to preserve the parallel ordering, then increment index by 1 → index_2_key_map,
3. Convert count_list to a NumPy array a, inheriting dtype from the list elements → a
4. Overwrite a with the smoothed IDF transform: a = log((total_num + 1) / (a + 1)), where the +1 offsets on both numerator and denominator prevent log(0) and division-by-zero when any count or total_num is 0; higher counts yield lower weights and the result is always finite for non-negative inputs → a
5. Initialize an empty dict result to accumulate the final key-to-weight mapping → result
6. Iterate over each (index, w) pair produced by enumerate(a); on each iteration look up key = index_2_key_map[index] to recover the original term key for that position, then assign result[key] = w; this re-indexes the positional array back to semantic term keys → result
7. Return result → result

   ! raise: KeyError "The integer index generated by enumerate has no corresponding key in index_2_key_map"

## cosine_similarities()
Summary: Computes the cosine similarity between a single query vector and every row of a matrix, returning a 1-D array of similarity scores in [-1, 1].
1. Compute the scalar L2 norm of vector_1 using np.linalg.norm and store it as norm; if vector_1 is the zero vector, norm will be 0.0. → norm
2. Compute the L2 norm of each row of vectors_all along axis=1 using np.linalg.norm, producing a 1-D array of shape (N,); any zero row yields a 0.0 entry in this array. → all_norms
3. Compute the dot product of each row of vectors_all with vector_1 using the externally bound callable dot, producing a 1-D array of shape (N,). → dot_products
4. Element-wise divide dot_products by the scalar product (norm * all_norms) to obtain the cosine similarity for each row; division by zero silently produces NaN or inf when any norm is 0.0. → similarities
5. Return similarities to the caller. → similarities
   ? The denominator (norm * all_norms) becomes 0.0 for every element; element-wise division of dot_products by zero produces NaN or inf throughout similarities without raising an exception.

## similarity() → float
Summary: Computes the cosine similarity between two vectors by normalizing each to unit length and returning their dot product, yielding a scalar in [-1.0, 1.0].
#   → similarity_score: float — Cosine similarity of the two input vectors; a real-valued scalar in the range [-1.0, 1.0]

3. Compute the dot product of unit_vector_1 and unit_vector_2 using dot; because both inputs are unit vectors the result equals the cosine of the angle between the originals and is bounded to [-1.0, 1.0] for real-valued inputs → similarity_score
4. Return similarity_score immediately without storing it in an intermediate variable → return_value
