Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

# Fields: expr, stack, right_brackets, left_brackets
# Calls: check_balanced_brackets→clear_expr

## __init__(expr: string)
Summary: Initializes a bracket-matching instance by storing the input expression and setting up empty stack and bracket lookup lists for subsequent validation.
#   expr: string — The expression string to be analyzed for bracket matching
1. Initialize self.stack as an empty list to serve as the bracket tracking stack → self.stack
2. Initialize self.left_brackets as the list ['(', '{', '['] containing the three recognized opening bracket characters → self.left_brackets]
3. Assign the input parameter expr to self.expr for use in later processing → self.expr

## check_balanced_brackets(self: object) → boolean
Summary: Validates that all bracket characters in self.expr are correctly nested and matched by using a stack, returning False immediately on any mismatch and True only if the stack is empty after processing all characters.
#   self: object — Instance providing expr (iterable of characters), left_brackets (set of opening bracket characters), stack (list used as a stack), and clear_expr method
#   → result: boolean — True if all brackets in self.expr are properly nested and matched, False if any mismatch or unclosed opener is detected
1. Call self.clear_expr() to reset or prepare the expression state before processing → expr_cleared
2. Iterate over each character Brkt in self.expr one at a time → brkt_iteration
3. Within the for loop, check whether Brkt is a member of self.left_brackets to determine if it is an opening bracket → is_opening_bracket
4. Within the for loop, if Brkt is an opening bracket, push Brkt onto self.stack and continue to the next character → stack_after_push
5. Within the for loop, if Brkt is not an opening bracket, pop the top element from self.stack into Current_Brkt (raises IndexError if stack is empty) → current_brkt
6. Within the for loop, on the closing-bracket path, check whether Current_Brkt equals '(' and if so check whether Brkt is not ')'; if both are true, return False immediately → paren_mismatch_check
7. Within the for loop, on the closing-bracket path, check whether Current_Brkt equals '{' and if so check whether Brkt is not '}'; if both are true, return False immediately → curly_mismatch_check
8. Within the for loop, on the closing-bracket path, check whether Current_Brkt equals '[' and if so check whether Brkt is not ']'; if both are true, return False immediately → square_mismatch_check
9. After the for loop completes, check whether self.stack is non-empty (truthy); if so, return False to indicate unclosed opening brackets remain → unclosed_check
10. If self.stack is empty after the loop, return True to indicate all brackets are balanced → balanced_result

   ? Check whether self.stack is non-empty; if empty return True, otherwise return False
   ? Within the for loop, all three sequential mismatch checks evaluate their outer condition as false, so no return False is triggered and iteration continues without validating the pair
   ! log: "self.stack.pop() raises IndexError because no opener was available to match the current closing bracket; the method does not guard against this case"
   ! raise: IndexError "Raised by list.pop() on an empty stack when a closing bracket appears with no corresponding unmatched opener on the stack"

## clear_expr()
Summary: Filters self.expr in place, retaining only those characters that appear in self.left_brackets or self.right_brackets, discarding all others while preserving original character order.
1. Iterate over every character c in the current value of self.expr, preserving original order → char_sequence
2. For each character c, evaluate the filter predicate: check whether c is a member of self.left_brackets OR c is a member of self.right_brackets; keep c only when at least one condition is true → filtered_chars
3. Join all surviving characters from filtered_chars into a new string using an empty separator, producing a string that contains only bracket characters in their original order → new_expr
4. Assign new_expr back to self.expr, replacing the old value; the right-hand side is fully evaluated before assignment, so there is no aliasing hazard → self.expr
   ? The generator produces no characters; join returns an empty string; assign empty string to self.expr
   ? Every character in self.expr fails the membership test; filtered_chars is empty; assign empty string to self.expr
   ? The OR predicate is non-exclusive; the character passes the filter and is retained exactly once in its original position
