Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

#   where: dict or None — Optional mapping of column names to values used to build the WHERE clause; defaults to None, in which case no WHERE clause is added
#   → query: string — The fully constructed DELETE SQL query string
1. Interpolate table into the string literal 'DELETE FROM ' to produce the base query string and assign it to query → query
2. Evaluate whether where is truthy (non-None and non-empty); if true, proceed to the alternative flow to append the WHERE clause → where_condition
3. Return query → query
   ? For each key-value pair (k, v) in where.items(), format each as the string "k='v'" using f-string interpolation with no escaping on either k or v
   ? Join all condition_parts with ' AND ' as the separator to produce a single conditions string
   ? Append the string ' WHERE ' concatenated with conditions_string to query using in-place string concatenation (+=)

## insert(table: string, data: dict) → string
Summary: Builds and returns a SQL INSERT statement string for a given table by joining the keys and single-quoted values from a dictionary.
#   table: string — Name of the target database table
#   data: dict — Dictionary mapping column names to their corresponding values
#   → result: string — A SQL INSERT INTO statement with columns and single-quoted values derived from the input dictionary
1. Join all keys of data with ', ' as the column list → keys
2. Join all values of data, each wrapped in single quotes, with ', ' as the value list → values
3. Format and return the string 'INSERT INTO {table} ({keys}) VALUES ({values})' using the resolved table name, keys, and values → sql_statement

## select(table: string, columns: string or list of strings, where: dict or None) → string
Summary: Builds and returns a SELECT SQL query string for a given table, optionally projecting specific columns and filtering rows with equality conditions joined by AND.
#   table: string — The name of the database table to query
#   columns: string or list of strings — The columns to select; defaults to '*' meaning all columns; if a list is provided each element is a column name
#   where: dict or None — Optional mapping of column names to equality filter values; if None or empty no WHERE clause is added
#   → query: string — The fully assembled SQL SELECT statement as a plain string
1. Check whether columns is not equal to the sentinel string '*'; if it is not, join all elements of the columns list into a single comma-separated string and overwrite the columns variable with that string → columns
2. Construct the base query string by interpolating the columns string and table name into the template 'SELECT {columns} FROM {table}'; note that neither columns nor table is validated or escaped at this point, creating a potential SQL injection vector if either originates from external input → query
3. Check whether where is truthy (non-None and non-empty); if so, build a WHERE clause by formatting each key-value pair from where as "{k}='{v}'", joining all pairs with ' AND ', prepending ' WHERE ', and appending the result to query → query
4. Return the fully assembled query string → query
   ? Skip the join step and keep columns as the literal string '*', so the SELECT clause becomes 'SELECT * FROM {table}'
   ? Skip the WHERE clause construction and return the base 'SELECT {columns} FROM {table}' string without any filtering predicate

## update(table: str, data: dict, where: dict or None) → str
Summary: Builds a raw SQL UPDATE statement string by interpolating the table name, a SET clause from all key-value pairs in data, and an optional WHERE clause from a separate conditions dict.
#   table: str — Name of the database table to update; used verbatim with no sanitization
#   data: dict — Mapping of column names to their new values; must be non-empty to produce valid SQL
#   where: dict or None — Optional mapping of column names to filter values; when omitted or None the WHERE clause is skipped

1. Iterate over every key-value pair in data; for each pair format it as the string "k='v'" (key unquoted, value wrapped in single quotes); join all resulting strings with ", " as separator and assign the result to update_str → update_str
2. Construct the initial query string by concatenating the literal tokens "UPDATE ", table, " SET ", and update_str using an f-string, then assign it to query → query
3. Return query → query
   ? Iterate over every key-value pair in where; for each pair format it as the string "k='v'"; join all resulting strings with " AND " as separator to form a WHERE predicate string
   ? Append the string " WHERE " concatenated with where_clause to query in-place before returning
