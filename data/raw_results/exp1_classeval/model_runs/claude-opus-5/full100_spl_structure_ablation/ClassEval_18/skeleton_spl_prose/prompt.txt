Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of the same class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

## _to_camel_case(key: string) → string
Summary: Converts a snake_case string key into camelCase by splitting on underscores, capitalizing the first letter of each subsequent part, and joining all parts together.
#   key: string — A snake_case string to be converted to camelCase; expected to be a non-null string, though boundary cases like empty string or leading/trailing underscores are handled by the split behavior
#   → result: string — The camelCase version of the input string; the first segment is lowercased as-is and each subsequent segment has its first character uppercased
1. Split key on the underscore character '_' to produce a list of string segments, assigning the result to parts; if key contains no underscore the list has one element equal to key; if key starts or ends with '_' the list includes empty strings at head or tail respectively → parts
2. Take the first element of parts (index 0) as the leading segment, preserving its existing casing without any transformation → head
3. Iterate over all elements of parts starting from index 1 to the end; for each element call its title() method, which uppercases the first character and lowercases the rest, collecting all transformed segments into a sequence → tail_segments
4. Join tail_segments into a single string with an empty separator, producing the concatenated tail → tail
5. Concatenate head and tail into one string and return it as the camelCase result → return_value
   ? parts[0] equals key itself; the tail_segments iterable is empty; the joined tail is an empty string; return key unchanged
   ? split('_') on an empty string yields [''], so parts[0] is an empty string, tail is empty, and the return value is an empty string
   ? Empty-string segments in the tail position have their title() called, returning an empty string, so those segments contribute nothing to the camelCase output; an empty-string head means the result starts with whatever the first non-empty tail segment's title() produces
