Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

Class specification:

# Class: CookiesUtil
# Fields: cookies, cookies_file
# Calls: get_cookies→_save_cookies

## __init__(cookies_file: str)
Summary: Initializes the object by storing the cookies file path and setting the initial cookies value to None.
#   cookies_file: str — Path to the file from which cookies will be loaded.
1. Set self.cookies_file to the value of the cookies_file parameter. → self.cookies_file
2. Initialize self.cookies to None. → self.cookies

## _save_cookies() → bool
Summary: Saves self.cookies as JSON to self.cookies_file, returning True on success and False if any exception occurs.
#   → return_value: bool — True if the cookies were written successfully; False if an exception occurred.
1. Open self.cookies_file in write mode ('w') using a with statement, truncating the file if it already exists, and bind the opened file object to file. → file
2. Within the with statement, write self.cookies to file as JSON using json.dump with no additional formatting options. → json_dump_done
3. After the with statement completes successfully, return True. → return_value
   ? Catch the raised exception and return False.

## get_cookies(reponse: mapping)
Summary: Stores the value of reponse['cookies'] into self.cookies and then calls self._save_cookies() to persist the cookie state.
#   reponse: mapping — Object that supports key-based access and is expected to contain the key 'cookies'.
1. Read the value associated with the key 'cookies' from the reponse mapping and assign it to self.cookies. → self.cookies
2. Call self._save_cookies() to persist the updated cookie state. → self._save_cookies()

## load_cookies(self: object) → dict
Summary: Loads cookies from a JSON file and returns them, or returns an empty dictionary if the file does not exist.
#   self: object — The object instance containing the cookies_file attribute which specifies the path to the JSON file.
#   → cookies_data: dict — The parsed JSON data from the cookies file, or an empty dictionary if the file is not found.
1. Open the cookies file specified by self.cookies_file in read mode. → file
2. Load JSON data from the opened file using json.load and assign it to cookies_data. → cookies_data
3. Return cookies_data. → cookies_data
   ? Return an empty dictionary as a fallback.

## set_cookies(self: object with cookies attribute)
Summary: Sets the 'cookies' key of the request to a semicolon-separated string of 'key=value' pairs built from self.cookies.
#   self: object with cookies attribute — The object whose cookies attribute is expected to be a dict-like collection of cookie key-value pairs.
1. Get the collection of cookie key-value pairs from self.cookies.items(). → cookie_pairs
2. For each key and value in cookie_pairs, format the string f'{key}={value}' and collect all formatted cookie strings in a list. → formatted_cookie_strings
3. Join all formatted cookie strings in formatted_cookie_strings with '; ' to produce a single cookie header string. → cookie_header
4. Assign cookie_header to request['cookies']. → request['cookies']
