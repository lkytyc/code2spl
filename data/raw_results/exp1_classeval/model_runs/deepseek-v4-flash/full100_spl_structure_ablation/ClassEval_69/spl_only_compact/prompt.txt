Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

Class specification:

# Class: PDFHandler
# Fields: readers, filepaths

## __init__(filepaths: iterable of file paths)
Summary: Initializes the object by storing the supplied file paths and constructing a PdfReader object for each file path, preserving order in a new readers list.
#   filepaths: iterable of file paths — An iterable of file path values used to create PdfReader instances.
1. Assign the filepaths argument directly to self.filepaths as an instance attribute, preserving the original object reference; note that if filepaths is an iterator or generator, this same object will later be consumed when building self.readers. → self.filepaths
2. Iterate over filepaths in order, calling PyPDF2.PdfReader(fp) for each item fp and collecting the results into a new list; assign that list to self.readers. If filepaths is empty, self.readers becomes an empty list. → self.readers

## extract_text_from_pdfs(self: object) → list[str]
Summary: Extracts text from every page of every reader in self.readers and returns the accumulated list of page texts.
#   self: object — Object exposing a readers collection; each reader has a pages collection and each page provides extract_text().
#   → pdf_texts: list[str] — List of extracted page text strings, one entry per page, in reader-major page order.
1. Initialize pdf_texts to an empty list. → pdf_texts
2. For each reader in self.readers, iterate over every page index page_num from 0 to len(reader.pages) - 1 inclusive. → page_num
3. Within the outer loop over reader and the inner loop over page_num, assign page = reader.pages[page_num]. → page
4. Within the same nested loops, call page.extract_text() and append the returned value to pdf_texts. → pdf_texts
5. After all readers and pages are processed, return pdf_texts. → return_value

## merge_pdfs(output_filepath: str) → str
Summary: Merges every page from each PDF reader in self.readers into a single PyPDF2.PdfWriter and writes the combined PDF to output_filepath, returning a confirmation message with that path.
#   output_filepath: str — Destination filesystem path where the merged PDF will be written.
#   → result: str — Confirmation message stating that the merged PDFs were saved at output_filepath.
1. Create a new PyPDF2.PdfWriter object and assign it to pdf_writer. → pdf_writer
2. Start iterating over each reader in self.readers. → reader
3. For the current reader, start iterating page_num over range(len(reader.pages)); this yields page indices from 0 to len(reader.pages) - 1 inclusive when pages exist, and no iterations when reader.pages is empty. → page_num
4. Within the current reader and page_num iteration, retrieve reader.pages[page_num] and assign it to page. → page
5. Within the same nested iteration, add page to pdf_writer by calling pdf_writer.add_page(page). → pdf_writer
6. After the nested loops finish, open output_filepath in binary write mode as out using a with block. → out
7. While out is open, write the accumulated merged PDF content by calling pdf_writer.write(out). → out
8. After the with block completes, return the string f"Merged PDFs saved at {output_filepath}". → result
