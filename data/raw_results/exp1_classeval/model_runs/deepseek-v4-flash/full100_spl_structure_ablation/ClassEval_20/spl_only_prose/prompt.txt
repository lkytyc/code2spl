Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

Class specification:

# Class: Chat
# Fields: users
# Calls: send_message→users

## __init__()
Summary: Initializes a new instance by setting its users attribute to an empty dictionary.
1. Create a new empty dictionary and bind it to the instance attribute users. → self.users

## add_user(username: str) → bool
Summary: Adds a new username to the users dictionary if it does not already exist, returning True on success and False on duplicate.
#   username: str — The username to add to the users dictionary.
#   → result: bool — True if the username was newly added; False if the username already exists.
1. Evaluate whether username is already a key in the self.users dictionary. → membership_check
2. If username is not already present in self.users, assign an empty list as the initial value for that username. → user_entry
3. Return True to indicate that the new user was successfully added. → add_user_result
   ? Return False without modifying self.users to indicate that the username already exists.

## get_messages(username: str) → list
Summary: Returns the messages associated with the given username, or an empty list if the username is not present in self.users.
#   username: str — The username whose stored messages are requested.
#   → messages: list — The stored message list for the username, or an empty list if the username is not found.
1. Evaluate whether username is not present in self.users. → username_missing
2. If username_missing is true, return an empty list immediately and skip the rest of the method. → []
3. If username_missing is false, return the value stored for username in self.users. → self.users[username]

## remove_user(username: str) → bool
Summary: Removes the given username from the users dictionary if it exists and returns True; otherwise returns False without modifying the dictionary.
#   username: str — The username key to look up and remove from self.users.
#   → return_value: bool — True if the username was found and removed; False if the username was not found.
1. Check whether username exists as a key in self.users. → username_exists
2. If username_exists is True, delete self.users[username] and return True. → return_value
   ? Within the else branch, return False without modifying self.users.

## send_message(self: object, sender: str, receiver: str, message: str) → bool
Summary: Records a message by appending a timestamped message_info dictionary to both sender and receiver message lists after validating both users are registered, and returns True on success or False if either user is invalid.
#   self: object — The instance containing the users dictionary that maps user names to lists of message_info records.
#   sender: str — The username of the message sender; must exist as a key in self.users.
#   receiver: str — The username of the message receiver; must exist as a key in self.users.
#   message: str — The content of the message to store in both users' message_info lists.
#   → result: bool — True if the message_info record was appended to both users' lists; False if either user was not found in self.users.
1. Generate the current timestamp as a string formatted as '%Y-%m-%d %H:%M:%S'. → timestamp
2. Create message_info dictionary with sender, receiver, message, and timestamp. → message_info
3. Append message_info to the list stored at self.users[sender]. → sender_message_list
4. Append message_info to the list stored at self.users[receiver]; if receiver equals sender, this appends a second copy to the same list. → receiver_message_list
5. Return True to indicate successful message delivery. → return_value
   ? Return False without appending any message_info or modifying self.users.
