Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

# Class: JSONProcessor
# Calls: process_json→read_json, process_json→write_json

## process_json(file_path: string, remove_key: string) → integer
Summary: Reads a JSON file, returns 0 if the read result is 0 or -1, otherwise deletes the specified key from the parsed data when present, writes the updated data back to the file, and returns 1 on success or 0 if the key is absent.
#   file_path: string — Path to the JSON file to read and potentially rewrite.
#   remove_key: string — Key to search for and remove from the parsed JSON data.
#   → return_value: integer — Returns 1 if the key was removed and the file was written; returns 0 if data was 0 or -1, or if the key was not present.
1. Call self.read_json(file_path) and assign the returned parsed data to data. → data
2. Verify that data is not 0 and is not -1; if it is 0 or -1, use the corresponding alternative flow. → data_guard
3. Verify that remove_key is present in data; if it is not, use the corresponding alternative flow. → key_present
4. Delete data[remove_key] from data. → data
5. Call self.write_json(data, file_path) to persist the updated data. → write_result
6. Return 1 to indicate that the key was removed and the data was persisted. → 1
   ? Return 0 immediately without modifying the file.
   ? Return 0 immediately without modifying the file.

## read_json(file_path: str)
Summary: Reads and parses a JSON file from file_path, returning the parsed data on success, 0 if the file does not exist, and -1 if an exception occurs during access or parsing.
#   file_path: str — Path to the JSON file to read.
1. Check whether file_path exists by calling os.path.exists(file_path). → path_exists
2. If path_exists is True, inside a try block, open file_path in read mode using with open(file_path, 'r') as file. → file
3. Inside the same try block and within the with block, parse the JSON content from file by calling json.load(file). → data
4. Return data. → data
   ? Return the integer 0.
   ? Return the integer -1.

## write_json(file_path: string) → integer
Summary: Writes JSON-serializable data to a file and returns 1 on success or -1 if any exception occurs.
#   file_path: string — Path to the file where the JSON data will be written.
#   → return_value: integer — Returns 1 on successful write, or -1 if an exception occurs.
1. Open the file at file_path in write mode using a with statement. → file
2. Serialize data to JSON and write it to the file using json.dump. → write_result
3. Return 1 to indicate successful write. → return_value
   ? Return -1 to indicate failure.
