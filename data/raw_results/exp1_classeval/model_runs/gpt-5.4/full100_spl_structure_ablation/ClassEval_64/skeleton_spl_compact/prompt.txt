Task:
Complete the Python class from the ClassEval skeleton, using the compact class specification as an implementation contract.

Skeleton Role:
- The skeleton controls imports, class name, constructor shape, field names, method names, and method signatures.
- Preserve the skeleton API if skeleton and specification disagree.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of the same class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Match each specification method section to its skeleton method by method name.

Step 2: Treat the skeleton as the public API contract and the specification as the implementation contract for method bodies.

Step 3: Build a class-level behavior map:
- constructor fields and shared state;
- method inputs, outputs, and side effects;
- cross-method calls from `# Calls:` and inside steps;
- data flow from step `→` result names;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 4: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become if/elif/else blocks;
- `! raise:` steps become try/except or explicit raise only when entailed;
- `→` result names become local variables, fields, calls, or returned values.

Step 5: Keep the implementation minimal and executable. Do not add unrelated APIs or behavior outside the skeleton plus specification contract.

Reconstruction Rules:
