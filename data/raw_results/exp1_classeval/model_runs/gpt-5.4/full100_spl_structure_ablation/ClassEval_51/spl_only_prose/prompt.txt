Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

## fleiss_kappa(testData: matrix_like, N: integer, k: integer, n: numeric)
Summary: Compute Fleiss' kappa from rating count data by converting the input to a float matrix, aggregating observed agreement across rows, estimating chance agreement from column totals, and returning the final scalar kappa value.
#   testData: matrix_like — Input rating count data that is converted into a NumPy float matrix for computation.
#   N: integer — Number of rows to iterate over when computing observed agreement.
#   k: integer — Number of categories or columns used for inner-loop iteration and one-vector allocation.
#   n: numeric — Per-row rating count used to normalize each row agreement contribution.
1. Convert testData into a NumPy matrix of float values and store it as dataMat. → dataMat
2. Create oneMat as a k by 1 matrix of ones. → oneMat
3. Initialize the total element accumulator sum to 0.0 and initialize the observed agreement accumulator P0 to 0.0. → sum,
4. For each row index i from 0 to N - 1, initialize temp to 0.0, then within that outer loop for each column index j from 0 to k - 1 add dataMat[i, j] to sum and add 1.0 multiplied by dataMat[i, j] squared to temp, then after the inner loop subtract n from temp, divide temp by (n - 1) * n, and add the normalized temp to P0. → sum,
5. Normalize P0 by reassigning it to 1.0 multiplied by P0 divided by N. → P0
6. Compute ysum as the column-wise sum of dataMat along axis 0. → ysum
7. For each column index i from 0 to k - 1, replace ysum[0, i] with the square of ysum[0, i] divided by sum. → ysum
8. Compute Pe as ysum multiplied by oneMat and then multiplied by 1.0. → Pe
9. Compute ans as (P0 - Pe) divided by (1 - Pe). → ans
10. Return the scalar value at ans[0, 0]. → return

## kappa(testData: matrix_like_numeric_data, k: integer) → float
Summary: Compute Cohen's kappa coefficient from an input matrix-like dataset by summing diagonal agreement, deriving marginal totals, and normalizing observed versus expected agreement.
#   testData: matrix_like_numeric_data — Numeric input data that can be converted into a NumPy matrix and whose entries are used to compute agreement statistics.
#   k: integer — Number of leading diagonal positions to include when summing observed agreement, iterating from 0 up to but not including k.
#   → cohens_coefficient: float — The computed Cohen's kappa coefficient derived from observed agreement and expected agreement.
1. Convert testData into a NumPy matrix and store it as dataMat. → dataMat
2. Initialize P0 to the floating-point constant 0.0 as the accumulator for diagonal agreement. → P0
3. For each integer i from 0 up to but not including k, add dataMat[i, i] multiplied by 1.0 to P0. → P0
4. Compute xsum as the sum of dataMat along axis 1 to obtain row-wise totals. → xsum
5. Compute ysum as the sum of dataMat along axis 0 to obtain column-wise totals. → ysum
6. Compute sum as the total sum of all elements in dataMat. → sum
7. Compute Pe as float(ysum * xsum) divided by sum and then divided by sum again. → Pe
8. Normalize P0 by reassigning it to float(P0 divided by sum multiplied by 1.0). → P0
9. Compute cohens_coefficient as float((P0 - Pe) divided by (1 - Pe)). → cohens_coefficient
10. Return cohens_coefficient. → return
