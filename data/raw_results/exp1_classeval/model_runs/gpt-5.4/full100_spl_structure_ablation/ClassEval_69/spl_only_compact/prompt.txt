Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

Class specification:

# Class: PDFHandler
# Fields: readers, filepaths

## __init__(filepaths: iterable)
Summary: Initialize the instance by storing the provided filepaths unchanged and creating a list of PyPDF2 PdfReader objects, one for each filepath.
#   filepaths: iterable — An iterable of filepath-like values to store on the instance and to pass one by one into PyPDF2.PdfReader.
1. Assign the input filepaths directly to self.filepaths without modification, validation, or copying. → self.filepaths
2. Iterate over each fp in filepaths and construct PyPDF2.PdfReader(fp), collecting the created reader objects into a new list assigned to self.readers. → self.readers
   ? Assign an empty list to self.readers after completing the empty iteration.
   ! log: "Iteration over filepaths fails during self.readers initialization."
   ! raise: TypeError "Raised implicitly when filepaths cannot be iterated to build the list of PdfReader objects."
   ! log: "Reader construction aborts at the failing filepath during self.readers initialization."
   ! raise: Exception "Whatever exception PyPDF2.PdfReader raises for an invalid or unreadable filepath is propagated without handling."

## extract_text_from_pdfs(self: object) → list
Summary: Collect the extracted text from every page of every reader in self.readers and return the texts as a list in traversal order.
#   self: object — Instance containing the readers collection to process
#   → pdf_texts: list — List of page text values extracted from all pages of all readers in order
1. Initialize an empty list to store extracted page texts. → pdf_texts
2. For each reader in self.readers, iterate through all valid page indices from 0 inclusive to len(reader.pages) exclusive. → reader_and_page_num_iteration
3. Within the loop for the current reader and page index, retrieve the page object at reader.pages[page_num]. → page
4. Within the same nested loop context, call page.extract_text() and append the returned value to pdf_texts. → pdf_texts
5. After all readers and their pages have been processed, return pdf_texts. → pdf_texts

## merge_pdfs(output_filepath: string) → string
Summary: Merge all pages from each PDF reader in order into a single PDF file and return the saved output path message.
#   output_filepath: string — Destination file path for the merged PDF output.
#   → result: string — A confirmation message indicating where the merged PDFs were saved.
1. Create a new PDF writer instance. → pdf_writer
2. For each reader in self.readers, iterate through every page index from 0 to len(reader.pages) - 1. → page_num
3. Within the outer loop over each reader, retrieve the page at reader.pages[page_num]. → page
4. Within the nested loops, add each retrieved page to pdf_writer using add_page. → pdf_writer
5. Open output_filepath in binary write mode and write the completed pdf_writer contents to that file. → out
6. Return the message "Merged PDFs saved at {output_filepath}". → result
