Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

# Class: PushBoxGame
# Fields: boxes, map, is_game_over, player_col, targets, player_row, target_count
# Calls: __init__→init_game, move→check_win

## __init__(map: data)
Summary: Initialize the game object by storing the provided map, setting all gameplay state fields to their default starting values, and then starting game-specific initialization.
#   map: data — Input map data used to initialize the object's map field.
1. Store the input map into self.map. → self.map
2. Initialize self.player_row to 0. → self.player_row
3. Initialize self.player_col to 0. → self.player_col
4. Initialize self.targets as an empty list. → self.targets
5. Initialize self.boxes as an empty list. → self.boxes
6. Initialize self.target_count to 0. → self.target_count
7. Initialize self.is_game_over to False. → self.is_game_over
8. Call self.init_game() to perform additional game initialization after the default state is set. → initialization_complete

## check_win(self: object) → bool
Summary: Counts how many boxes are on target positions, marks the game over when that count equals the total target count, and returns the game-over state.
#   self: object — Instance containing boxes, targets, target_count, and is_game_over state.
#   → result: bool — Current game-over state after evaluating whether all boxes are on targets.
1. Initialize box_on_target_count to 0 as the starting count of boxes on targets. → box_on_target_count
2. Within the loop over each box in self.boxes, check whether the current box is contained in self.targets; if it is, increment box_on_target_count by 1. → box_on_target_count
3. After counting all boxes, compare box_on_target_count to self.target_count; if they are equal, set self.is_game_over to True. → self.is_game_over
4. Return self.is_game_over as the method result. → self.is_game_over

## init_game()
Summary: Scan every cell of the map to locate the player, collect all target positions while counting them, and collect all box positions.
1. For each row index row from 0 up to but not including len(self.map), begin scanning that row of the map. → row_iteration
2. Within each row iteration, for each column index col from 0 up to but not including len(self.map[row]), inspect self.map[row][col]. → cell_value_check
3. Within the nested row and column loops, if self.map[row][col] equals "O", assign self.player_row = row. → player_row_set
4. Within the same "O" branch, assign self.player_col = col. → player_col_set
5. Within the nested row and column loops, if the current cell is not "O" and self.map[row][col] equals "G", append the tuple (row, col) to self.targets. → target_position_added
6. Within the same "G" branch, increment self.target_count by 1. → target_count_updated
7. Within the nested row and column loops, if the current cell is neither "O" nor "G" and self.map[row][col] equals "X", append the tuple (row, col) to self.boxes. → box_position_added
8. For any cell value other than "O", "G", or "X", perform no action and continue scanning until all rows and their actual column lengths have been processed. → full_map_scanned

## move(direction: string) → boolean
Summary: Compute a tentative player move from the input direction, apply it only if the destination is not a wall and any encountered box can be pushed into a non-wall cell, then return the win-state check result.
#   direction: string — Movement command where 'w' moves up, 's' moves down, 'a' moves left, and 'd' moves right; any other value leaves the tentative position unchanged.
#   → result: boolean — The value returned by self.check_win() after any allowed movement or box push is processed.
1. Initialize local tentative coordinates by copying self.player_row into new_player_row and self.player_col into new_player_col. → new_player_position
2. If direction equals "w", decrement new_player_row by 1; else if direction equals "s", increment new_player_row by 1; else if direction equals "a", decrement new_player_col by 1; else if direction equals "d", increment new_player_col by 1; otherwise leave both tentative coordinates unchanged. → updated_tentative_player_position
3. Check whether self.map[new_player_row][new_player_col] is not equal to "#" before allowing any movement processing. → destination_not_wall
4. If the destination is not a wall and the tuple (new_player_row, new_player_col) is present in self.boxes, compute new_box_row as new_player_row + (new_player_row - self.player_row) and new_box_col as new_player_col + (new_player_col - self.player_col). → tentative_box_position
5. If the destination is not a wall, the destination contains a box, and self.map[new_box_row][new_box_col] is not equal to "#", remove (new_player_row, new_player_col) from self.boxes, append (new_box_row, new_box_col) to self.boxes, and then set self.player_row to new_player_row and self.player_col to new_player_col. → pushed_box_and_moved_player
6. If the destination is not a wall and the tuple (new_player_row, new_player_col) is not present in self.boxes, set self.player_row to new_player_row and self.player_col to new_player_col. → moved_player_without_pushing
7. Return the result of self.check_win(). → result
   ? Do not modify the tentative coordinates after initialization, so the attempted destination remains the current player position.
   ? Do not move the player and do not modify any box positions.
   ? Do not move the box and do not move the player.
