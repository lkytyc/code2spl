Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

## check_balanced_brackets(self: object) → boolean
Summary: Checks whether the current expression has properly balanced and correctly matched brackets by resetting state, scanning the expression with a stack, and returning False on the first mismatch or leftover opening bracket.
#   self: object — Instance containing the expression, bracket definitions, stack state, and helper methods used during validation.
#   → result: boolean — Returns True when all brackets in the expression are balanced and correctly matched; otherwise returns False.
1. Call self.clear_expr() before validation begins to reset or normalize the expression-related state used by this method. → expression_state_cleared
2. Iterate through each Brkt in self.expr from left to right. → current_bracket_sequence_processed
3. Within the loop for each Brkt, if Brkt is in self.left_brackets, append Brkt to self.stack as an unmatched opening bracket. → opening_bracket_pushed
4. Within the same loop, otherwise treat Brkt as a closing bracket and pop the most recent opening bracket from self.stack into Current_Brkt. → current_brkt_popped_from_stack
5. Within the closing-bracket branch, if Current_Brkt equals "(", require Brkt to equal ")"; otherwise return False immediately. → parenthesis_pair_validated_or_false_returned
6. Within the closing-bracket branch, if Current_Brkt equals "{", require Brkt to equal "}"; otherwise return False immediately. → brace_pair_validated_or_false_returned
7. Within the closing-bracket branch, if Current_Brkt equals "[", require Brkt to equal "]"; otherwise return False immediately. → square_bracket_pair_validated_or_false_returned
8. After the loop completes, check whether self.stack still contains any unmatched opening brackets. → remaining_stack_checked
9. If self.stack is not empty after processing all characters, return False. → false_returned_for_leftover_opening_brackets
10. Return True when the full expression has been processed without any mismatch and no unmatched opening brackets remain in self.stack. → result
   ? During loop processing of a closing bracket, if Current_Brkt is "(" and Brkt is not ")", return False immediately.
   ? During loop processing of a closing bracket, if Current_Brkt is "{" and Brkt is not "}", return False immediately.
   ? During loop processing of a closing bracket, if Current_Brkt is "[" and Brkt is not "]", return False immediately.
   ? After the loop, if self.stack contains any remaining items, return False.

## clear_expr()
Summary: Filter self.expr so it retains only characters that belong to self.left_brackets or self.right_brackets, preserving their original order.
1. Iterate through each character in the current self.expr and keep only characters for which membership in self.left_brackets is true or membership in self.right_brackets is true, using short-circuit OR logic for the inclusion test. → filtered_characters
2. Join the kept characters into a single string with an empty-string separator, producing an empty string if no characters were kept or if the original self.expr was empty. → filtered_expr
3. Assign the resulting filtered string back to self.expr. → self.expr
