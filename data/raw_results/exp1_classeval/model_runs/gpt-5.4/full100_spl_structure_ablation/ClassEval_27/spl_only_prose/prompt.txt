Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

## add_currency_rate(self: object, currency: key, rate: value) → bool
Summary: Adds a currency rate to the stored rates map unless that currency already exists, in which case it returns false without changing anything.
#   self: object — Instance containing the rates mapping.
#   currency: key — Currency identifier used as the map key.
#   rate: value — Rate value to store for the given currency.
#   → result: bool — Returns false if the currency already exists; otherwise stores the rate and returns null implicitly.
1. Check whether the given currency is already present in self.rates. → currency_exists
2. If the currency is already present, return false immediately without modifying self.rates. → false
3. Otherwise, store the provided rate in self.rates under the given currency key. → self.rates[currency]
   ? Skip the assignment to preserve the existing stored rate.
   ? Return false to signal that the rate was not added.

## convert(amount: number, from_currency: string, to_currency: string) → number_or_boolean
Summary: Convert an amount from one currency to another using stored exchange rates, returning the original amount for identical currencies and False when either currency rate is unavailable.
#   amount: number — The monetary amount to convert.
#   from_currency: string — The source currency code to convert from.
#   to_currency: string — The target currency code to convert to.
#   → result: number_or_boolean — The original amount if both currencies are the same, the converted amount if both rates exist, or False if either currency is missing from the rates mapping.
1. Check whether from_currency is different from to_currency before performing any rate lookup or conversion. → currency_comparison
2. When from_currency and to_currency are different, verify with short-circuit logic whether from_currency is absent from self.rates or to_currency is absent from self.rates. → rate_availability_check
3. When both currencies exist in self.rates, read self.rates[from_currency] into from_rate. → from_rate
4. When both currencies exist in self.rates, read self.rates[to_currency] into to_rate. → to_rate
5. When both rates have been read, compute converted_amount as (amount / from_rate) * to_rate. → converted_amount
6. Return converted_amount. → result
   ? Return amount unchanged without reading self.rates.
   ? Return False.
