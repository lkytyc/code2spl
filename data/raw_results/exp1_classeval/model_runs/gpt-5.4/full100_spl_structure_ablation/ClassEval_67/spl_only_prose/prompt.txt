Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

# Class: Order
# Fields: menu, sales, selected_dishes
# Calls: checkout→calculate_total

## __init__()
Summary: Initialize a new instance with empty menu, empty selected dish list, and empty sales records containers.
1. Initialize the instance attribute self.menu as an empty list to hold menu item dictionaries with dish, price, and count fields. → self.menu
2. Initialize the instance attribute self.selected_dishes as an empty list to hold selected dish dictionaries with dish, count, and price fields. → self.selected_dishes
3. Initialize the instance attribute self.sales as an empty dictionary to hold sales aggregation or sales record mappings. → self.sales

## add_dish(dish: dict) → bool
Summary: Checks the menu for a matching dish, rejects the request if the available count is too low, otherwise decreases the stored count and adds the dish to the selected list.
#   dish: dict — A dish record containing at least a dish name and a requested count.
#   → result: bool — True when the dish is accepted and added to the selected list; False when the requested count exceeds available menu stock.
1. Iterate through each menu_dish in self.menu and compare dish["dish"] with menu_dish["dish"]. → matched_menu_dish_search
2. When a matching menu_dish is found, if menu_dish["count"] is less than dish["count"], return False immediately. → false_return
3. When a matching menu_dish is found and menu_dish["count"] is at least dish["count"], subtract dish["count"] from menu_dish["count"] and break out of the loop. → updated_menu_dish
4. After the loop completes, append dish to self.selected_dishes and return True. → true_return

## calculate_total() → number
Summary: Compute the total sales-adjusted cost of all selected dishes by summing each dish's price multiplied by its count and the sales multiplier for that dish.
#   → total: number — The accumulated total of price times count times sales multiplier across all selected dishes.
1. Initialize total to the numeric constant 0 as the accumulator before processing any selected dishes. → total
2. Iterate over each dish record in self.selected_dishes. → dish
3. Within the loop for the current dish record, read dish["price"], dish["count"], and dish["dish"], then use dish["dish"] as the key to read the corresponding multiplier from self.sales. → current_dish_factors
4. Within the loop for the current dish record, compute dish["price"] * dish["count"] * self.sales[dish["dish"]]. → dish_total
5. Within the loop for the current dish record, add the computed dish_total to total using cumulative assignment. → total
6. After all dish records have been processed, return total. → total

## checkout(self: object) → bool_or_calculated_total
Summary: Return False when no dishes are selected; otherwise compute the current total, clear the selected dishes list, and return the computed total.
#   self: object — The instance whose selected dishes are checked, totaled, and then cleared.
#   → result: bool_or_calculated_total — Returns False if there are no selected dishes; otherwise returns the computed total before clearing the selected dishes.
1. Check whether the length of self.selected_dishes is equal to 0. → is_empty
2. If the selected dishes list is not empty, call self.calculate_total() and store the returned value in total. → total
3. After computing total, assign a new empty list to self.selected_dishes to reset the selection state. → self.selected_dishes
4. Return total. → result
   ? Return False immediately without calculating a total or modifying self.selected_dishes.
