Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

## find_blank(state: grid) → tuple or null

#   state: grid — A 3x3 grid of cell values to scan for a zero entry.
#   → result: tuple or null — The row and column of the first zero cell, or no return value if none is found.

2. Within the outer loop over i, iterate j from 0 to 2 over the columns of the current row. → col_index
3. Within the nested loops, check whether state[i][j] equals 0. → cell_is_blank
4. If state[i][j] equals 0, return the coordinates (i, j) immediately. → blank_position

## get_possible_moves(state: object) → list
Summary: Determine which directional moves are valid for the blank position in the given state by checking its row and column against 3x3 grid boundaries and returning the resulting move list.
#   state: object — Puzzle state from which the blank position is located.
#   → moves: list — List of valid move names for the blank position, including any of 'up', 'down', 'left', and 'right'.
1. Initialize an empty list to accumulate valid move names. → moves
2. Call self.find_blank(state) and unpack its two returned values into row index i and column index j. → i,
3. If row index i is greater than 0, append 'up' to moves. → moves
4. If row index i is less than 2, append 'down' to moves. → moves
5. If column index j is greater than 0, append 'left' to moves. → moves
6. If column index j is less than 2, append 'right' to moves. → moves
7. Return the accumulated moves list. → moves

## move(state: grid, direction: string) → grid
Summary: Creates a row-level copy of the input grid, finds the blank position, swaps that blank with an adjacent cell based on the given direction, and returns the resulting state.
#   state: grid — The current two-dimensional state from which the blank position is located and copied.
#   direction: string — The movement direction to apply; supported values are 'up', 'down', 'left', and 'right'.
#   → new_state: grid — A row-level copied state reflecting the blank swapped with an adjacent cell if the direction matches a supported value; otherwise the copied state is returned unchanged.
1. Call self.find_blank(state) to get the blank position coordinates and assign them to i and j. → i,
2. Create new_state as a row-level copy of state using a per-row slice copy so later modifications do not mutate the original state rows. → new_state
3. If direction equals 'up', swap new_state[i][j] with new_state[i - 1][j]. → new_state
4. Else if direction equals 'down', swap new_state[i][j] with new_state[i + 1][j]. → new_state
5. Else if direction equals 'left', swap new_state[i][j] with new_state[i][j - 1]. → new_state
6. Else if direction equals 'right', swap new_state[i][j] with new_state[i][j + 1]. → new_state
7. Return new_state after the conditional chain completes. → new_state
   ? Do not perform any swap because no conditional branch matches.
   ? Return the copied state unchanged.

## solve()
Summary: Performs a breadth-first search over states to find and return the move path that reaches the goal state, or returns null if no goal is reachable.
1. Initialize the open queue with the initial state paired with an empty path, and initialize the closed list as empty. → open_list,
2. While the open queue is not empty, remove the first queued state and its path, then append the current state to the closed list. → current_state,
3. If the current state equals the goal state, return the current path immediately. → path
4. Within the while loop, for each possible move from the current state, compute the resulting new state. → new_state
5. Within the while loop, if the new state is not already in the closed list, append the new state and the extended path with that move to the open queue. → open_list
6. If the open queue becomes empty without reaching the goal state, return null. → None
