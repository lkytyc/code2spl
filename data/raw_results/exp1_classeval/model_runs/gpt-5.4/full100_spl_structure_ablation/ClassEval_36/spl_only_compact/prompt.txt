Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

## clear_inbox(self: object, size: number)
Summary: Clear emails from the front of the inbox until enough space has been freed or the inbox becomes empty, unless the address list is empty and the method returns immediately.
#   self: object — The instance containing the addr and inbox collections.
#   size: number — The target amount of space to free.
1. Check whether self.addr is empty, and if it is, return immediately without modifying the inbox. → early_return
2. Initialize freed_space to 0 before any email removal begins. → freed_space
3. While freed_space is less than size and self.inbox is non-empty, take the first email in self.inbox, add that email's size to freed_space, and remove that email from the front of self.inbox. → freed_space

## fetch(self: object) → object_or_none
Summary: Return the first unread inbox item after marking its state as read, or return None if the inbox is empty or contains no unread items.
#   self: object — Instance containing the inbox list to inspect and update.
#   → result: object_or_none — The first inbox item whose state was exactly 'unread' after changing its state to 'read', or None if no such item is found.
1. Check whether the length of self.inbox is equal to 0. → is_inbox_empty
2. If is_inbox_empty is true, return None immediately. → return_none_when_empty
3. Iterate i from 0 up to len(self.inbox) - 1 in ascending order. → inbox_index_iteration
4. Within the loop for each index i, check whether self.inbox[i]['state'] is exactly equal to "unread". → is_current_item_unread
5. Within the loop, if is_current_item_unread is true, set self.inbox[i]['state'] to "read". → marked_current_item_read
6. Within the same loop iteration after marking the item as read, return self.inbox[i] immediately. → return_first_unread_item
7. If the loop completes without returning any item, return None. → return_none_when_no_unread_item
   ? Return None without entering the loop.
   ? Finish the loop without modifying any item state.
   ? Return None after the loop completes.

## get_occupied_size(self: object) → integer
Summary: Computes the total occupied size by summing the size of each email in the inbox.
#   self: object — The object containing the inbox collection.
#   → result: integer — The total summed size of all emails in the inbox.
1. Initialize occupied_size to 0 as the running total. → occupied_size
2. For each email in self.inbox, add email["size"] to occupied_size. → occupied_size
3. Return occupied_size as the final total. → result

## is_full_with_one_more_email(size: data_type) → boolean
Summary: Determines whether adding one more email of the given size would make the occupied size exceed the capacity.
#   size: data_type — The size of the additional email to evaluate against the remaining capacity.
#   → result: boolean — True if occupied_size plus size is strictly greater than self.capacity, otherwise False.
1. Call self.get_occupied_size() and assign its returned value to occupied_size. → occupied_size
2. Compute whether occupied_size + size is strictly greater than self.capacity. → is_over_capacity
3. Return True if is_over_capacity is true; otherwise return False. → result

## send_to(self: object, recv: object, content: any, size: number) → boolean
Summary: Sends an email to a receiver if there is room for one more message of the given size; otherwise it clears inbox space and reports failure.

4. When the receiver can accept the email, append the email record to the receiver inbox and return True immediately. → true
5. When the receiver cannot accept one more email, call self.clear_inbox(size). → cleared
6. When the receiver cannot accept one more email, return False immediately. → false
