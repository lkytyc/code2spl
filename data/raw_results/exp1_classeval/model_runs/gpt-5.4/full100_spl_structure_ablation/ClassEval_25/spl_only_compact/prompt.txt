Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

# Class: CookiesUtil
# Fields: cookies_file, cookies
# Calls: get_cookies→_save_cookies

## __init__(cookies_file: any)
Summary: Initialize the instance by storing the provided cookies file reference and setting the cookies state to an uninitialized None value.
#   cookies_file: any — The value to store as the instance's cookies file reference without validation or transformation.
1. Assign the input value cookies_file directly to the instance attribute self.cookies_file without modification or validation. → self.cookies_file
2. Set the instance attribute self.cookies to None as the default uninitialized cookies value, overwriting any prior value. → self.cookies

## _save_cookies() → bool
Summary: Save the current cookies dictionary to the configured cookies file as JSON and return success or failure.
#   → result: bool — True if the cookies are saved successfully, otherwise False
1. Enter a try block to attempt saving the cookies to disk. → try_block
2. Open the file at self.cookies_file in write mode as file. → file
3. Serialize self.cookies into the open file using json.dump. → written_cookies
4. Return True after the cookies are successfully written. → true_result
   ? Catch the exception and suppress it.
   ? Return False to indicate the save operation failed.

## get_cookies(self: object, reponse: mapping)
Summary: Extract the cookies entry from the response object, store it on the instance, and then save the cookies.
#   self: object — Instance receiving the cookies value.
#   reponse: mapping — Response-like object expected to contain a 'cookies' key.
1. Assign the value from reponse['cookies'] to the instance attribute self.cookies. → self.cookies
2. Call self._save_cookies() to persist the updated cookies on the instance. → _save_cookies_result

## load_cookies() → dict
Summary: Loads cookie data from the configured cookies file as JSON and returns an empty dictionary if the file does not exist.
#   → result: dict — The loaded cookie data, or an empty dictionary if the file is missing.
1. Open the file at self.cookies_file in read mode and parse its contents as JSON. → cookies_data
2. Return the parsed cookies_data. → cookies_data
   ? Return an empty dictionary instead of cookie data.

## set_cookies(self: object, request: mapping) → mapping
Summary: Build the request cookies header as a semicolon-separated string from the object's stored cookie key-value pairs.
#   self: object — Object containing a cookies mapping.
#   request: mapping — Request object that receives the cookies header string under the 'cookies' key.
#   → request: mapping — The same request object updated with a 'cookies' string.
1. Read all key-value pairs from self.cookies. → cookie_items
2. Format each cookie pair as 'key=value'. → formatted_cookies
3. Join the formatted cookie strings with '; ' as the separator. → cookies_header
4. Assign the resulting string to request['cookies']. → request
