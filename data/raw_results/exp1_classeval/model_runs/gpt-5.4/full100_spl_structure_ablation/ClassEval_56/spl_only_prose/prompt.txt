Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

## f1_score(self: object, predicted_labels: unknown, true_labels: unknown) → float
Summary: Compute the F1 score from predicted and true labels by updating internal state, deriving precision and recall, returning 0.0 when their sum is zero, and otherwise returning the harmonic mean formula.
#   self: object — Instance providing update, precision, and recall methods.
#   predicted_labels: unknown — Predicted labels passed to update, precision, and recall.
#   true_labels: unknown — Ground truth labels passed to update, precision, and recall.
#   → result: float — The computed F1 score, or 0.0 when precision plus recall equals 0.0.

2. Compute precision from predicted_labels and true_labels using the current instance. → precision
3. Compute recall from predicted_labels and true_labels using the current instance. → recall
4. If precision plus recall equals 0.0, return 0.0 immediately. → 0.0
5. Otherwise, return (2 * precision * recall) divided by (precision + recall). → result

## precision(predicted_labels: data, true_labels: data) → float
Summary: Updates the metric state with predicted and true labels, then returns precision as true positives divided by predicted positives, or 0.0 when the denominator is zero.
#   predicted_labels: data — Predicted labels passed to the state update method.

## recall(predicted_labels: unknown, true_labels: unknown) → float
Summary: Updates metric counts from the predicted and true labels, returns 0.0 when the recall denominator is zero, otherwise returns true positives divided by true positives plus false negatives.
#   predicted_labels: unknown — Predicted label data passed to the update step.
#   true_labels: unknown — Ground-truth label data passed to the update step.
#   → result: float — Recall value, or 0.0 when the denominator is zero.
1. Call the internal update step with predicted_labels and true_labels to refresh the object's metric state. → self.update(predicted_labels,
2. Check whether self.true_positives plus self.false_negatives is exactly 0. → denominator_is_zero
3. If the denominator is zero, return 0.0 immediately. → 0.0
4. Otherwise compute and return self.true_positives divided by self.true_positives plus self.false_negatives. → result
   ? Return 0.0 to avoid division by zero.

## update(predicted_labels: sequence, true_labels: sequence)
Summary: Iterate through paired predicted and true binary labels and increment the corresponding confusion-matrix counter for each recognized label pair.
#   predicted_labels: sequence — A sequence of predicted labels iterated in parallel with true_labels using zip.
#   true_labels: sequence — A sequence of true labels iterated in parallel with predicted_labels using zip.
1. Iterate over paired values predicted and true from zip(predicted_labels, true_labels), processing only pairs up to the length of the shorter input sequence. → paired_label_iteration
2. Within the loop, if predicted equals 1 and true equals 1, increment self.true_positives by 1. → self.true_positives
3. Within the same loop iteration, otherwise if predicted equals 1 and true equals 0, increment self.false_positives by 1. → self.false_positives
4. Within the same loop iteration, otherwise if predicted equals 0 and true equals 1, increment self.false_negatives by 1. → self.false_negatives
5. Within the same loop iteration, otherwise if predicted equals 0 and true equals 0, increment self.true_negatives by 1. → self.true_negatives
   ? Do not increment any confusion-matrix counter for that iteration.
