Task:
Reconstruct one complete executable Python class from the compact class specification.

Spec Concept:
- The compact specification is a code-derived, human-readable behavior map of a class.
- A `# Class:` line names the class, `# Fields:` lists its fields, and `# Calls:` lists cross-method call edges.
- Each method has a `## name(self, ...) → return` section that lists its parameters with types and its numbered implementation steps.
- Numbered steps describe the normal statement order; steps marked `IF`, `RETURN`, or `THROW` describe branches, returns, and raised errors.
- `?` lines describe alternative branches; `! log:` and `! raise:` lines describe exception paths.
- A `→ name` annotation on a step names the value that step produces.

Reconstruction Workflow:
Step 1: Scan the class overview and method sections to infer class name, constructor, field assignments, method names, method signatures, and return behavior.

Step 2: Build a class-level behavior map:
- fields and shared state from `# Fields:` and step result names;
- method contracts from each method signature;
- call graph from `# Calls:` and cross-method calls inside steps;
- branch and exception behavior from `IF`, `?`, and `!` lines.

Step 3: Implement each method from its numbered steps:
- numbered steps become the normal statement order;
- `?` alternative steps become conditional branches;
- `! raise:` steps become try/except or explicit raise only when required;
- `→` result names become local variables, fields, calls, or returned values.

Step 4: Use the simplest valid Python implementation when formatting, style, or exact variable names are omitted.

Step 5: Do not invent unrelated behavior that is not supported by the specification.

Reconstruction Rules:
- Identify the class, constructor, fields, methods, dependencies, return values, and error behavior described by the specification.
- Preserve cross-method calls, field usage, control flow, data flow, return values, and exceptions.
- Output only the complete Python class implementation.
- Do not use markdown fences and do not explain.

Class specification:

# Class: JSONProcessor
# Calls: process_json→read_json, process_json→write_json

## process_json(file_path: text, remove_key: text) → integer
Summary: Load JSON data from a file, return 0 immediately if the read result is the sentinel value 0 or -1, otherwise remove a specified key if present, persist the updated data, and return 1 on success or 0 if no key was removed.
#   file_path: text — Path to the JSON file to read and potentially update.
#   remove_key: text — Key to remove from the loaded JSON mapping if it exists.
#   → result: integer — Returns 1 if the key is found, removed, and the updated JSON is written back; otherwise returns 0.
1. Read JSON data from file_path by calling self.read_json(file_path) and store the returned value in data. → data
2. Check whether data equals 0 or data equals -1 using short-circuit OR; if either comparison is true, return 0 immediately without attempting key removal or writing the file. → early_return_on_invalid_read
3. If remove_key exists as a key in data, delete data[remove_key]. → data_after_key_removal
4. Within the branch where remove_key exists in data, write the modified data back to file_path by calling self.write_json(data, file_path). → write_completed
5. Within the branch where remove_key exists in data, return 1 immediately after writing the updated JSON. → success_return
   ? Return 0 immediately and do not check membership, delete any key, or write any file content.
   ? Return 0 without modifying data and without calling self.write_json(data, file_path).

## read_json(self: object, file_path: string) → object_or_integer
Summary: Checks whether a file exists, returns 0 if it does not, otherwise attempts to load and return JSON content from the file and returns -1 if reading or parsing fails.
#   self: object — Instance context for the method.
#   file_path: string — Path to the JSON file to check and read.
#   → result: object_or_integer — Returns 0 when the file does not exist, the parsed JSON data when loading succeeds, or -1 if an error occurs while opening or parsing the file.
1. Check whether the path given by file_path exists in the filesystem. → path_exists
2. If path_exists is false, return 0 immediately as an early exit. → result
3. If path_exists is true, open the file at file_path in read mode. → file_handle
4. Load JSON data from the opened file handle. → data
5. Return the loaded JSON data. → result
   ? Return 0 immediately without attempting to open or parse the file.
   ? Return -1 as the fallback result for any exception caught by the try-except block.

## write_json(data: any, file_path: string) → integer
Summary: Write the provided data as JSON to the specified file path and return 1 on success or -1 if any exception occurs.
#   data: any — Data to serialize and write as JSON content.
#   file_path: string — Path of the file to open for writing the JSON output.
#   → result: integer — Returns 1 when the JSON data is written successfully, or -1 if any exception occurs during opening or writing the file.
1. Attempt to open the file at file_path in write mode as file within a try block. → file
2. Within the try block and using the opened file handle, serialize data and write it to the file as JSON. → write_status
3. If opening the file and writing the JSON both complete without exception, return 1. → result
   ? Catch the exception without rethrowing it.
   ? Return -1 as the failure indicator.
